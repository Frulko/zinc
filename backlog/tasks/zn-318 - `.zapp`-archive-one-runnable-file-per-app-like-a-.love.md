## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`zinc pack [dir] -o app.zapp`: the ZBC, the baked resources, the assets and the manifest (zinc.json subset, engine version, a signature slot) in one deterministic archive; `zinc run app.zapp` runs it; double-click on macOS/Linux opens it with zinc.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 two packs of the same project are byte-identical
- [x] #2 `zinc run app.zapp` gives the same output and frame as `zinc run dir`
- [x] #3 an archive made for a newer engine, or a corrupted one, is refused with a clear message
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done: zinc pack [dir] [-o out] (default build/<name>.zapp) writes a deterministic ustar (src/zapp.cpp: sorted names, time 0, owner 0, mode 0644): manifest.json (format 1, engine, name, SHA-256 of every file, empty signature slot), program.zbc, resources.bin (the baked fonts and images), zinc.json, assets/ (hidden files out). zinc run app.zapp checks header checksums, SHA-256s, unlisted files, paths outside, format and engine version, unpacks once into ~/.zinc/cache/zapp/<sha> and runs program.zbc with its resources.bin and zinc.json. Test tests/t0/zapp.sh: two packs byte-identical, tar lists it, same frame (game-2d) and same output (cli) as the directory, corrupted / newer engine / escaping archives refused. Double-click: ZN-391. Docs: docs/zapp.md. tests/run --changed 45/45. usage: n/a
