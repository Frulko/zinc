## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
rn-showcase and the mobile demos read best in a phone shell. zinc.json `web.frame` (phone, tablet, none) and `?frame=` in the URL draw the shell around the canvas or DOM root at the device's size and ratio, with a rotate button; the app sees the device's size, not the window's.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-11-12 — isolated worker work/86303-webframe, base 95eefd2bc.

Implemented targets.web.frame (validated phone|tablet|none, default none), URL override, and an event-driven neutral shell with a native rotate button. Phone390x844/tablet768x1024 are CSS-pixel viewports; fixed width/height retain their existing app-surface semantics and set the initial preview viewport. The same-origin iframe keeps DOM/canvas pointers, DPR, page/app scrolling, fixed portals and modal contexts in logical coordinates without app/library rewrites. Parent runtime does not start the app, bridge, assets or frame loop; child is identified by frameElement. App startup leaves the shell keyboard controls reachable. rn-showcase source unchanged, only targets.web.frame config added. No per-frame shell work, animation or dependency.

Decision proposal: use native iframe viewport rather than transforming zinc-root: root-only sizing would need coordinated pointer/drag/painted-field/portal/dialog/page-scroll/global-viewport changes. Initial URL query/hash are preserved; Stack routes and Back belong to the inner context (frame=none exposes main-address routing). No history mirror. Existing Vite pageParts spreads config and uses this same runtime, so no Vite source change needed. PWA shell has no new asset to cache.
