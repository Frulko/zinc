## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented editable sketch snapshots in Atelier Share. Pack asks for a destination, runs one headless interpreter frame for the cover, then uses the existing .zapp writer with sources and the existing icon.png member. A same-filesystem staging directory and final rename preserve a previous export on failure. Import verifies hashes and paths through the existing zapp reader, refuses an existing destination, and opens a fresh sketchbook copy. `zinc pack --sources [--cover picture.png]` and `zinc unpack file.zapp --out new-folder` expose the same path. Ordinary packs keep their contents. No upload, publication, account, new archive format, or package dependency.

Reuse: zapp::pack/unpack, zinc:process, zinc:fs, system dialogs, gfx clipboard/capture, the existing project metadata reader, and kit buttons/focusScope. Typed packs lacked editable sources and there was no verified import command; small helpers in src/zapp.{h,cpp} fill those gaps. main.cpp contains only option/dispatch/helper wiring, outside display work. Workspace entry lookup now reuses readProject rather than matching an entry string inside a comment. The existing model fixture asserts JSONC comment/escaped-entry behavior.

The URL carries the playground's existing path-to-text map as #files-json/<percent-encoded JSON>. A shared std helper validates paths/value types/counts/size; the site still reads its compressed #files/ links. Atelier collects source/JSON files independently of the editor tab-list depth limit, copies the URL to the clipboard, and accepts its source links as startup arguments or in the headless Open prompt. Metadata entry must name a source in the map. File/source readers reject oversized input, symlinks and invalid paths; root manifest.json remains reserved by .zapp. Imported sources/config/assets/cover are retained, compiled/native archive payloads are not used as editable sources.

Research: https://maker.makecode.com/share (immutable source snapshots with title/thumbnail); https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment (fragment handled by the client rather than sent to the server). Choice: use std URI encoding for the same existing map instead of porting lz-string into Zinc; no second compression implementation or cloud service. Revisit only if the 8,192-character limit makes common small sketches impractical. This is a routine reversible wire-encoding choice; no decision number allocated.
