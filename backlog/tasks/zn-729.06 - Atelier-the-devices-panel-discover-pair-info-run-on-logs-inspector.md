## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Atelier lists the devices `zinc device list --json` finds, pairs one with its code, shows what it is (kind, power, memory, temperature, apps), and Run takes a device as its target: the sketch is installed and started there, its log arrives in the console, Debug opens its inspector. Atelier talks to the CLI through zinc:process, as it does for the rest.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done in a worktree (2026-10-12), with main's binary: no C++ change, the engine was not built.

What it is: app/atelier/app/devices.ts (state: the list, the pairing form, the figures), components/Devices.tsx (the panel), app/tools.ts (Run, Stop and Debug on a device), model.ts (the JSON of list and top), the run menu of Header.tsx (paired devices under the engines, Devices…), Sketch > Run on a Device…. Report: the section Atelier's devices panel of docs/reports/zinc-next-agent.md.

Criteria, on tests/t1/atelier_devices.sh through tests/run (PASS three times in a row, 6 to 10 s):
1. the list (empty at first, then bench), a wrong code said in plain words, the right code typed in its field and Enter: paired. The test has no mDNS: a device found on the network is the parsing case of tests/t0/atelier.sh, and was seen once by hand (an agent announced on the loopback interface: listed with its pairing open, a press on its row, the code typed, paired by its name).
2. the console has the deploy command, installed and started, the sketch's lines; Stop: status Stopped, and zinc device apps then says the app is stopped.
3. two samples or more of top over the session, the app seen running then stopped; the labels are in the golden.
4. one golden, tests/golden/atelier/devices-30.png, compared over the panel without its right column (addresses and figures).

Decisions (reversible, no record number taken):
- Run on a device is zinc device <name> deploy . --name <folder>; the follower ends at the log's [exited n] line. Debug is Run plus zinc device inspect at the app's zinc devtools: line, not zinc dev --device (a dev session is not an app, inspect has nothing to forward).
- The chosen device is the Run target and the one whose figures are shown: one choice, not two.
- The golden leaves out what changes with the machine (pngdiff --crop, twice) instead of a fake device.
- New in the scripted sessions of Atelier: pair:, device:, wait:<text> (holds the frame until the app says it, 10 s at most), and ZINC_ATELIER_BROWSE.

Pitfalls met:
- tests/run exports ZINC_DETERMINISTIC=1: an agent started by a test hands the virtual clock to its apps, a timer then fires without a pause (11000 lines in 50 s, a whole core, and Stop had no effect before the session's timeout). The test starts its agent with env -u ZINC_DETERMINISTIC. Seen only through the runner: run a new agent test through tests/run before believing it.
- A new ZINC_HOME for a program with native plugins (Atelier: system, process) downloads zig outside tests/run: the test links toolchains and cache of the real home into its own.
- A pairing code can start with 0: no shell arithmetic on it without a 1 in front.

Not proven: a real window, a real device (a Pi: its temperature, a slow link), Debug on a device in the test (tried by hand, headless: the inspector forwarded and Zinc Inspector started on its port), a device that goes away during a run (the Lost status is written, not run).
