## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
W0602 says 'the native side X has no browser backend: its calls throw ZnUnsupported' (Device, Lvgl, Cdp, Process, Ipod...). Following docs/reports/web-bridge-research.md §3 (JSON-RPC envelope, OBS-style handshake, token, binary frames): the dev server (src/cli_web.cpp), on loopback and same origin as the page, loads the plugin's native library and answer the page's calls; the generated web entry calls the bridge when no browser backend exists and the bridge answered hello, else ZnUnsupported as today. plugin.json web level: native | bridge | none, W0602 says which. Local development only (owner, 2026-10-30): a hosted page never gets process, fs or devices from a server; the online demos use browser backends, the in-page device simulator and a demo mode instead.
