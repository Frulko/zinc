## Implementation Notes

- Scope: independent helper leaf of ZN-541, following ZN-541.02. `downgradeMaterials(scene)` and `mergeStaticMeshes(parent)` in the same pure-JS `zinc:three-pi` module; no service, native module, scene-wide automatic merge, global cache, public test knob or production three selector change.
- Research (coordinator's delegated Three research): upstream built-in Lambert and mergeGeometries are reused. https://raw.githubusercontent.com/mrdoob/three.js/r162/src/materials/MeshLambertMaterial.js ; https://raw.githubusercontent.com/mrdoob/three.js/r162/examples/jsm/utils/BufferGeometryUtils.js ; https://threejs.org/docs/pages/BufferGeometry.html . Standard.copy is not used on Lambert: only Material base state plus explicitly applicable Lambert state transfers. Upstream r162 alphatest/clipping shader chunks confirm alpha-to-coverage uses fwidth, so it is cleared along with flatShading/alphaHash; normal/bump/displacement/environment/PBR-only features remain absent.
- Merge contract: only direct ordinary Mesh siblings explicitly marked `userData.static = true`, same material object, matching render/layer and attribute storage state. No geometry groups/partial ranges, morph/skinned/instanced/custom/transparent or order-sensitive depth-disabled/nonwriting/stencil materials. Only ordinary BufferAttribute/Float32BufferAttribute; integer/normalized/half-float transform attributes, interleaving, reflected/singular/nonfinite transforms stay intact rather than rounding/breaking winding. Local matrices bake directly into parent coordinates (no world inverse), normals/tangents use upstream geometry transforms. GPU type, usage and names restore after merge for r162. Every result is prepared before removing originals; no source geometry/material disposal. Output object names/metadata/identity are intentionally replaced under the explicit static promise; this is documented.
- Exact proof: stable shared compiler SHA256 `54114b62024f586d835630c7964bfa7e037f93c989b8d9464961b04beea46a9b` (source b7c0d7b4c), no build. `zinc check tests/data/three-pi/material-merge.js --engine quickjs --profile rpi1`: 7 modules, zero warnings. `tests/run --only three_pi`: PASS, split and material/merge fixtures on r186 profiles rpi1(T2), linux(T3), macos(T4), plus external checksum-pinned r162 T2. Tests include material fields/array sharing/custom retention/no global cache, transformed parent and nonuniform scale, normal/tangent correctness, normalized raw data and integer GPU metadata, unsupported cases, resource non-disposal and 65,538-vertex merge re-splitting.
- Actual direct Mac renderer proof: `ZINC_HEADLESS=1 ZINC_WEB=1 ZINC_FRAMES=1 zinc run tests/data/three-pi/material-render.js --engine quickjs --profile rpi1` PASS current r186 WebGL2, two textured Standard planes converted to Lambert and merged into one mesh, red pixels at both expected transformed positions and no GL error. Same original fixture under the external r162 import map PASS actual WebGL1; expected upstream WebGL1 deprecation warning only. T2 profile on Mac is not VC4 emulation or Pi hardware evidence.
