## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
What adb gives, through the agent: a remote shell (a command with its exit status, or a terminal), files both ways, apps installed and started on the device with their logs, and ports of the device reached from the workstation (the inspector and the debugger of a running app go through that).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 zinc device <d> shell <command> prints its output and exits with its status; without a command it opens a terminal on the device (PTY, window size followed)
- [x] #2 push and pull copy a file or a directory tree with the file modes; a name that leaves the destination is refused
- [x] #3 install takes a .zapp or an export directory; run, stop, apps, logs [-f] and uninstall work on it; the output of a running app is kept in a bounded log
- [x] #4 forward <local> <remote> makes a port of the device answer on the workstation: /json/list of a running app's inspector is read through it
- [x] #5 A test on the loopback interface covers the four criteria above
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-10-12, with ZN-729.01 (same files: src/agent/server.cpp and client.cpp).
shell: a command through $SHELL -lc with stdout and stderr apart and its exit status, or a pseudo-terminal (raw mode on the workstation, the window's size sent at start and at every SIGWINCH). push / pull: entries with modes; into an existing directory the tree lands under its name, as cp does; names that are absolute or hold .. are refused by the receiver. install: a .zapp (checked member by member as zinc run does) or an export directory (run.sh); run starts the app in a session of its own with its output appended to logs/<name>.log (cut back past 4 MiB, the last 1 MiB kept in .log.1), so it outlives the agent; stop, uninstall, apps, logs [-f]. deploy: zinc pack, install, run, logs -f in one command. forward: one session per connection to 127.0.0.1:<port> of the device.
Tests: tests/run --tier t1 --only agent_apps PASS in 3.4 s (a cli project deployed, its output and [exited 0] in its log; a UI app with zinc:devtools whose /json/list is read twice through a forwarded port, the inspector answering with the forwarded port in its WebSocket address; an export directory with arguments and variables, its log followed, stopped, removed; a 5 MB log bounded; the terminal driven through a pty: stty size 30 100, then 40 120 after a resize, exit 3). Files and the shell's pipes are in tests/t0/agent.sh.
Limits, each a ponytail comment and a line of later.md: links left out of transfers, blocking writes to a shell's input, an app known by its pid file, no reverse forward. Doc: docs/reports/zinc-next-agent.md.

Added after closing, same day: zinc device reverse <device-port|0> <local-port> (adb reverse): the agent listens on its own address, names each connection it takes on the client's session, and a session of its own carries it to the workstation's port. tests/t1/agent_apps.sh: the device fetches a page of a server of the workstation through it. With it the notes' 'no reverse forward' no longer holds.
