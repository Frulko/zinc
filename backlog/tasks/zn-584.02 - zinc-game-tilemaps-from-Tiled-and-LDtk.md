## Implementation Notes

- Need → provider → gap: Tiled/LDtk parsing and culled drawing already live in `src/assets/tilemap.cpp` (yyjson) and `plugins/tilemap/index.ts`; `zinc:game` now reexports `loadTileMap`, `TileMap`, `Level`, `Layer`, `MapObject`, `Properties`. No duplicate parser or additional dependency. Existing asset rules, lifetime and errors are preserved.
- Delegated pre-task research supplied by coordinator: Tiled GIDs clear all four high bits and apply diagonal before horizontal/vertical flips (https://docs.mapeditor.org/en/stable/reference/global-tile-ids/); map JSON describes external relative tilesets, margins/spacing, offsets and bottom alignment (https://github.com/mapeditor/tiled/blob/master/docs/reference/json-map-format.rst). LDtk schema specifies reverse layer order, pixel positions, flips and total offsets (https://ldtk.io/files/JSON_SCHEMA.json). Existing importer covers these paths; documented finite orthogonal/format limits remain.
- Scope: game export, game T0, existing tilemap fixture's import, API docs and changelog. Existing T1 now exercises the game import, including transitive tilemap/sprite discovery; no new demo or suite.
- Proof: common read-only zinc compiled 7b47aef28 with `ZINC_ROOT` this tree. `zinc check tests/data/game/main.ts` passed; exact `tests/run --only game` passed all three engines. `.logs/game584/proof.sh` ran the existing real tilemap fixture for two headless deterministic frames per engine, checked expected metadata/draw counts and equal frame hashes. Native/interpreter/QuickJS hash: `442439ac4b8ed9c3`. Logs: `.logs/game584/{check,t0,proof}.log`, per-engine stdout/stderr/hash. No engine build or timing/performance claim; no owned process left.
- Lean import check: a plain `Scene`/`SceneController` source without any plugin declaration compiled with `--emit=cpp` (`.logs/game584/plain.{ts,cpp,err}`). No tilemap loader/drawing implementation symbols remain in emitted C++; generic embedded method metadata still contains `drawLayer`, so total-byte elimination is not claimed. Existing tilemap import initializes an empty atlas array only; no asset I/O or listeners.
