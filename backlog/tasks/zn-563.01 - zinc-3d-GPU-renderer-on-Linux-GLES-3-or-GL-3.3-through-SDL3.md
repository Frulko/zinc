## Implementation Notes

2026-11-12: Linux desktop now selects the existing renderer through a private SDL/OpenGL ES 3 dispatch. The renderer uses the vendored glad declarations, checks the actual ES version and every used GL function, uses GLSL ES 3.00, and falls back to software when the host has no SDL window module or a context cannot be created. No GL/SDL development package, new SDK, linked libGL/libGLES/SDL dependency or core/HAL edit was added. macOS keeps its GL3.2/GLSL150 path and deterministic/software selection remains unchanged. GLES interpolation and unsupported depth visibility are documented; no SSIM claim is made.

Primary research supplied before work: SDL GetProcAddress/CreateContext/LoadLibrary documentation (https://wiki.libsdl.org/SDL3/SDL_GL_GetProcAddress, https://wiki.libsdl.org/SDL3/SDL_GL_CreateContext, https://wiki.libsdl.org/SDL3/SDL_GL_LoadLibrary), Khronos ES3 (https://registry.khronos.org/OpenGL/specs/es/3.0/es_spec_3.0.pdf), and the existing pinned glad provider (https://github.com/Dav1dde/glad). Existing private-table patterns in the SDL HAL were read, not edited. The new Linux path calls only the existing exported zn_window_load when present and resolves its SDL functions from RTLD_DEFAULT; it does not dlopen another SDL library, install anything or change a service.

The SDL bootstrap has explicit NotTried/Resolving/Ready/Unavailable transitions, an atomic publication and mutex for resolution, a complete immutable table before use, cached unavailable reasons and a ready fast path without dlsym. An initial off-main-thread call defers admission; a later off-main-thread call cannot invalidate a ready table. Context admission uses NotTried/Opening/Ready/Failed/Closed with RAII rollback and restoration of the previous SDL context. Context failure is cached. The renderer remains main-thread-only, not a new general concurrent GL API, and SDL quit/restart/VM-unload ownership is not claimed fixed.

GPU meshes and targets use private generation-safe handles with 20 slot bits/11 generation bits and retirement on exhaustion; stale get/deform/draw/free cannot affect a replacement, and stale target resize is refused. The software staging mesh is still internal; shared software/world and console pools were deliberately not migrated. Existing world mesh handles are int32 values and flow unchanged through draw/free, without desktop tag masking. PSP tag schemes and console sources remain unchanged.

Installed source payload includes existing SDL public API headers/licence and glad declarations. The focused test executes the two actual tools/package payload operations and verifies/compiles staged headers without staging the entire package. Added raw source payload is89 files/3,800,642 bytes, not a compressed package size or runtime-memory measurement. tools/package keeps its existing full package/budget checks for a selected milestone.
