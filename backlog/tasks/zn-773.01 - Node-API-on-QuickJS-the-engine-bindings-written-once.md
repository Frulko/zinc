## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Owner asked for the fastest path (2026-10-21: 65 ns against 13 is not acceptable, get close to 13). JsRuntimeHost's QuickJS Node-API as vendored cost 65-83 ns for a two-number call and leaked a callback's values; patched (third_party/node-api/patches/0001): handles by value in blocks, a scope around every callback, arguments read in place, numbers read from their tag, plus napi/inline.h for the engine's own bindings: 26-28 ns against 21-22 direct, empty call 15-16 against 12-13 (perf log). A real binding shows no difference (Canvas 2D beginPath+moveTo 164-166 vs 167 ns). Decision: Node-API is the one binding ABI; the __host_* rows (the hottest, generated from include/zn/runtime.h) keep a direct path per engine; structuredClone and module() of webenv stay QuickJS's own (engine services: each engine gives its own). Hooks (include/zn/js_ext.h) now receive a napi_env; WebGL still binds QuickJS through contextOf(env) until ZN-773.02. AOT programs that use zinc:script link libzn_napi_qjs.a. Tests run: napi (new, T0; it fails with the callback scope removed), qjs, qjs_native, qjs_robust, qjs_demos, qjs_bundle, segment, physics3d, script, webenv, webenv_canvas, webenv_canvas2d, webenv_canvas2d_full, webenv_canvas2d_libs, webenv_image, webenv_p5, webenv_phaser, webenv_pixi, webenv_three, webenv_audio, webenv_gamepad, webgl_module, webgl_js, three: all pass. later.md lines for the coordinator: none.
