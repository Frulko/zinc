## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`zinc agent` listens on TCP and announces `_zinc._tcp` over mDNS. A client pairs once with the code the agent shows (a PAKE, so the short code cannot be attacked off line), which gives it a key of its own; every later session is TLS with that key. `zinc device list|pair|unpair|info`. No crypto of our own: mbedTLS.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-10-12. src/agent (agent.h public; wire: TLS session over a non-blocking socket, frames, JSON, file transfers; mdns: announce and browse; server: zinc agent; client: zinc device), compiled into zinc.
Decision D116: pairing is TLS 1.2 EC J-PAKE with the 6-digit code (three tries, 5 minutes, one workstation), sessions are TLS 1.3 PSK with ECDHE, a key per workstation; all mbedTLS (MBEDTLS_KEY_EXCHANGE_ECJPAKE_ENABLED turned on in the vendored config, host/tls.h gained openPskClient, openPskServer, openPake, randomBytes). Discovery: mjansson/mdns 1.4.3 vendored (third_party/mdns), service _zinc._tcp.
Found on the way: tls::read returned after a TLS 1.3 session ticket with the bytes behind it unread (fixed, tests tls and net pass); an agent bound to one address answered mDNS on every network (now only where it listens); mbedTLS has no thread support in our build, so the agent's threads share one lock around its calls; SIGPIPE ignored by the agent stayed ignored in the programs it started (reset before exec, regression check in the test).
Measured on the loopback interface (M1 Pro): a session with one request 35 ms, a shell command 43 ms; 227 KB of code in zinc.
Tests: tests/run --only agent PASS (discovery, three wrong codes close the pairing, a made-up key refused, pairing by name, key files 0600, info and --json, shell, eight sessions at once, push and pull, a name outside the destination refused, forget). Also PASS: tls, net, cli_core, security_guide.
Not proven: Linux (the code is there: /proc figures, forkpty with libutil; line in later.md, cross-platform pass); two machines over a real network (only the loopback interface and this Mac's interfaces). Doc: docs/reports/zinc-next-agent.md.
