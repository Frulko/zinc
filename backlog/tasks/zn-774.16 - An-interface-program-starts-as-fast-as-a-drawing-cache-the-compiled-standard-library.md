## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-10-22 (parallel worktree, ZN-774.16).

Why the cache seemed not to apply: the ZBC cache of ZN-415 (~/.zinc/cache/zbc) already served a plain headless `zinc run` of sample 12 on its second run (0.01 s, 155 M instructions). The measurement of 0.32 s / 3.4 G instructions on every run is a run with ZINC_DETERMINISTIC=1 (tests/run exports it; it turns the cache off by design): measured here 0.33 s / 3.41 G with it. The real gaps were: (1) zinc dev never used it: its child runs in hot mode and needed the keys of a compile, so every start compiled the whole program (sample 12 with the inspector: 23 files, 815 functions, 0.58 s); (2) zinc dev rewrote build/.zinc-dev/main.ts (the inspector entry) at each start, which would have staled any entry; (3) a windowed run that cannot build natively (no engine libraries or C++ compiler) loaded the cached ZBC, then threw it away and compiled.

What changed (src/main.cpp, src/cli_core.cpp): zinc dev child caches its whole hot unit (dev/hot.h save/load: ZBC, stable keys, modules, resources) under a key of its own (" hot"); a Fast Refresh after a cached start works (checked by hand: v1 refreshed src/main.tsx). inspectEntry writes main.ts only when its text changes. A windowed run that cannot build natively uses the cached ZBC (canBuildNative, one shell once). Key = entry + profile + strict + hot + engine root (ZINC_ROOT); signature = version + engine binary stamp + compiler variables (as before); inputs = every source (absolute now), its directory (a file added beside it), every tsconfig.json and package.json above it (stamp "-" when missing, so creating one recompiles), zinc.json, lib/std, lib/compat, lib/fonts, assets, plugin dirs, and the cache files themselves (program.zbc, resources.bin, modules). A damaged entry (unreadable ZBC or unit) says "damaged cached program; compiling" and compiles. gRoot is absolute (a relative ZINC_ROOT stays valid after the run moves into its project).

Why whole-program, not per module: the checker instantiates generics where they are used, the optimiser inlines and devirtualises across modules and removes unreachable functions and classes, and the ZBC has one table of strings, classes, selectors and globals: lib/std compiles to no ZBC of its own a program could link. A 7-line zinc:ui program compiles in 337 ms, as much as sample 12 (336 ms): all of it is lib/std, paid again at the first run of any program and at each edit. Separate compilation is a larger change (later.md line below).

Measurements (Mac of 2026-10-22, load 6 to 7, not quiet; headless, 120 frames, /usr/bin/time -l, best of three; first = fresh ZINC_HOME):
- 01-window-and-shape: first 0.04 s, 16 MB, 458 M instr; second 0.00 s, 6.5 MB, 49 M instr.
- 12-a-small-app: first 0.35 s, 62 MB, 3.86 G instr; second 0.01 s, 9.2 MB, 155 M instr (before this task: the same, the cache already applied; with ZINC_DETERMINISTIC=1: 0.33 s, 67 MB, 3.41 G).
- zinc dev child of sample 12 with the inspector (zinc run build/.zinc-dev/main.ts, ZINC_HOT=1): uncached 0.58 s, 92 MB, 6.16 G instr; cached 0.02 s, 13 MB, 221 M instr.
For docs/reports/zinc-next-perf.md (PERF-16), written by the coordinator.

Tests: tests/t1/zbc_cache.sh extended (3.2 s): sample 12 headless twice (hit), an edit of a copy of lib/std/ui.ts under ZINC_ROOT (miss, then hit), a damaged program.zbc with its size and time kept (miss, the run succeeds), zinc dev --no-devtools started twice (second start cached); it fails on the previous engine (zinc dev, second start: compiled). Passed one by one: zbc_cache, run_cache, run_compiled, hot_swap, fast_refresh, dev_mode, asset_reload, learn_samples, package.

Lines for backlog/later.md:
- ZN-774.16: separate compilation of lib/std (a linkable ZBC per module, or the checked and lowered std kept between compiles) so the first run of a zinc:ui program and each Fast Refresh stop paying ~330 ms for lib/std: a 7-line zinc:ui program compiles in 337 ms, the same as sample 12; needs generics instantiated per module, inlining after the link and one string/class table built at the link.
- ZN-774.16: a windowed zinc run whose native build fails (a Mac without the Command Line Tools: /usr/bin/c++ is a stub) compiles the program and tries the C++ build at every run before it interprets; remember the failure beside the run cache and start from the cached ZBC.

Decision to record (coordinator): the compile cache stays whole-program (reasons above); per-module caching waits for separate compilation.
