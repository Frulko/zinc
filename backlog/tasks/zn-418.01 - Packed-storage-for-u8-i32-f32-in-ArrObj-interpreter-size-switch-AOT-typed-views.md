## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Review 2026-11-07, from backlog/later.md: ZN-typed-arrays: real typed arrays (`Uint32Array`, `Float64Array`... with `set(src, offset)`, `subarray`, `fill`) as the standard JS API; a block copy between two arrays is one native call (`dst.set(src.subarray(a, b), off)`, the form engines document as the fast one), and the data is dense on small boards. Pixel Plays copies its frame buffers element by element in the interpreter (19 ms against 3 ms in AOT); `copyWithin` (done) covers only one array.
Review 2026-11-07, from backlog/later.md: chat-10m (2026-11-07, docs/reports/zinc-next-perf.md): `u8[]`/`i32[]`/`f32[]` keep 8 bytes an element on the interpreter and the compiled run (10 M `u8`: 188 MB peak); compact storage by element type would cut a big data set 4 to 8 times; and `Uint8Array`/`Int32Array` are refused outside `zinc:gl` although they are standard TypeScript.
