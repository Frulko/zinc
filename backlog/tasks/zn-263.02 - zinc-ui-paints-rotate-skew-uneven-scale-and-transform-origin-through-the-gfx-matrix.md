Research (sonnet search): Tailwind's nine origin-* keywords and `origin-[33%_75%]` (https://tailwindcss.com/docs/transform-origin); React Native's transformOrigin, default centre, keywords/%/px, z ignored in 2D (https://reactnative.dev/docs/transforms); CSS composes T(o)·M·T(-o) with o in the element's own box, keywords in either order (https://developer.mozilla.org/en-US/docs/Web/CSS/transform-origin); hit testing inverts the whole matrix; SW vs GL anti-aliasing differs at 15/45 degrees, so GL is held to a tolerance (ui_style_gl.sh already does) while 90 degrees is near exact.

Done:
- lib/std/ui.ts: TransformX carries an origin (fraction of the box + pixels per axis, centre by default); tfOX/tfOY replace the hard-coded centre in paint (even scale fold, pushTf, the compositor layer), hitIn, scrollerAt and boxOf. With the default origin the arithmetic is bit-identical (x*0.5 vs x/2), so today's frames do not move: tests/golden/style-transform kept its hash b7b7d16ae9040fcc with the new code before it was extended.
- `origin-*` classes (origin-center, -top, -top-right ... -left, origin-[25%_75%], origin-[10px_bottom]) and React Native's `transformOrigin` string ('top left', '10px 20%'), lowered by src/frontend/jsx.cpp to the `@origin-[..]` token; jsx.cpp validates origin-* classes.
- Goldens: tests/golden/ui-style/transform-15/45/90.tsx (rect, border, shadow, image, text; centre and origin-top-left rows) with their software hashes; ui_style_gl.sh runs the same scenes through the GL replay at its tolerance. tests/golden/style-transform gains a card turned 90 degrees around its top-left corner (transformOrigin) and a child turned inside a parent scaled 1.5: hits at the corner, inside, beside and in the old box (hits.out, frame.hash re-recorded). Hits pass on the interpreter, AOT and QuickJS.
