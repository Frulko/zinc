## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
An editor application of its own (examples/pinball3d-editor, written with zinc:ui, embedding the game of examples/pinball3d) that makes a complete new table without touching code or JSON: a top view to draw and edit walls and lanes (points, arcs, snapping, mirror), a palette to place, move, rotate and delete every element kind of the format, a property panel for physics (restitution, friction, forces), look (primitive or mesh asset, material, colour, light) and sounds per event (with preview), the rules (scores, missions and their steps), a live 3D preview beside the top view, test play from the current state, undo and redo, save, load and duplicate tables. (Owner request, 2026-10-10: a pinball all in real 3D instead of fake 3D, with a suited physics engine, a vertical table in the style of Space Cadet, parametrable in its lanes and assets, with a complete editor to make new tables, visual and sound.)

Owner's answers, 2026-10-10: a SEPARATE application, not a mode of the game: it embeds the game (table loading, scene, physics, rules) to play the table being edited without leaving the editor; for someone who does not code and with direct access to the file for fine tuning (the file stays readable and stable under load and save); everything is editable: paths and elements with their heights (ramps, rails, upper playfields), physics and look, sounds and music with preview, rules and missions; it works in a folder and exports one package file.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Slice 1 (2026-10-10, parallel agent, branch worktree-agent-aebb79adb81c0ac02): examples/pinball3d-editor, a separate application (own zinc.json) that imports the game's format and geometry from ../pinball3d/src. A table folder opens (argument, or Open); the top view draws every placed thing from the file with the game's own geometry (tessellate, flipperOutline, offset): walls, gates, flippers with the swing as a ghost, the plunger, bumpers, slingshots and kickers with their kick or exit arrow, standup and drop targets, rollovers, spinners, ramps (the track shaded by its height, chevrons for the way), wire rails, upper playfields, lights by shape and colour, models; heights are read twice: a shadow as long as the thing is tall, and a side view (the table seen from its right: foot to top of each thing, the height profile of each ramp, the glass). Pan (drag the background), zoom (wheel, buttons, Cmd+0 fits), select (click on the table or in the list at the left), move (drag, arrows), turn (round handle, R, the 15 degree buttons), delete; a property panel generated from the schema; undo, redo; save. Test: next/tests/t1/pinball3d_editor.sh (17 s): PASS pinball3d_editor.

Decisions of slice 1 (to file; reversible):
- The document is the format's own tree (Table.data), never typed per kind: every operation is said with a path as the loader writes it (flippers[1].speed, walls[2], plunger) and resolved through the schema (doc.ts: set, move, turn, remove, replace). Why: the owner wants a field added to the format to appear without editor code; a typed model per kind would need a line per field. Checked: selftest 'ok: the sound of an event is a choice among the sounds of the table'.
- Every operation is checked by the game's loader before it replaces the document (parseTable on the changed tree); a refused change is not made and the status bar shows the loader's message, which names the field. So Save never writes a file the game refuses, and the editor repeats no limit of the format. Cost: one stringify, parse and check per edit (17 KB table: not measurable in a session).
- Mending by the loader's faults instead of knowing the rules: a rename (id, group) gives the new name to every value a fault points at that still holds the old one; a deletion clears the optional references a fault points at and deletes the outermost list item (the rule, the mission) of any other fault, then checks again (12 rounds at most). Why: the targets of conditions and actions are plain texts whose name space depends on the test (table.ts checkRules); copying that table into the editor would drift. The status bar says how many things went with a deletion; one undo brings all back.
- Undo keeps the whole tree and its text per step (17 KB each); 'unsaved' compares the canonical text with the bytes on disk, so a file written another way is unsaved as soon as it is opened and Save rewrites it canonically.
- What has a place on the table, and how it moves and turns, is derived from the SHAPE of schema fields (required row of 2-3 numbers = a point, rows of up to 3 numbers = a path, a number ranging -360..360 = a direction), marked ponytail in doc.ts; asked of the format's owner: an explicit role per field.
- A field's form control comes from its Kind (number with limits, switch, segmented or list for an enum, list of the table's names for a reference, colour swatch and text, row of numbers); labels come from one table in strings.ts keyed by field name (English and French), a key the table lacks is shown made readable; the help is the format's own doc line (English only: see follow-ups).
- Frame and file goldens run on a table kept with the test (tests/golden/pinball3d-editor/table.json, Tidal Lock of 2026-10-10) so that the game's table can change (looks, sounds) without moving them; only 'opened and saved untouched is byte-identical' also runs on the game's live table.
- Frames are compared by bytes first and by tools/pngdiff only when the bytes differ: pngdiff takes 3.4 s per 1440x900 frame (11 frames: 39 s of a 69 s test, 17 s after).
- Copied from the museum editor (examples/museum-table/editor, D76) into examples/pinball3d-editor/src/widgets.tsx: Ico, Tool, Action, Segmented, Heading, the colours, DRAWN; same patterns for doc/state/strings/selftest. Proposed follow-up: a shared editor kit.

Engine and zinc:ui findings (no shared file touched in slice 1):
- 'e instanceof TableError' is false once the caught value went through a parameter typed any (true on the catch variable), compiled and --interp. Repro: class MyError extends Error; function viaAny(e: any): boolean { return e instanceof MyError; } in a catch: direct true, viaAny false.
- A cast or an assignment from any to a typed array or an interface COPIES and converts (const items: any[] = dyn; items.splice() leaves the tree untouched; new Table(raw, null) throws 'cannot convert Dyn (undefined) to number' on a tree without its defaults). The editor rebuilds lists through the dynamic value.
- JSX: {list.map((x, i) => cond ? <A/> : <B/>)} renders the node handles as text ('388,397,406'); a map whose arrow returns one JSX element works. Worked around with a component that holds the condition (form.tsx Entry).
- tools/pngdiff is 3.4 s per 1440x900 frame (pure Python).

Repair after the format grew (2026-10-10, commit after 55607fbc): the roles of the format replace the guesses (doc.ts isPoint, isPath, isDirection, isRotation read Field.role), Field.unit is shown beside numbers and in the help, checkTable(tree) replaces the text round trip. The test no longer depends on how many fields or lists the format has: sessions reach a field by its key (Cmd+F: the box that finds a field of the selection, exact key alone, else what holds the text), a thing by its path or name (Cmd+G: go to), the selection's text by Cmd+J; a frame is its golden's bytes or else the same picture in the top view and heights (tools/pngdiff --crop, new); the generated form has its pixels on a schema of every kind kept in the editor (src/formcheck.tsx, English and French). Proof on a copy of the tree whose format had three more fields (two before the fields the sessions edit) and one more list: 'pinball3d_editor: ok' in 37 s (18 s when nothing changed: every frame then falls back to the 3.4 s pixel comparison). Shared file touched: next/tools/pngdiff (--crop X,Y,W,H).

Slice 2 (2026-10-10): drawing. A selected path shows its points on the top view: a square moves a point, the round dot of a stretch bends it into an arc (the bulge of the format; near a straight line, a quarter circle or a half circle it is that exactly), a double click on a stretch adds a point, a pressed point then Delete takes it away; every thing with two points (gate, slingshot, rollover, spinner) has the same squares. Points snap to the points of other things, to the table's axis and to a grid (5 mm, 1 cm, 1 mm, off; Alt frees a drag). The palette (presets.ts) has a line for every list of the format whose items have a place, with the top view's own drawing of it as its picture; clicks then place it in the order of its fields (one per point, then its path, Enter or a double click ends). Ramps and rails are a path plus a height profile shaped as a curve in the panel; an upper playfield is an outline and a height. The plunger lane is one entry and one undo step (wall, gate, plunger, from the size of the board and of the ball). Duplicate (Cmd+D), Mirror (M): the mirror image about the axis, the name with left and right exchanged. Test: PASS pinball3d_editor (27 s), sessions draw.input (drawn.json, five frames) and lane.input (lane.json, two frames).

Decisions of slice 2:
- A point or an arc being dragged changes the document as it goes, the whole drag being one undo step (Doc.set with merge), instead of a preview drawn apart: the element is then drawn by the one code that draws it, and the panel shows its numbers live. Cost measured: 8.3 ms an edit on the 17 KB table (12.9 ms before checkTable replaced the text round trip), load 4.2; moving and turning a whole element keep their cheap preview.
- The palette is data (key, list, name in two languages, the fields beyond the defaults as JSON) plus one generic entry per list the file names nothing for, so a kind added to the format can be placed at once; an entry is also reached by its key in the go-to box (+wall), which is what the scripted sessions use.
- Mirror is said by the roles (points, paths with their bulge negated, directions, rotation) and three guesses marked ponytail in doc.ts mirrorItem: a number in degrees with a symmetric range is a swing that changes sign (flipper.stroke), a choice between left and right takes the other word (flipper.button), kicker.exit by its name; two points change places so that a side (the kick of a slingshot, the way through a gate) is mirrored too. Checked on Tidal Lock: the mirror images of guideLeft, slingLeft and the left flipper about x = 23.85 are byte for byte guideRight, slingRight and the right flipper.
- The table's axis is not the middle of the board when there is a plunger lane: it is found when a table opens (the middle between a left and a right flipper, else the middle of the board), shown as a dashed line, and moved by its marker on the ruler; it is not kept in the folder (ponytail in state.ts; follow-up: an editor.json beside table.json, or a field of the format).
- Asked of the format's owner: a role for kicker.exit (an offset that turns and mirrors with its kicker), a word for a path that closes by itself (floor.points; known today as a path that needs three points).

Slice 3 (2026-10-10): the game played in the editor. The pane beside the top view shows the heights or the table in 3D (V): the game's own scene (TableScene) built from the document at every change, seen as the table's layout looks at it (the portrait layout's camera in a pane taller than wide, the field of view opened to the pane's shape). B then a click on the top view drops a ball there (Game.placeBall); P starts a game as a player does, pauses and resumes; O steps a paused game by a frame; Escape ends it. The game runs with the table's rate, physics, rules and sounds (TableAudio.update each frame) and the game's own controls (input.ts readControls: its keys, pad buttons and touch zones). The top view shows each ball where the physics has it (its shadow farther the higher), what the balls touch (white, from the physics' touches) and the switches and rules that fire (green, with the name of the event, from the game's log); the pane shows the score, the ball, the step of the mission and the last lines of the log. W opens the game's own window: the table and its score panel drawn by the game's code (View, drawPanel) with a camera of its own; keys pressed there play too. --log prints the game's events. Test: PASS pinball3d_editor (49 s): play.input (play.log, four frames of the top view, the 3D pane and the window), flip.input.

Decisions of slice 3:
- Nothing of the game is written again: play.ts imports Game, TableScene, TableAudio, readControls, View and drawPanel from ../pinball3d/src. Proof: the events of a ball dropped at (17.5, 20) in the editor are, line for line, those the game's tools/probe.ts prints for the same drop ('0.404 pop1 hit +500 = 500', '0.477 lane1 roll +1300 = 1800').
- A change of the table ends the game being played and rebuilds the scene: the next game is the changed table's. The game and its physics are made when a game is first asked for, the scene whenever the 3D pane is shown. Not measured: what a rebuild costs per edit while the pane is open.
- The code that runs while views are drawn writes no signal (play.ts drop()): a stale table is found out when its scene is asked for, and advance(), once a frame, says that no game runs any more. (Writing a signal there looped: 'runtime error: stack overflow'.)
- The 3D pane and the game's window are the game's drawing, which the look task changes: their frames are held to the golden's bytes or else to SSIM 0.5, and to showing the game (a frame with a ball in play is not the frame of the table waiting for a player); the top view beside them keeps exact pixels.
- Not verified: the sounds (a headless run has no audio output: TableAudio is called, nothing is heard), a real window on screen for the game's window (headless frames only), the keys of the game typed in the game's window (the script presses the pad button in the main window).

Slice 4 (2026-10-10): sounds, rules and levels. A reference to a sound has a button that plays it as an event of the game would (TableAudio.preview through play.ts previewSound); a sound of the list has Listen; the music of each state is four such references. A list of objects inside a form (the rules, the missions, the steps of a mission, the conditions and actions of a rule, the high scores, the lamps, the items of a panel) is a line per item that says what the item is (doc.summaryOf: 'pops hit [score 500, bonus 100]') and opens the item's own form, with the way back above it (Rules > mission), Add, Duplicate, Delete and the two arrows that move it in its list; ball save, extra balls, the multiplier, tilt and multiball are the fields of the rules. A long list of names opens with a box to type in (the 70 elements of a table). The go-to box adds by kind: +sound, +look, +rule, +mission, +step, +action, to the list of that kind nearest the selection. The top view shows the painting of the board (look.texture, read by the game's images.ts) under a veil, models as outlines, and has a level switch (L) when the table has upper playfields: with a level chosen, what stands on the others is only hinted at and not picked, a ball is dropped on that level, a new thing stands on it. Roles offset (kicker.exit turns and mirrors with its kicker) and area (floor.points) replace the two workarounds. Test: PASS pinball3d_editor (49 s): rules.input (rules.json; 'preview: sound1 vol 1.00 rate 1.00' in the log; the game's probe on the saved file gives 'pop1 hit +800 = 800' for the rule made in the editor), levels.input (levels.json: the bumper placed on the level has z 5).

Decisions of slice 4:
- The rules are edited through the same generated forms as everything else: a selection can be any object of the file (rules.when[3], rules.missions[1].steps[0]), a list inside a form is lines that open their item. No screen written for rules: a field or a kind of action added to the format appears. What this does not give, and is proposed as a follow-up: a guided view of the scores (a grid of element or group by event) and of a mission as a sentence.

- The level a new thing stands on is its field z, known by its name (ponytail in state.ts): a role for it is asked of the format's owner.
- Not verified: that a sound is heard (headless: the call is logged, nothing sounds); the painting of the board in a frame golden (the test's table has none: seen on the live Tidal Lock, screenshot only).
