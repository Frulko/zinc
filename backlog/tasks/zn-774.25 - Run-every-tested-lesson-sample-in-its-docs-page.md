## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Research (sonnet sub-agent, 2026-11-08): make the frame on click (web.dev facade pattern, https://web.dev/third-party-facades), not loading=lazy; Restart = a new iframe (reassigning the same src may not reload); focus the iframe on the click and on load; detect import maps with HTMLScriptElement.supports('importmap') (Chrome 89, Firefox 108, Safari 16.4; https://developer.mozilla.org/en-US/docs/Web/API/HTMLScriptElement/supports); one frame at a time, removing it stops loops, audio and the GL context; an aria-live line for running/stopped.
Decision (for the decision log): the lessons run from the web exports the gallery already commits (site/public/play/<lesson>/, tools/site-examples, ZN-774.36: `zinc export --target web`, the program as JavaScript on the browser's engine, about 40 KB a lesson), not from .zbc on vm-web.wasm as option A of docs/reports/onboarding-benchmark-docs.md wrote before the web target existed: no 1.6 MB wasm, no COOP/COEP service worker (whose first load needs a reload), the same files the gallery shows and tests/t1/site_examples.sh checks. Criterion 1's 'samples the web VM can draw' becomes the samples whose export has no native side without a browser backend (examples.txt; all 20 today), the others keep their picture with the line 'runs at home only: its X side has no browser version yet'; criterion 2's 'without wasm or cross-origin isolation' becomes 'without import maps (or WebAssembly when the export lists wasm modules)', the only things an export needs.
Done: site/src/components/DocPage.astro: on a learn/ page whose sample is in learn/catalog.txt, a Run block (data-pagefind-ignore) moved by an inline script under the lesson's picture: 'Run it here' puts an iframe of /play/<lesson>/ (scaled to the column as the gallery does) in the picture's place, then Restart (a new frame) and Back to the picture (removes it); the hint and an aria-live line; strings learn.* in the five languages (site/src/i18n). French pages run too (lesson 06 checked).
Proof (site built with astro build; headless Chrome through tools/web-browser-test, by hand): lesson 01: Run, 184 frames in the frame after 3 s, canvas drawn, Restart shown, the iframe focused, 'The program is running.'; with HTMLScriptElement.supports removed: no button, the picture stays, the line names the browsers and `zinc run docs/learn/samples/01-window-and-shape`; fr lesson 06 (sound): 191 frames. Frame of the export (640x400) against the native run (ZINC_HEADLESS, deterministic, frame 3): 208 px differ (the circle's antialiasing, max diff 37, PSNR 57 dB). 20 lesson pages carry the block (en), fr too. tools/i18n-docs-check: no error. Written, not run: tests/t1/learn_web.sh (all of the above; tests/affected.json maps it).
Note: a bare `astro build` does not copy docs/learn/img (the 'assets' script of site/package.json does): pictures are broken in such a build only.
