## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The 3D half of ZN-583, needed first by the 3D pinball (ZN-649). A plugin `plugins/physics3d` on Jolt Physics (MIT), vendored inside the plugin with its licence, pinned version and checksum: a world with a fixed step and deterministic stepping; static, kinematic and dynamic bodies; shapes (sphere, box, capsule, cylinder, convex hull, triangle mesh, height field); continuous collision for a small fast body (a pinball); hinge constraint with motor and limits (flippers), slider constraint (plunger); contact added / persisted / removed events with the impulse; sensors; ray and shape casts; per-body friction and restitution; layers and collision filtering. A typed API for compiled Zinc code, the same calls from the interpreter and from QuickJS. No physics in the engine core: a plugin, loaded by programs that import it. (Owner request, 2026-10-10: a pinball all in real 3D instead of fake 3D, with a suited physics engine, a vertical table in the style of Space Cadet, parametrable in its lanes and assets, with a complete editor to make new tables, visual and sound. Owner's answer the same day: complete 3D physics, not 2D in the table plane.)

Decisions (RULES section 4: fit x3, performance x3, size x2, maintainability x2, licence x2, portability x1, effort x1)
- Library: Jolt 5.6.0, the owner's choice of real 3D. Scored for the record: Jolt 62 (5 5 3 4 5 4 4), Box2D v3 in the table plane 58 (2 5 5 4 5 5 4: cannot do jumps, ramps as volumes or upper levels), Bullet 3 46 (4 3 2 2 5 4 3), hand-written 43 (2 3 5 1 5 5 1, and RULES section 3 forbids it).
- Vendored inside the plugin (as sqlite, audio), the library's own files unmodified, without the parts nothing includes (compute, shaders, hair, vehicle, character, ragdoll, skeleton): 4.3 MB instead of 5.5.
- Four unity translation units: 30 s with Apple clang, 48 s with the pinned zig, against a quarter of an hour file by file. The builder needed one rule: C++ sources under vendor/ go to vendor.a (scored against a new manifest key: same result, one more parser change, 0 existing plugin has C++ under vendor/).
- The plugin registers the shapes itself instead of calling RegisterTypes(): that function's type factory only serves serialization and references every subsystem.
- One thread (JobSystemSingleThreaded): exact, no thread to manage on small targets. A thread pool is a follow-up.
- API: step() once, then two bulk reads (moved bodies, events) decoded into plain fields, instead of a native call per property: 3 native calls a step on every engine, which is what keeps QuickJS near the compiled time.
- QuickJS: a generic bridge for native modules (any plugin's index.ts runs there) rather than a JavaScript binding written for physics: scored 5/4/4 against 3/5/2 on fit, performance, effort; proven on the C test module too.
- Contact impulse: Jolt calls the listener before it solves, so the impulse is its EstimateCollisionResponse at that moment (4 iterations), plus the approach speed.
- -O3 for the library: no measurable gain (4.55 to 4.79 ms against 4.5 to 4.6), not kept.

Findings the pinball must apply
- A kinematic body that sweeps INTO a continuous ball is seen at its end-of-step pose: at 240 Hz 2 of 2,500 slow balls end behind a flipper turning at 40 rad/s; from 480 Hz none. The pinball should step at 960 Hz (4 x 240), as the old one did.
- Two continuous bodies flying at each other are missed when each travels less than the gap but both together more (Jolt casts body 1's box along its own motion against where body 2 was): 941 of 2,500 head-on shots at 240 Hz. With collision steps = ceil(closing speed x dt / (0.5 x radius)), 0 of 2,500 (also 0 at 1 radius, 1 at 2 radii).
- Sensors are not swept: a fast ball crosses a thin sensor unseen. Rollovers and gates should be tested in the game from the ball's positions before and after a step.
- Jolt's default speed limits (500 units/s, 47 rad/s) are too low for a pinball in centimetres: maxSpeed and maxAngularSpeed are body options.
