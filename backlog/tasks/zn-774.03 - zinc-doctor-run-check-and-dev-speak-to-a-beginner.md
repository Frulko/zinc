## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done (parallel worktree, 2026-10-22).
- zinc doctor: the rows are gathered first, then the title, the verdict ("Ready: you can make and run programs on this machine." or "Not ready yet", exit 1, when the engine files, <root>/lib/std, are missing), the rows, Worth doing, "Start with zinc new game hello && cd hello && zinc dev". The console SDK, iPhone 4S (ios-legacy) and Rust (cargo) rows are gone from it: --details already listed the SDKs and now has a "Rust (cargo), for the Rust code of loro" line. The plugins row: "all N ... are ready", "each one is built the first time a program uses it, once (5 to 20 s)" or "N are ready; the others are built ..."; the "A plugin without a ready library..." item no longer fills Worth doing.
- zinc run: before compiling a plugin (its vendored libraries or its own code, after the cache and the published binary missed), one step line "  plugin     building the plugin <name>, once (5 to 20 s); the next runs start at once" (src/tc/plugin_build.cpp; zn_tc links zn_i18n). It is a command step: hidden by ZINC_STEPS=0, -q and JSON logs, as tests/run sets.
- zinc check: on success prints "ok: src/main.ts and its imports checked (N files), no errors" (the files of the program, not the engine's: main.cpp engineFile(), shared with the baked-resources code).
- zinc dev: the first start is "zinc dev: v1 started" (the "(0 ms after the save)" only from v2 on, locally and on a device), then "zinc dev: change src/main.ts and save: the program updates at once. Ctrl+C stops."
- 46 messages added to i18n/<lang>/cli.json in en, fr, es, it, de (with the many forms of fr, es, it; de: Strg+C).
Decisions: "v1 started" stays as the start marker the dev tests wait on (dev_mode, asset_reload, fast_refresh, hot_swap, agent_dev, zinc_go...); the hint is a second line. zinc doctor --details stays English (the full report for maintainers, like the long zinc help details), and so do the update status and how-to-update texts that come from src/tc/selfupdate.cpp (shared with the update notice). The plugin build notice is a step line, not a TTY-only message: steps are on by default, so Atelier and a redirected run show it too, and tests stay quiet with ZINC_STEPS=0. zinc check --engine quickjs and the mquickjs check print nothing new.
Tests: tests/run --only doctor_friendly PASS (verdict on the third line, no SDK/iPhone/cargo rows, plugins row, cargo in --details, French check-up, exit 1 and "Not ready yet" with ZINC_ROOT on an empty directory), plugin_starter PASS (the first run of the starter's example prints the step line with hello-zinc, the second does not), first_run PASS (zinc check's ok line, zinc dev --no-devtools' first lines), i18n PASS (i18n-check: 172 English messages, 0 errors, 0 warnings), cli_core PASS, console_sdks PASS; build warning-free.
Not proven: dev_mode, asset_reload, fast_refresh and the other dev tests (they wait for "v1 started", still printed; they measure time, so they run after integration); the "Not ready" path on an installed Zinc missing share/zinc (proved with ZINC_ROOT only).
