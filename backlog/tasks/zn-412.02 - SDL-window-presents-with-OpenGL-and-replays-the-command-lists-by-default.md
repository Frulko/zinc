## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
targets/macos/hal_sdl.cpp presents through SDL_Renderer and rasterizes every frame on the CPU. Present with an OpenGL context of the window instead, replay the command lists with the display-gl renderer (moved where both can use it) when the context is a hardware GPU, keep the software raster as the fallback (no GL, llvmpipe, ZINC_RENDERER=cpu) and as the oracle; keep the window features (transparent key colour, frameless, always on top, text input, clipboard, cursors, live resize, fullscreen, vsync).
<!-- SECTION:DESCRIPTION:END -->

- [x] #2 ZINC_RENDERER=cpu|gl|auto chooses; auto picks cpu on llvmpipe or without GL

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
usage: n/a

Done:
- runtime/gl_replay.cpp: plugins/display-gl/src/gl_renderer.cpp moved there (git mv). Everything static, so each user has its own copy; GLR_CORE picks the desktop core profile; new resize().
- display-gl includes it from the runtime; the plugin cache key hashes it (src/tc/plugin_build.cpp).
- targets/macos/hal_sdl.cpp, with ZN_HAL_GL (Next's CMake on macOS; the prototype's builds compile it without):
  - ZINC_RENDERER=cpu|gl|auto (default auto): an OpenGL 3.2 core window, created hidden and shown once the context is a hardware one;
  - the GL replay into the window when it has the surface's size and most of the frame changed, else into its texture with a letterboxed present pass;
  - the software rows uploaded when a frame has no lists;
  - coordinates through from_window / to_window (pointer, pen, touch, IME area);
  - live resize resizes the replay at the next present;
  - SDL_Renderer kept for cpu, transparent windows, display plugins, and when no hardware GL comes up (llvmpipe, softpipe, Apple's software renderer);
  - ZINC_GL_STATS prints "zinc: window renderer gl (GPU)" or "cpu".
- CMake: OpenGL.framework linked into zn_host_gfx and into the programs zinc build writes (ZN_HOST_LIBS).
- docs/guide/06-testing.md: the window renderer, ZINC_RENDERER, ZINC_VSYNC.

Measured, bouncing-ball 200k in the default window:
- GL replay, surface 1280x960, drawn straight into the window. A sample shows no zrt::raster::render at all, only cull_pack and cull_walk (AC1).
- 119 fps with ZINC_VSYNC=0 against 94 fps on the software raster.
- With vsync on, 60 fps: the display's rate. The SDL_Renderer path asked for vsync too but ran at 95 fps.
- AOT hero opens a GL window.

Follow-ups:
- Linux GL window: ZN-412.06 (a loader that does not interpose with the WebGL module's glad).
- hero on the GL replay: 0.10% of pixels over 24 but a mean error of 4.87 against the limit of 3, the subject of ZN-412.03, next. navigation is within the limits (0.44%, 0.59).

- input, display_drivers, system_manifest, gl_renderer, gl_occlusion, gl_offscreen, dev_mode, tiles, framehash and ui pass; tests/run --changed 10 passed (AC3).
