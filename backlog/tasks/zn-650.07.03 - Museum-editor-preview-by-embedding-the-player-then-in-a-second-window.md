What exists
- The player is a class: `examples/museum-table/src/player.ts` (the former main.ts, moved with git mv): `new Player(project, firstSequenceId, lang)`, `frame(dt, x, y, w, h)` (or `update` and `draw` apart, for a zinc:ui canvas), `close()`, `setLanguage()`, `sequence`, `fault`, and the flags the command line sets (`telling`, `logging`, `pins`, `timing`, `stress`). `src/main.ts` is the window and the command line (45 lines).
- `src/files.ts`: where the files a project names are read (`files.picture / text / bytes / exists / path`). Default: the assets of the app. The editor puts functions there that read the project's folder; the player itself never imports zinc:fs.
- `src/stage.ts`: the 3D views a player made are its own (`Views`, freed by `Player.close()` through `ObjectView.dispose`, `Lookout.dispose`, `PanoramaView.dispose`); they were module-level caches. `src/touch.ts`: `Fingers.update` takes the box the player has; a finger that lands beside it is nobody's until it lifts.
- `editor/preview.tsx`. "Play from here" (a button at the top-left corner of the storyboard and of a table, key P): the player takes the place of the views, from the open table, else the selected sequence, else the start, on a copy of the document as it is (saved or not), in the content language shown, with its own language button; Escape or "Back to editing" comes back, and nothing done there changes the project. "In a window" (key W): a second window (zinc:gfx openWindow, 960 x 540) that shows the sequence being edited and starts it again 0.25 s after the last change of the document or of the sequence being edited; the editor's content language switch changes its language; its clicks are its own; closing the editor closes it.
- `--story` on the editor's command line: the previews print the story log, as the table's app does.

Decisions (for the coordinator to file)
1. A class and not module state: the preview is made again for every state of the document, and a new object cannot keep anything of the last one. Two players can live at once (the pane and the window).
2. Files through functions the host replaces, not zinc:fs in the player: the kiosk reads its assets only and stays buildable where there is no file system (the web).
3. Whoever owns the window clears it: main.ts calls clear, the editor clips its pane and paints the table's colour, `Player.draw` only draws. The app issues the commands it issued before (frame hashes of the player tests unchanged).
4. The two preview buttons sit at the top-left corner of each view, like the zoom tools at the right, not in the top bar: in French, with a table open and unsaved changes, two more labelled buttons pushed the content language switch out of a 1440 pixel window.
5. The preview window follows the sequence being edited (the open table, else the selection); with nothing selected it stays where it was. It waits 0.25 s after the last change, so typing a title makes one new preview.

Limits, each marked `ponytail:` in the code
- preview.tsx: a picture decoded for the preview is kept until the editor closes; a file replaced on disk shows after a restart.
- viewer.ts `dispose`: the textures a glTF model brought are not freed (zinc:3d/gltf does not say which images it made).
