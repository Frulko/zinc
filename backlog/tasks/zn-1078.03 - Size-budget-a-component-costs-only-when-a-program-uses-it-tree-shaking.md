## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Keep the kit lean as it grows to CUI's size: no module-level side effects or central registries that reference every component, one module per family (charts, code editor, data grid, planning, AI...), icons imported one by one, themes as data. The typed engines already drop unreachable functions and unused selectors (ZN-431, rapid type analysis); the QuickJS bundle tree-shakes with esbuild. Prove it with a gate.

Reference: CUI (github.com/yappologistic/CUI, MIT, C99, ~170 components, docs/design.md, docs/components.md, docs/components-more.md, examples/). Owner 2026-11-09: same components and associated demos as CUI, a theme with the same design, its principles applied to our demos and future apps, written into AGENTS.md, CLAUDE.md and the skills, and no obesity (tree shaking).

Why the AOT side fails (engine, not kit):
1. Plugins are linked by the files the loader read (src/main.cpp notePlugins → gUsedPlugins/gPlugins), not by reachable code. `zinc:icons` (spinner, overlays) and `ProgressRing`/imageviewer import `zinc:svg`, so any kit program links the svg plugin. With a plugin present, `liteHost` is false (main.cpp around line 1371): the full system host is linked, with llhttp, mbedTLS and the network symbols (`_listen`, `_sendfile` appear in nm). A program's own unused `import { Svg } from 'zinc:svg'` does not trigger this, since the frontend drops it. Fix: after `removeUnreachable`, keep a plugin only when a surviving function calls one of its natives (or one of its Zinc functions survives); compute `liteHost` from that. Proof: kit_size passes, and the `zinc: plugins:` line is gone for Button.
2. Smaller: `devirtualize` runs before RTA. It turns `touchSecondary`'s call through `fn (f64, f64) => void` into a direct call of `ZoomView/begin`, the only class that implements it in the whole program, so ZoomView's handler stays live in every kit program. Fix: run `removeUnreachable` once before `devirtualize` too (src/ir/opt.cpp optimize), or count only constructed classes.
3. Seen in the IR: unused families still leave their class layouts. These are abstract classes, about 53 KB of module metadata (the kModule blob grows from 51 KB to 104 KB). They may need trimming to fit 4 KB per family once 1 is fixed: drop a class that no kept function names.

Next command once the engine is fixed: `tools/build zinc && tests/run --only kit_size`. Tick #1 and set Done.

Research (sonnet sub-agent, 2026-11-09):
- size-limit's `import` option measures one named export, tree-shaken, with a budget per entry: the "import one component, measure the delta" pattern (github.com/ai/size-limit). Budget a base cost and a per-component cost separately.
- agadoo (npmjs.com/agadoo) bundles "import everything, use nothing" and fails if anything is left. This is our side-effect check. The three.js and Shoelace hunts show the same causes: top-level calls, instances made at load, tables naming every export.
- Dart's tree shaker (dart.googlesource.com, kernel treeshaker) works on reachability from main; reflection or lookups by name disable it. Same failure as a registry that names every component.
- Lucide (lucide.dev, optimizations guide): icons are imported one by one, and barrel imports pull the whole set where the bundler shakes badly. Our `zinc:icons` compiles only the names written in the sources.
