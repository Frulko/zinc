### Research and reuse

- Primary reference: [CUI Planning documentation](https://github.com/yappologistic/CUI/blob/f70a1d3d095cafd67814b23bdd82c2dfba28efe0/docs/components-more.md#planning), [public structs/options](https://github.com/yappologistic/CUI/blob/f70a1d3d095cafd67814b23bdd82c2dfba28efe0/include/cui/cui.h), and [actual Kanban/week/Gantt implementation](https://github.com/yappologistic/CUI/blob/f70a1d3d095cafd67814b23bdd82c2dfba28efe0/src/cui_planning.c), pinned to `f70a1d3d095cafd67814b23bdd82c2dfba28efe0`. Read and compared the actual implementations and light/dark reference pictures, not only the component names. MIT reference; original Zinc code, no copied C implementation or new dependency. Sonnet was unavailable and agent slots full; the assigned worker performed this focused lookup.
- [WAI-ARIA APG Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/) supports a single calendar entry point, arrow navigation and an active day; drag controls also expose explicit keyboard moves and native edge handles. Current focus visibility is distinct from actual containment: cancellation checks `!ui.hasFocusWithin(root)`.
- Need → provider → gap: card drag/drop, closest-edge targeting, cancellation and autoscroll → existing `lib/std/dnd.ts` and real `examples/kanban` Board/TaskCard consumer → kit-owned ghost, declarative target/index preview and keyboard state, without its app-global signals or import-time initialization.
- Civil-day arithmetic, leap years and month movement → existing `picker-date.ts` and Calendar/RangeCalendar → scheduling placement only. Never convert calendar days through local midnight or add another date library.
- Focus/lifetime, lazy geometry drawing and overflow → existing neutral host, Canvas, native buttons, Dialog and virtual rows → one family module plus a pure model leaf. No engine/layout copy, timer, app service, auto-scheduler or new UI framework.

### Implemented scope

- Public `KanbanBoard`, `WeekCalendar`, `MonthCalendar`, `GanttChart`, props/data types and immutable `moveKanbanCard`, with caller-owned stable IDs/accessors. One `planning.tsx` family and pure `planning-model.ts`; no import-time effects.
- Kanban source-excluding target slots, WIP warning, column/board scrolling, disabled cards, add/click callbacks, pointer ghost, target/insert feedback and Space/arrows/Enter/Escape moves. Cross-column keyboard focus follows the moved card; stale source replacement rejects the gesture.
- Week collision lanes, 15-minute day/time movement and end resize, current-time/today markers, read-only click behavior and explicit keyboard alternatives. Pointer deltas include the original press threshold.
- Month four-to-six-week civil grid, inclusive multi-day span lanes, sorted timed entries, lazy virtual overflow dialog, narrow dots/selected agenda, localization arrays, today/selection, first weekday, 12/24-hour event times, page/day keyboard navigation and activation.
- Gantt bounded half-open day ranges, progress, owner list, weekend/month/day ruler, today's line, elbow dependencies and milestones, synchronized scroll, bar and both edge dragging/keyboard. Dependencies are descriptive. Stable-ID unknown/cyclic dependencies and malformed values are diagnosed; there is no scheduling policy.
- Explicit interaction/agenda/focus phases and owned cleanup; no permanent frame callback, decorative animation or reduced-motion exception. Data identity changes invalidate geometry caches; replace arrays/changed records to edit. Limits documented as correctness bounds, not performance claims.
- Four focused `GALLERY=planning PLANNING_VIEW=board|week|month|gantt` gallery entries, docs/API contracts and real Zinc light/dark/360px pictures. No app/demo test session added.
