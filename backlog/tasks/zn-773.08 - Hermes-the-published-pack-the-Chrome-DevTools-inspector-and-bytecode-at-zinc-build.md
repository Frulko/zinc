## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-10-21 (M1 Pro, loaded machine).

#1 Pack: tools/hermes-pack re-extracts and re-patches when tools/hermes-patches change (SHA-256 stamp in <src>/.zinc-patches, archive cached), always configures with HERMES_ENABLE_DEBUGGER=ON, and copies into the SDK the licences of what libhermesvm links (llvh, dtoa, zip, asmjit, boost.context, dragonbox, fast_float) beside Hermes's LICENSE, plus a version file (2026.10.21: a commit hash does not order in newerVersion). tools/engine-pack hermes takes that version; the pack is 2.0 MB (module + libhermesvm + 8 licence files). zinc-next.yml: build job caches ~/.zinc/sdk/hermes (minus src-*/build-*) keyed on hashFiles(tools/hermes-pack, tools/hermes-patches/*), runs tools/hermes-pack on a miss, packs hermes beside v8 and wasm; test shards restore the cache (fail-on-cache-miss). pages.yml needed nothing (it merges every pack of the release). tests/t0/engine_pack.sh: packs this build's hermes module, checks lib/libhermesvm and licenses/ in it, signs it into a local index, and a zinc with no module beside it downloads and runs --engine hermes (PASS). actionlint and release_workflow PASS. Help and CHANGELOG no longer say no download is published (still experimental).

#2 Inspector: the patch makes the Runtime a HermesRuntime (makeHermesRuntime, napi env on getVMRuntimeUnsafe) and adds API/hermes/zn_cdp.cpp: zn_hermes_cdp_start/message/run/pause over CDPDebugAPI + CDPAgent, console through a JSI host function __zn_cdp_console. src/engine/hermes.cpp serves it on src/dbg/ws.cpp as target zinc-hermes: tasks run at each drainJobs and in the --inspect-brk wait (Hermes's AsyncDebuggerAPI runs them while JS runs or is paused), runIfWaitingForDebugger answered by the target then a pause (reason other), executionContextCreated sent on Runtime.enable, source map inlined, JIT off and full debug info under --inspect. The CDP objects are leaked at exit (their static destructors crashed after a client had connected). zinc dev of an engine hermes project gets it as V8's. tests/v8_inspect_check.mjs takes the engine and now also checks a breakpoint and a step (Hermes sends no hitBreakpoints; V8 steps to the return value on the same line); tests/t1/hermes_inspect.sh PASS, v8_inspect PASS.

#3 Bytecode: zinc build of a project on jsc/v8/hermes now bundles (build/<name>.js + map) instead of trying the AOT; on hermes the module's exported zn_engine_compile (patch's zn_hermes_compile, no hermesc shipped) writes build/<name>.hbc (-O). zinc run build/<name>.hbc (.hbc picks hermes) and zinc export's app (app.hbc) mmap it through hermes_run_bytecode when it is not older than the bundle and has this VM's bytecode version (else the source runs; checked with a tampered header). Frames name the bundle's file; the driver (traceName) maps them through the source map: the trace names main.js:2:24 as from source. Hero startup (ZINC_FRAMES=1 wall, 5 runs x2): bytecode 279/282 ms, source 525/443 ms; frame 30 pixel-identical. docs/reports/zinc-next-perf.md and hermes-engine.md updated.

Not proven: hero CPU with the debugger build (0.94-1.02 s/600 frames on the loaded machine vs 0.89 before); the CI job itself (runs at the next release).
