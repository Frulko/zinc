## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Part of ZN-339: one download function in src/tc tries ZINC_MIRRORS (and ZINC_TC_MIRROR) then the origin, checks each answer (pinned SHA-256, TUF target hash) and goes on to the next source when one is refused; curl honours HTTPS_PROXY / NO_PROXY. Used by the toolchains, the index and the published binaries.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->

- [x] #2 through an HTTP proxy (test proxy) every download works
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
tc::downloadTo / downloadBytes: ZINC_MIRRORS (<mirror>/<rel>) then the origin, each answer through an accept check, a refused source reported and the next tried; curl honours HTTPS_PROXY / http_proxy / NO_PROXY; ZINC_OFFLINE=1 keeps file:// only. Used by fetchTool (toolchains, rel = the archive name, checked against the pin) and by the TUF index (tuf::indexFetch, rel = index/<path>; the Fetch now carries the signed SHA-256 of a target so a modified copy is refused at the source). tests/t1/mirrors.sh: mirror 1 serves a modified archive (reported, refused), mirror 2 serves it; only a modified source = failure; an HTTP index through a counting proxy (every metadata and target request went through it) and NO_PROXY bypasses it. tuf_index now expects the source report for a tampered target. tests/run --changed 58 pass. Not done: updates (fetchManifest, downloadUpdate) and zinc add archives still call curl directly (proxies apply, mirrors not): with ZN-339.02. usage: n/a
