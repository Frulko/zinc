## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-11-09 (worktree agent). Scope: the importer part of ZN-440 (QOA); IMA ADPCM encoding, Opus, loudness and r8brain resampling are not in it (later lines below).
- Importer `audio` (src/assets/assets.cpp importAudio, version 1): options `codec` (qoa, the default; anything else is refused with what exists), `rate` (8000-192000), `channels` (1 or 2). The source is decoded by zinc:audio's own translation unit (plugins/audio/vendor/miniaudio_impl.c, included by src/assets/audio_codecs.c with MA_NO_DEVICE_IO/THREADING/ENGINE/NODE_GRAPH/RESOURCE_MANAGER/GENERATION/ENCODING), which also resamples and mixes down, then qoa_encode. That file is compiled with -fvisibility=hidden: zinc has ENABLE_EXPORTS, and the audio plugin it dlopens carries its own miniaudio and qoa built with other options (checked: `nm -gU build/zinc` shows no ma_/qoa_/stb_vorbis symbol). The entry keeps the source's name (sfx/coin.wav holds QOA bytes) and is stored as it is (zpk::readInPlace by extension), so the program's code does not change per target and loadMusic reads it in place.
- Vendored: qoa.h at phoboslab/qoa commit 93b0680030d1312e7a2829e53272353cc1de6ece (2026-11-08; last code change bc05897 of 2026-09-27), MIT, unmodified, in plugins/audio/vendor beside miniaudio (the plugin carries what it compiles), sha256 in PIN, a row in third_party/README.md. QOA_MAX_CHANNELS is 8 in this file.
- Runtime: a miniaudio decoding backend for QOA in audio.host.cpp (onInitMemory; s16 output; one decoded frame of 5120 samples a channel held, allocated through the decoder's counted allocator; seek = arithmetic frame offset, since every frame but the last is full; a damaged frame ends the stream). Every decoder config of the plugin goes through decoding(), which puts the QOA backend before miniaudio's own (load, the long-file decode thread, loadMusic). openMusic (a file on disk) does not read QOA (the backend reads memory). Console mixer: qoa_decode in load() (targets/console/qoa_console.c compiles qoa.h for the core). Web: not done (decodeAudioData does not know QOA; later line).
- report.json: each sound (the audio importer's, or a copied file with a sound extension) gets `codec`, sniffed from the artifact's first bytes (soundCodec: qoa, pcm, pcm-float, ima-adpcm, ms-adpcm, wav, flac, vorbis, opus, mp3, aac); totals get `codecs`: {codec: pack bytes}.
- Engine gap met on the way and fixed (AGENTS.md "Fill the engine's gaps"): String.fromCharCode / fromCodePoint refused more than one argument (Z0104). The checker now rewrites a call of several codes into one concatenation, () into ''; zinc.d.ts takes `...codes`. Regression lines in tests/golden/str_index (Node's output): PASS on interpreter, AOT, QuickJS.
- Proof: tests/t0/audio_import.sh (new): a 4 s stereo 44.1 kHz PCM WAV (705,644 bytes) becomes 142,528 bytes of QOA (4.95x); the same at "rate": 22050, "channels": 1 is 35,720; report codecs {"pcm": 705644, "qoa": 178248}; the pack's entry starts with "qoaf"; load() gives mono 22050 Hz 4 s at peak 0.5; loadMusic streams it, 10 s looped seamless (no step above 0.04, channels opposite within 0.02), memory 25,024 bytes, seek to 3.5 lands at 3.51 after 10 ms of mix. PASS on the interpreter, QuickJS and AOT. audio_stream_pack and audio_fade still PASS (the WAV and ADPCM paths now go through the custom-backend-first config).
- Numbers for the perf log (2026-11-09, M1 Pro, null backend, `audio_import`): `music.memory` of a 4 s stereo 44.1 kHz QOA track streamed from a pack: 25,024 bytes (one decoded frame, 20,480 bytes, plus the decoder and its conversion). QOA encode at pack time: 12.6 ms for 4 s of stereo 44.1 kHz (cold, dev profile, load ~4).
- Research (sonnet, 2026-11-09): qoa.h API and pin (https://github.com/phoboslab/qoa; frames independent, LMS state in each frame header; samples==0 rejected by this implementation; https://qoaformat.org/, https://phoboslab.org/log/2023/04/qoa-specification: decode 3.0 s vs MS ADPCM 3.7 s, Vorbis 8.7 s on 2h43m); no existing miniaudio QOA backend, written from miniaudio's custom_decoder example (https://miniaud.io/docs/examples/custom_decoder.html); adpcm-xq (BSD-3, https://github.com/dbry/adpcm-xq) for IMA ADPCM encoding if ever needed; the README warns qoa.h is not fuzzed: inputs are our own packs.
- later.md lines: ZN-440.01: IMA ADPCM encoding in the audio importer (adpcm-xq, BSD-3) for the ESP32 profile's `adpcm:16000`; ZN-440.01: QOA in the web backend (decodeAudioData does not know it: a small JS decoder or the wasm module); ZN-440.01: a codec default from the target profile's `sfx` for audio rules without `codec` (today qoa); ZN-440.01: a QOA line in tests/t0/console_audio.sh (needs a QOA file: commit one made by the importer); ZN-440.01: openMusic of a .qoa file on disk (a file read path for the backend); ZN-440.01: `zinc assets report` could print the codecs line.
- Proposed tests: `tests/run --only console_audio` with a QOA clip added (builds the console core, ~3 min, ~1 GB); the asset T0s `assets` and `project_assets` (the report gained fields; ~20 s).
