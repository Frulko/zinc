## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done (2026-10-21). Which projects: "engine": "quickjs" named in zinc.json. A .js entry with no engine keeps the typed AOT build of zinc build: it builds a native program today when the program fits Zinc, and turning it into a bundle would change what zinc build gives every such project; zinc run already picks QuickJS for it. A cross build (--target) of a quickjs project and its export to other targets than macos stay AOT as before.

Mechanism: buildEngineProgram and buildEngineApp (ZN-773.08) take quickjs too, with the existing writer (BundleOptions.bytecode, zinc bundle --bytecode): build/<name>.js + map + .qbc; the .app carries Resources/app/app.js + app.qbc, no engine pack, no allow-jit entitlement. Loading: qjs::run, given <name>.js or <name>.qbc with the .js beside it, runs <name>.qbc when it is not older than the bundle and JS_ReadObject reads it (BC_VERSION byte and checksum); otherwise the source, with a step line and no error. A .qbc alone (no .js) runs as before. Frames of bytecode name the path it was compiled under: the trace swaps it for the bundle's path here (a moved build or app), then maps through the source map.

Test: tests/t1/qjs_build_bytecode.sh PASS (build writes js/map/qbc; run from .qbc runs the bytecode, not the edited source; trace from moved bytecode names main.js:1:29; damaged .qbc and stale .qbc fall back with exit 0; macos export carries app.qbc and starts from it). qjs_bundle and jsc PASS. Hero: bytecode 360/368 ms against source 412/415 ms median (docs/reports/zinc-next-perf.md).
