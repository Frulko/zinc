## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-11-09 (worktree agent). The criteria are the parent's ("fixtures equal Node's output; a size budget recorded for each addition"), applied to these five statics.

How it works:
- The checker (src/frontend/check.cpp, objectStatic) rewrites each call.
- On typed objects it emits functions generated for the static types, as for...in already does: assign copies fields, getOwnPropertyNames lists field names (ownKeysHelper, shared with for...in now), and defineProperty sets a value.
- On any values it calls new helpers of the Dyn prelude (src/frontend/dyn.cpp).
- QuickJS runs the real JavaScript statics, so it needed no change.

What each static does:
- assign:
  - `Object.assign({}, a, b)` with typed sources becomes the spread `({ ...a, ...b })`, so a new record of the merged fields.
  - `Object.assign(target, ...)` onto a typed object copies each source field. An optional field is copied only when present. A field the target does not declare is a diagnostic ("declare it, or make a new object with { ...a, ...b }").
  - A typed object onto an any object goes through __dynSet. An any source onto a typed target copies the target's fields that the source owns.
  - An any onto an any goes through __dynAssign (own enumerable keys in JS order).
  - `null` and `undefined` sources are skipped. `({}, anyValue)` makes a new any object.
- freeze:
  - On an any object it marks every key read-only and the object not extensible (DynAttrs).
  - A write then throws TypeError, with V8's messages on the Zinc engines: "Cannot assign to read only property 'k' of object '#<Object>'", "Cannot add property z, object is not extensible".
  - On a typed value it returns the value unchanged (see the decision below).
- fromEntries:
  - Takes an array of [string, T] pairs (an array literal is checked as [string, any][]), a Map<string, T>, or an any array of pairs.
  - The result is an any object, standing in for TypeScript's { [k: string]: T }. Zinc refuses Record<string, V> for dictionaries, so an any object is the object form. Later duplicates win.
- getOwnPropertyNames:
  - A record or class lists its fields in declaration order (an optional one when present). An array lists its indices and 'length'.
  - An any value lists its keys in JS order, plus the non-enumerable ones in creation order (DynAttrs.names), plus 'length' for arrays and strings.
- defineProperty:
  - On an any object it supports data descriptors written as an object literal (value, writable, enumerable, configurable). Omitted attributes default to false for a new key and stay unchanged for an existing one.
  - A non-enumerable property lives in DynAttrs.hidden, outside the map, so JSON.stringify, console.log, Object.keys, for...in and assign skip it with no change to the runtime's walkers. Only DynGetFast (src/rt/rtcalls.cpp) now leaves a missing key to the prelude when the object has attributes.
  - On a typed object it accepts a declared field's value. writable or enumerable set to false is a diagnostic, as is an undeclared key and an accessor (get/set).
- DynObj gained a second field `attrs: DynAttrs | null`. It is null until freeze or defineProperty first touches the object, and the runtime's zero-filled DynObjs read it as null.

Research (sonnet sub-agent; web results were thin):
- AssemblyScript refuses these statics on its static classes (https://www.assemblyscript.org/status.html).
- MakeCode Static TypeScript lists the keys of object literals in static field order (https://forum.makecode.com/t/indexsignature-not-supported-error-and-object-keys-not-working/28994).
- Nothing was found for Static Hermes or Porffor.
- Pitfalls taken from the spec and checked against Node:
  - Key order is integer keys first, then insertion order.
  - assign skips null and undefined sources, runs [[Set]], and returns the target.
  - freeze is shallow and returns its argument.
  - defineProperty defaults its attributes to false, and a non-enumerable property is hidden from keys, JSON and console.log but listed by getOwnPropertyNames.
  - Error texts differ between engines (QuickJS: "'k' is read-only"), so the fixture prints err.name, as the sub-agent advised.

Proof:
- tests/golden/run/object_statics.ts, whose .out is Node 24.14.0's output (`node object_statics.ts`), prints the same 27 lines on --interp, --native and --engine quickjs.
- tests/t0/object_statics.sh (new) runs the fixture on the three engines and checks the four diagnostics: PASS.
- These existing T0 tests pass: dyn_union_view (ZN-1077's JSON views of class unions through any), dyn_string, dyn_array_methods, dyn_generic, dyn_function, dyn_number, dyn_bitwise, forof_dyn_conditional and json_typed_shape. tests/golden/run/for_in.out is unchanged on --interp and --native, since forInKeys now shares ownKeysHelper.

Size budget (M1 Pro, macOS arm64 AOT, page-rounded to 16 KB):
- zinc grows from 20,182,000 to 20,233,264 bytes (+51,264: the checker and the prelude text).
- AOT programs, each a base program (a record and a JSON.parse'd any) plus one call:
  - base: 454,936
  - plus freeze: +0
  - plus getOwnPropertyNames: +0
  - plus assign: +16,528
  - plus fromEntries: +16,528
  - plus defineProperty: +16,544
- Budget: at most one 16 KB page per static used. A Dyn program that calls none of them is unchanged (dynsmall: 487,992 before and after).

Proposed decision: Object statics on typed objects are lowered from the static types; on any values they go through the Dyn prelude.
- Object.freeze of a typed object returns it unchanged. Its type keeps saying what may change: TypeScript types the result Readonly<T> and refuses writes at compile time, and a per-object frozen bit for every typed object would change the layout of all three engines.
- Object.defineProperty on a typed object only sets a declared field's value. Hiding, read-only and accessor properties are for any values, or a readonly field or `get` accessor in the declaration.
- The result of Object.fromEntries is an any object (Zinc has no index-signature object type: Record<string, V> with open keys is refused for Map<string, V>).
- Rejected:
  - a frozen bit on every object (layout cost on every engine for a rare call);
  - a runtime-visible attribute table walked by the runtime's JSON and console.log (the hidden map keeps them unchanged);
  - fromEntries to a Map (`e.a` would not read it).

Later lines:
- ZN-161.01: Object.freeze of an any array freezes nothing: push, splice and index writes still change it. DynArr would need the same DynAttrs, checked in __dynItems.
- ZN-161.01: Object.keys, Object.entries and Object.values of a typed record are still refused (Object.keys says "fields are known from its type"). ownKeysHelper now gives the keys, so they are a few lines each.
- ZN-161.01: Partial<C> of a class is refused ("it takes an interface or a record of data properties"), so `constructor(init: Partial<Box>) { Object.assign(this, init); }` needs an init interface.
- ZN-161.01: Object.assign from a string or an array (spread into index keys) is a diagnostic; only records and any values are sources.
- ZN-161.01: Object.isFrozen, isExtensible, preventExtensions, seal and getOwnPropertyDescriptor are not there yet; DynAttrs holds what they need.

Proposed tests:
- tests/run --only object_statics: the five statics on three engines and the four diagnostics. About 5 s, 150 MB.
- A T1 run of an app that uses `Object.assign(this, options)` in a constructor, if the owner picks one. A few seconds.
