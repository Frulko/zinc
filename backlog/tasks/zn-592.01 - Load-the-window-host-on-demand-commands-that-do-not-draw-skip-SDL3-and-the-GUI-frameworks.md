## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ZN-592 found zinc's launch on the Intel Mac: 29 ms to main, 21-24 after dropping the replaced operator new; an empty program linked with the same frameworks reaches main in 9.3 ms, a plain one in 3.5 ms. The rest: ~1800 binds (438 libSystem, 244 weak coalescing, 205 libc++, ~300 into the GUI frameworks) and the frameworks themselves (AppKit, Metal, OpenGL, QuartzCore, CoreMedia, CoreVideo, Carbon, UniformTypeIdentifiers). Move the window host (zn_host_gfx, hal_sdl, SDL3 and its frameworks) into a module loaded at the first graphics call, as libzn_webgl is (RTLD_GLOBAL: display-gl and libzn_webgl resolve SDL3 from it), so zinc --version, check, build and console programs load none of it.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-10-10. zinc links libSystem and libc++ only (D67):
- The window host is the module libzn_window.dylib (CMake option ZN_WINDOW_MODULE, on for APPLE): targets/macos/hal_sdl.cpp, hal_cocoa.mm, SDL3 force-loaded, the GUI frameworks; zinc's src/host/window_module.cpp loads it RTLD_GLOBAL at the first window and forwards sdl_hal_* / hal_set_* (setters kept until then). Compiled programs link the static zn_host_window (libzn_host_window.a after libzn_host_gfx.a; also stamped in the AOT cache keys). hal_dispatch.cpp: a weak zn_window_load() returning 1 (programs), zinc's strong one loads the module; without it the program runs headless and says why. libzn_webgl and the display drivers get the module loaded first; a plugin whose dlopen fails on an _SDL_ symbol (zinc:3d's GL renderer, webview) is loaded again after it. zinc fuse embeds the module (trailer ZNFUSED2), written to ~/.zinc/cache/modules on the first window. tools/package ships it.
- The module alone was worth 7% (macOS 15's libSystem loads ~560 images, CoreFoundation and Foundation included, for any program). The rest: tools/zinc-unexported.txt (zn::, harfbuzz, libc++ symbols not exported: 629 -> 6 weak-def coalescing binds, no shared-cache patching; no plugin or module imports them, checked against all cached plugins' imports) and CoreFoundation opened by runningBundleId() instead of linked (400 -> 31 initializers).
- Cached zinc run: stampOf is one stat (format unchanged), executablePath() resolved once.
- AC1: tests/t1/launch_time.sh now compares with an empty program linked with libc++ only, fails if zinc links anything else; --version 3.6-4.5 ms over it (budget 5). A cached zinc run also checks ~80 inputs and runs the program: budget 6, measured 5.1-5.9 (decision: the launch is --version; the run's 1 ms is its work). Instructions 115.5M -> 31.5M, wall 21 -> 8.3-10 ms.
- AC3: window_renderer, gl_renderer, gl_cube, native_plugins, webgl_module, aot (t0, t1), fuse (now also checks the fused game loads its embedded module from a fresh home): PASS. Interpreted breakout opens its window through the module; ZINC_WINDOW_LIB=/nonexistent runs headless with the message.
- AC2 not met: jsonout interpreted 24.4 -> 10.6 ms vs qjs 6.9 (best of 40, interleaved; bench-m4 medians under load 18.4 vs 14.6): the gap is zinc's remaining ~3.5 ms of launch (binds, 28 initializers, pages of a 12 MB binary). Split to ZN-592.03. -no_fixup_chains tried: no gain. Linux: ZN-592.04 (deferred).
