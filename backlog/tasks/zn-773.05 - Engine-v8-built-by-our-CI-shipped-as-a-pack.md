## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-10-21. Decision: V8 comes from Homebrew's bottles, not a build of ours. Homebrew's CI builds every V8 stable for macOS arm64 (sequoia, tahoe) and Linux x86_64/arm64, signed, BSD licence, a component build against the system's libc++ with `v8_enable_sandbox=false`. That is the build an embedder needs and keeps up with V8 stable without a 2-hour CI job of ours. `tools/v8-pack` fetches the bottle from ghcr.io (anonymous token), checks its sha256 against formulae.brew.sh, renames the dylibs to @rpath, signs them ad hoc and lays out `~/.zinc/engines/v8/<version>` (`include/`, `lib/` with icudtl.dat, `current`). Our own build stays for what has no bottle: Intel macOS, Windows, armhf (backlog/later.md, Cross-platform pass). The ZN-773.04 pack format will wrap the same directory.

Done:
- `src/engine/v8.cpp` (isolate, ICU from beside libv8, explicit microtasks, the rejections told after each checkpoint) with the generic driver: `libzn_engine_v8` is built when `ZN_V8_DIR` (default `~/.zinc/engines/v8/current`) has `include/v8.h`.
- JsRuntimeHost's V8 Node-API ported to V8 15, `third_party/node-api/patches/0003-v8-15.patch`. Pitfall: its headers forced `V8_ENABLE_SANDBOX`, which moved the isolate's root offsets, so `v8::True`/`False` read the wrong slots ("Unexpected instance type" aborts). `V8::Initialize`'s config check does not catch it, because only that one file saw the define.
- `tests/t0/v8.sh` runs `jsc.sh v8` (goldens, the errors, top-level await, the rejections, a gfx project with "engine": "v8"): PASS. `zinc test --runner v8` gives quickjs's 8 known failures. On v8, webenv, webenv_canvas2d_full and webenv_audio pass; the rest of webenv_canvas2d, webenv_image and the webenv window check fail only where WebGL is needed (ZN-773.02), as on jsc. js-gsap and js-anatomy are pixel-identical to QuickJS.
- Numbers: docs/reports/zinc-next-perf.md, "V8 beside QuickJS-ng and JavaScriptCore". Host call 50 ns (QuickJS 70, JSC 131), fib(30) 8 ms against 76.

AC #2 (2026-10-21): V8's own inspector (`v8_inspector::V8Inspector`, in libv8) in src/engine/v8.cpp, served by `src/dbg/ws.cpp`. That is the discovery and WebSocket transport of `zinc debug --cdp`, taken out of cdp.cpp so both use it; the module calls zinc's exported mbedTLS for the handshake.
- `zinc run --engine v8 --inspect[=port]` / `--inspect-brk[=port]` (ZINC_INSPECT=port[,brk]).
- `zinc dev` on a project with "engine": "v8" sets it on the devtools port (9229, plugins.devtools.port, ZINC_DEVTOOLS_PORT). It also passes `--engine jsc|v8` to the child, which runs a file and so never read zinc.json's engine.
- The client's messages run on the main thread: at each drain of the driver, through `RequestInterrupt` while JavaScript runs, and in a loop while paused.
- console.* goes to V8's console too, so DevTools' Console shows it.
- The source map is inlined as a data: URL, since DevTools fetches no file:// map for a node target.
- `tests/t1/v8_inspect.sh`: discovery, the map inline, the pause at start, a `debugger` statement in `twice`, evaluateOnCallFrame, console.log, the exit. PASS.
- zinc dev checked by hand on a gfx project in a background window: Runtime.evaluate gives "v8" from the running frame loop.
- Not done: JavaScriptCore has no inspector (Safari's Web Inspector needs the private remote-inspection API).
