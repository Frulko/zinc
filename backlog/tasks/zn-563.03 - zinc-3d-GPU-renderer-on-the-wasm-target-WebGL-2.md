## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-10-30: the site gallery (ZN-774.36) runs 34 of 35 catalogue examples as web exports; '3d' says 'runs at home only' because zinc:3d has no browser backend.

2026-10-30, choice (cheapest correct path): Render3D's surface in JavaScript over the page's WebGL 2 (plugins/3d/web/render3d.js, plugin.json web.native + impl, as lottie), a port of render3d.gl.cpp: the same GLSL (ES 3.00, the same programs per kind of material), 4x MSAA framebuffer per target, blitted into the backend's canvas at end() and copied into the target's own 2D canvas, which present() paints in the box (Z.paint.element: canvas and DOM render). Rejected: render3d.host.cpp to wasm (the software rasterizer, not the GPU, and it needs zrt's images and gfx command list in the page); routing through three.js (zinc:3d is not the three subset; three.js's own lighting would not be render3d's). The runtime gained Z.images.rev(id) so textures re-upload when a gfx image changes. Not in the browser yet: worlds (worldOpen answers -1), assetOpen (-1: loadModel reads the .zmesh through zinc:assets and meshLoad), the plugin options msaa/filter (no options reach the page; defaults 4 and mipmap). Pixels: drawn at devicePixelRatio (max 2); y is not flipped, so the flat-shading normal loses render3d.gl.cpp's minus.
Proof: tests/t1/web_3d.sh (new): 'web_3d: three/cubes in Chrome: ssim 0.9867 (minimum 0.95) against the software frame' (criterion #1: examples/three/cubes in the browser goes through plugins/three/web, three.js on WebGL 2) and 'web_3d: 3d/cubes in Chrome: ssim 0.9450 (minimum 0.93) against the software frame' (zinc:3d on WebGL 2; the native GPU renderer scores 0.9453 against the same golden, mipmaps and MSAA against nearest texels; the browser frame against the native GPU frame: 0.9985). tests/t1/site_examples.sh: 'site_examples: 3d in its page: 170 frames, 0.110 drawn'; tools/site-examples: 35 examples, none at home only. web_export, web_plugins pass.
