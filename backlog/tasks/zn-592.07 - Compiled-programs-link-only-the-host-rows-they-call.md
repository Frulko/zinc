## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
After ZN-592.06 a compiled console program with a timer links libSystem and libc++ only and starts in 7.0 ms against 4.9 for an empty program (Intel Mac): the rest is mostly dyld resolving ~240 libSystem imports (~1.2 ms) that the host's row dispatch (src/host/gfx_host.cpp and sys_host.cpp: one switch over every row: sockets, HTTP, TLS, MQTT, processes, files...) keeps alive through -dead_strip. Let the AOT emitter call the rows a program uses directly (as it already does for the hot gfx rows, ZN-397) or split the dispatch per family so that the linker drops the families a program never calls; measure the imports and the launch.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Closed 2026-10-10 without the change: measured first, not worth it. Of the ~215 distinct libSystem symbols a compiled console program with a timer imports (after ZN-592.06's -dead_strip), only 18 are needed by the network and TLS code alone (http, sock, tls, mqtt, osc, crypto, netlog, mbedtls, llhttp: atexit, fread/fseek/ftell, gmtime_r, inet_pton, printf, strftime, strstr...); the rest is imported by libuv (162 of them across the archive: the event loop that runs the timers), the runtime, loop.cpp and sys_host.cpp, which any program calling the host keeps. A dispatch split per family would save ~18 x 5 us = 0.1 ms of the 2.0-2.2 ms over an empty program; the 1 ms target would need a host without libuv. No follow-up: the floor is the event loop.
