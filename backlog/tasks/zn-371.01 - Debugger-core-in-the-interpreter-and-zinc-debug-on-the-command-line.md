## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
First part of ZN-371 (D84). Debug builds (zinc debug): the lowering emits DbgLine at each statement and DbgVar after each write of a local; no inlining; ZBC gets a Line opcode (index into a line table of file, line, column), per-function variable homes (a register per local, written by DbgVar, references retained there and released at return) and field names; the interpreter's Line handler tests one byte per statement (breakpoints, stepping and pause requests set it) and calls the debugger hook. src/dbg holds breakpoints (file:line), step over/into/out, the call stack with lines, locals formatted by type (numbers, booleans, strings, arrays, objects one level). zinc debug <file> runs the program interpreted and takes commands on stdin when paused (b file:line, c, n, s, o, bt, locals, p name, q). Release builds are unchanged.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done (2026-10-11), D84. IR: DbgLine (file << 32 | offset) at each statement and DbgVar after each write of a named local (this included) in the program's own code (not the prelude, zinc:*, lib/std, lib/compat, plugins: they run without stops); Module::debug skips inlining and recursion unrolling. ZBC: Line opcode (new format LX, 24-bit index into Module::lines), Function::vars (a home register per local after the parameters, below every call window; references retained there, the previous released, all released at return), ClassInfo::fieldNames; debug modules are never encoded, the verifier refuses a Line index past the table; AOT treats Line as nothing. Interpreter: Machine::lineHot (a byte per line), debugHook; the debugger runs in its own copy of the loop (execT<false, true>): one loop with the call (never taken) cost every program 6-7% (fib, nbody), with a cold label or a noinline cold function too; the copy costs 73 KB. src/dbg: breakpoints by file:line (first line with code at or after; trailing path match), step over/into/out by frame depth, the stack (frames of the program's code only, <top level>), locals formatted from the IR type (numbers, booleans, strings, arrays, objects with field names one level, cells unwrapped, lambdas show their captures); command-line front end (b, d, c, n, s, o, bt, locals, p, q, help; echoed without a terminal; end of input runs to the end; q exits 0). zinc debug <entry> in main.cpp (interpreted, no ZBC cache), in the command table and docs/dev-mode.md. AC1: tests/t1/debug_cli.sh (two transcripts: first stop, step into a call and a constructor, step over, step out, breakpoints set/missing/hit in a loop/deleted, stack, locals of numbers, string, array, object, this, print, help, quit). AC2: zinc --emit=zbc-bin of 59 programs (tests/conformance, examples, bench kernels, a ui scene) byte-identical to the binary before the task. AC3: debug build idle vs armed on a line reached at the end: fib 1006-1007 M vs 1006 M, nbody 10.47-10.50 G vs 10.47-10.49 G instructions (= ); normal runs 473-485 M (fib) and 7.41-7.43 G (nbody) vs 479-484 M and 7.43 G before (=); a debug build costs 2.1x (fib) and 1.41x (nbody) a normal one (perf log). T0: all pass but tls (known) and build_inputs_tracked (src/dbg not committed yet at the time). Also checked by hand: generics, a closure, exceptions caught in a loop with a breakpoint in the throwing function, a zinc:ui program headless (its .tsx lines are ZN-371.03). usage: n/a
