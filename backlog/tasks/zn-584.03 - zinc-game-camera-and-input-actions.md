## Implementation Notes

- 2026-11-12: AC1 implemented in caller-owned `zinc:game` Camera/InputActions/InputAction. Camera uses top-left world coordinates for Level.draw, positive viewport, origin-based bounds (undersized axes center), snap follow and separate timed shake offsets with Idle/Shaking transitions; restart/expiry clears shake. Finite/nonnegative validation covers coordinates, size/time/amplitude. No scene globals, listeners, transforms, dependencies, smoothing/zoom stack or engine edits.
- Actions combine key, zero-based pointer button, analog gamepad button and directional axis bindings by maximum strength before edges. Key Down/Up transitions preserve same-frame taps, duplicate Down/Repeat/Text create no new edge, reset clears retained keys/state, disconnected pad releases. Host focus is a shared signal (`targets/macos/hal_sdl.cpp`); deliberately leave consuming that queue to the application and document reset on focus loss. The existing platformer uses Camera (retaining its own smoothing) and actions, with Btn retained for console HAL input. No new demo or service.
- Scope/callers checked: game exports, existing game regression fixture/runner/affected mapping, platformer input/render, game reference and changelog. No data storage or destructive change. The layer is opt-in and keeps existing public scene/sprite/tilemap behavior.
- Delegated research supplied by coordinator: Phaser Camera https://docs.phaser.io/api-documentation/class/cameras-scene2d-camera and Godot Camera2D https://docs.godotengine.org/en/4.5/classes/class_camera2d.html support viewport-centered follow, bounds and transient shake; Godot input https://docs.godotengine.org/en/latest/classes/class_input.html and Bevy ButtonInput https://docs.rs/bevy/latest/bevy/input/struct.ButtonInput.html support aggregate action strength and nonconsuming frame edges. ### Review correction: focus loss

- Platformer is the sole owner of its gfx signal queue (all source callers inspected). Its `readControls` now drains signals after action sampling and resets actions on `focus 0`, so a missing key-up across alt-tab cannot retain movement. Generic InputActions still never drains the shared queue. Camera view getters also reject finite base+shake sums that overflow, rather than exposing infinity.
- Added exact small regression importing the real platformer Controls/readControls module, not a duplicate: held d, focus loss without key-up, focus regain, new d press, release.
