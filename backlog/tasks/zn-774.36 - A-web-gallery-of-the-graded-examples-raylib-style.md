## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Decision (cheapest correct way to run an example in the page): zinc export --target web per example, run by tools/site-examples and committed under site/public/play/<name>/ (the site's CI has no zinc), shown in a scaled iframe beside the source on site/src/pages/examples/[name].astro. Measured on the 35 catalogue entries in headless Chrome: the web export runs 34 (only 3d fails: zinc:3d has no browser backend, docs/targets/web.md 'not yet'); the wasm VM of site/public/play ran 27 (no Canvas2D: the six canvas examples; no Audio: both sound examples; no Render3D). The web export is also 50 to 250 KB of JavaScript per example (3.8 MB in all) against a 6 MB vm.wasm that must be rebuilt with every ZBC change, and needs no COOP/COEP service worker and its reload. So vm.wasm and coi-sw.js left the site; /play/breakout/ and /play/bouncing-ball/ are now web exports at the same addresses. The criterion's '(wasm)' is read as 'in the browser'.
Engine gap fixed on the way (own commit): tools/build-wasm no longer built since zinc:worker (std::mutex and __cxa_thread_atexit in wasm32-wasi): targets/wasm/worker_none.cpp replaces src/rt/worker.cpp there (a worker start errors), stubs.cpp answers __cxa_thread_atexit. tests/t1/export_wasm.sh passes again (hello printed 479 bytes, forms drew 960x600).
Pages: /examples/ (the catalogue as cards, filters by module and grade, no JS framework), /examples/<name>/ (the program in a frame at its zinc.json window size, scaled to the column; each source file with a copy button; zinc run example:<name> and zinc new --from example:<name> with copy buttons; the lesson link). site/public/play/examples.txt keeps a hash of each example's files: tools/site-examples --check (in the test) names the examples changed since the last export. Navigation untouched (the demos page links the gallery).
Criterion #2 open: 34 of 35 run in the page; 3d says 'runs at home only: its Render3D side has no browser version yet' until zinc:3d gets a browser backend (render3d.host.cpp to WebAssembly with a JS impl, as physics2d does): a task of its own (New-task: blocks site gallery 3d), then rerun tools/site-examples and the test.
