## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A JS module evaluated only in QuickJS contexts that ask for it, plus a few host rows: window/self/navigator/location/screen/devicePixelRatio (from pixelScale), a minimal element tree with getElementsByTagName/getElementById/querySelector, EventTarget everywhere, Zinc input translated to PointerEvent/MouseEvent/TouchEvent/WheelEvent/KeyboardEvent with the targets libraries expect (PixiJS: pointermove on document, pointerup on window; Phaser: keys on window, mouse on canvas + window; p5: window), focus/blur/visibilitychange/resize, requestAnimationFrame driven by the frame loop with real performance.now timestamps, fetch/Request/Response and XMLHttpRequest over project files, data: and blob: URLs and zinc:net, Blob and URL.createObjectURL, localStorage/sessionStorage over zinc:storage, structuredClone, MessageChannel/postMessage, PromiseRejectionEvent (without it core-js in p5 1.x replaces the native Promise), ResizeObserver, matchMedia, getComputedStyle, DOMParser; zinc.json keys 'web' (generalising 'webgl': true) and 'engine': 'quickjs'; new Script({web: true}) for zinc:script. Seeds: the traced environment used for the report (~400 lines, games-libs/probe/env.mjs) and tests/webgl-conformance/dom-shim.js. (From docs/reports/games/js-game-libraries.md.)

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-10-10, parallel agent (worktree), Intel Mac. Decision recorded before the code (RULES 4); the coordinator files it with a number.

DECISION: where the browser around WebGL comes from. Scores 1-5: fit x3, performance x3, size x2, maintainability x2, licence and supply x2, portability x1, effort x1.
(A) A mature DOM implementation in JavaScript inside QuickJS: 43. jsdom 30.1.2 (MIT, 5.5 MB unpacked, 20 dependencies) and happy-dom 20.14.6 (MIT, 9.2 MB, 3,058 files) need Node built-ins (vm, http, undici, ws): they do not run on QuickJS. linkedom 0.18.13 (ISC) does, as one file of 411 KB: measured here import 19-21 ms and +5.2 MB RSS per context (load average 4.8). It gives the node tree, CSS selectors, HTML and XML parsing, bubbling events and MutationObserver; its window lacks, measured: requestAnimationFrame, location, innerWidth, devicePixelRatio, fetch, XMLHttpRequest, localStorage, matchMedia, getComputedStyle, Pointer/Keyboard/Mouse/Wheel/Touch events, ResizeObserver, URL, Blob, MessageChannel, PromiseRejectionEvent, structuredClone; canvas.getContext returns null and getBoundingClientRect is all zeros (no layout). What a game library reads is therefore still ours to write, and the tree it replaces is the smallest part. Scores 2,3,2,3,5,5,3.
(B) A thin environment of our own, written against what the libraries call (the traces of docs/reports/games/js-game-libraries.md 3.1) and checked by their boot paths: 67. Scores 5,5,5,4,5,5,4. The risk is a gap found by the next library: an opt-in trace of unknown window members (ZINC_WEB=trace) names them.
(C) B, plus a proven library where the specification is a parser (RULES 3): 64 as a whole (5,5,4,4,5,5,3), and the rule decides the parts: URL and URLSearchParams come from the WHATWG parser the repository already has (lib/std/web.ts, the typed engine's, loaded on first use); DOMParser (XML bitmap fonts, none of the four boot paths calls it) is a later slice on a vendored parser (@xmldom/xmldom 0.9.12, MIT, no dependency, or linkedom's) loaded on first use; structuredClone is QuickJS's own serializer.
CHOICE: B for the window, the document, events, the frame loop, storage and the network glue (bindings to Zinc's host: no library provides them), with C's rule for parsers. Revisit if a library needs real CSS selectors or layout (then linkedom under the same window, on demand).

Shape: src/qjs/webenv.cpp holds the JavaScript (a raw string, as prelude.cpp) and a few native helpers over existing host rows (no new row); evaluated before the entry module only when ZINC_WEB is set or zinc.json has "web"; off by default.

SLICE 1, the globals and events (2026-10-11): lib/std/webenv.js (read at run time from lib/std, like the other standard modules: packaged with it, no byte in zinc), started by src/qjs/webenv.cpp when ZINC_WEB is set or zinc.json has "web" (true or an object; ZINC_WEB=0 wins; ZINC_WEB=trace prints each window, document or navigator member a library reads and does not find). The window is the global object (its prototype chain holds EventTarget, so a bare addEventListener works); navigator is a desktop Chrome by name with the host's platform, locale and core count; location is file://<project directory>/index.html (the directory of zinc.json, else the entry's), what relative URLs will resolve against; innerWidth, innerHeight and devicePixelRatio read the host at each access. The document has html, head and body, createElement (canvas, img, audio, video have their classes; media elements play nothing until ZN-573), text nodes and fragments, attributes, classList, a style object, the simple selectors (tag, #id, .class, [attr], [attr=v], descendant and child, comma lists; anything else is a SyntaxError naming it). Events: capture, target and bubble phases along the parents, then the document, then the window; once, passive, signal, listener objects, on<type> handlers, stopPropagation, preventDefault; a listener that throws is the window's error event and the others still run. Mouse, Pointer, Wheel, Keyboard, Touch, Focus, Error, Message, PromiseRejection, Progress and Custom events exist as classes. Also: structuredClone (QuickJS's serializer: cycles, Map, Set, Date, typed arrays), MessageChannel, postMessage, ResizeObserver (told after observe and at each resize), MutationObserver (inert), matchMedia (nothing matches), getComputedStyle, DOMContentLoaded and load after the module. No layout: a box is what the style says (px, %, vw, vh), else the window for html and body, the bitmap for a canvas, the parent's width and no height for the rest, all at the origin. innerHTML with markup is kept as text (no HTML parser).
Test: tests/t0/webenv.sh with tests/golden/webenv/dom.js (off by default, zinc.json, ZINC_WEB=0, the surface's size and scale: ZINC_SIZE=800x600 ZINC_SCALE=2 gives 800 600 2, trace).

SLICE 2, frames, timers and input (2026-10-11): requestAnimationFrame and cancelAnimationFrame run on the engine's frame loop: the first call, or the first canvas put in the document, sets globalThis.__zincFrameCb (the loop of ZN-566 then starts, also after an await) and asks the host for a surface that follows the window; zinc:gfx's onFrame step, if the program has one, runs after the callbacks. Each frame: the host's input as DOM events, a resize event and the ResizeObservers when the size changed, then the callbacks with performance.now(). A deterministic run (ZINC_DETERMINISTIC) reads the virtual clock through performance.now too (QuickJS's own now is neither writable nor configurable: the global is an object over it), so tests see steps of 16.67 ms; a real run keeps the real clock. Timers stay the prelude's (virtual clock, advanced by the frame time). Input, from the rows zinc:gfx already has (no new row): pointerover/enter once, pointermove + mousemove, pointerdown/up + mousedown/up with DOM button numbers and the buttons mask, click, dblclick within 500 ms, contextmenu on the right button, wheel (a notch is 100 px downwards-positive, plus a trackpad's pixels), keydown / keyup with key, code, the legacy keyCode and repeat, keypress per typed character, touchstart / touchmove / touchend with their lists. One dispatch at the target (the canvas under the pointer, the capturing element, or the focused element for keys), then the event bubbles to the document and the window: PixiJS's and Phaser's listeners are reached without a table per library.
Not done in this slice: focus, blur and visibilitychange of the window (no host row says it); a finger is the pointer only as moves (the host sends no button event for it); modifier keys alone send no event (the host reports them only as flags); the resize event is not proven (a headless run cannot be resized).
Test: tests/t0/webenv.sh with tests/golden/webenv/frames.js and frames.input (9 callbacks 16.67 ms apart, a 40 ms timer in frame 3, a scripted drag reaching the document's pointermove and the window's pointerup, wheel, keys on the window, a touch).

SLICE 3, network and storage (2026-10-11): URL and URLSearchParams are the typed engine's WHATWG parser (lib/std/web.ts), loaded at the first URL made (12.8 ms once; the two globals are shells until then, with createObjectURL, revokeObjectURL and canParse of their own). For that, zinc:web had to load on QuickJS at all: the type stripper (src/qjs/strip.cpp) now blanks the modifiers after 'static' ('static readonly X') and Zinc's decorators ('@weak', '@pooled(n)'), two cases added to tests/golden/qjs/strip.ts. Blob and File hold bytes. fetch, Request, Response and Headers (no streams: body is undefined, libraries then read it whole; an AbortSignal rejects with AbortError) and XMLHttpRequest (text, json, arraybuffer, blob; readystatechange, loadstart, progress, load, error, abort, loadend; synchronous for what answers at once) read: file: URLs through the host's fs row (so permissions hold), relative ones resolved against the page (the project's directory); a path that is not on disk is looked for under the project ("/assets/a.png" written for a server's root); a missing file is a 404, as a server says; data: and blob: URLs; http and https through zinc:net's rows, called from webenv.cpp so that a body arrives as its bytes (the row's string result would be re-read as UTF-8), the host's loop being given a turn at each of ours while requests are out. localStorage is zinc:storage's (kept between runs, read at the first use), sessionStorage lives as long as the program; both by their methods only (no localStorage.key as a property). A script element put in the document runs: a classic script as global code under its file's name (its functions and vars are the window's: how a UMD library or a p5 sketch is written), type=module through import(), an inline one from its text; then load or error.
No new host row: src/qjs/webenv.cpp calls HostFsReadText, HostHttpFetch, HostLoopWait, HostEvReady, HostEvNext, HostHttpStatus/Head/Url/Body/Free.
Not done: a request body over http is text only; FormData; ReadableStream; DOMParser and responseType 'document' (the vendored XML parser of the decision); cookies; the localStorage property form.
Tests: tests/t0/webenv.sh with net.js (files, data:, blob:, 404, abort, XHR events in order, storage, scripts), a second run reading what the first stored, and http.js against a Python server on a loopback port the system picks (a 256-byte binary intact, a 404, two requests at once, a refused connection rejects); qjs (the stripper cases), quickjs, layout_bridge, three pass.

DECISIONS taken in this task, for the coordinator to file: (1) the environment is a thin one of our own (scores above); (2) its JavaScript is one file in lib/std read at run time, as the other standard modules, not a string in the binary: hackable, packaged with lib/std, no byte in zinc; a built app that wants it in a zinc:script context would embed it then; (3) the frame loop starts at the first requestAnimationFrame or the first canvas put in the document, so a program that only computes still ends; (4) a deterministic run reads the virtual clock through performance.now; (5) an error in a listener or a frame callback is the window's error event and the program goes on, as in a browser; (6) until ZN-570 and ZN-569 a 2D context draws nothing and an image gets its error event, each with one notice on stderr, rather than an exception or a wait for ever; (7) the MIT libraries of the tests (PixiJS, three.js) are vendored as test data in third_party; p5.js, LGPL-2.1, is not in the repository: a pinned download into a cache (tools/test-lib), the test skipped when it is not to be had; (8) the root-relative file URL that does not exist is looked for under the project ("/assets/a.png").
