## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Owner 2026-10-30: the hero demo must play its video in the browser, the file served as an asset by the server zinc starts. Today zinc:video's web entry resolves only assets/ (Z.assetUrl), and hero reads media/bbb.mp4 next to the program (not in git, examples/hero/README.md fetches it), so the page says 'not found'.

2026-11-07 (worktree agent): done.
- Page fs (targets/web/runtime.js): files and folders in memory (zinc:fs stays synchronous), written through to IndexedDB per app id (db zinc-fs:<id>) 100 ms after a change and on pagehide/visibilitychange, read back in preload before the program starts; tmp/ not kept. Real directories (mkdir, list kinds, stat isDirectory, remove recursive), rename, copyFile, realpath, mkdtemp, chmod (ignored), paths normalised (. and ..). Assets and project files read only. Under zinc dev the machine's fs stays (bridge), the IndexedDB store is not loaded.
- zinc.json targets.web.files: project files/folders shipped next to the page under their project path; media streamed (not preloaded, not in the sw precache, not in the 40 MB budget). hero: files [media] (plays media/bbb.mp4, checked in headless Chrome: readyState 4, 640 px, currentTime 5.7 s); carnet: files [welcome].
- capabilities.json web fs: true; docs/targets/web.md 'Files: zinc:fs in the page'; web-demos.md rows for carnet, kanban.
- Found and fixed on the way: every web export reading bytes (readBytes of zinc:fs/zinc:assets) died with '__qjs_bytes is not defined' (the bundle goes through the QuickJS loader's rewrite, src/qjs/qjs.cpp:316): the page defines __qjs_bytes. gfxImageAlpha (2026-11-02) missing from the web runtime made every zinc:ui export warn W0603 and failed web_caps: a no-op row (page images are canvases).
Decisions (for the coordinator to record): IndexedDB write-through, not OPFS (sync access handles are worker-only; main-thread createWritable missing from older Safari; same pattern as Emscripten IDBFS and Pyodide). No navigator.storage.persist() (Firefox prompts). The web settings live under targets.web (the top-level 'web' key turns on the QuickJS web environment), so the task's 'web.demo'/'web.proxy' become targets.web.demo/proxy.
Research: MDN OPFS https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system ; Pyodide fs https://pyodide.readthedocs.io/en/latest/usage/file-system.html ; Emscripten OPFS PR https://github.com/emscripten-core/emscripten/pull/26495 ; zen-fs Safari notes https://github.com/orgs/zen-fs/discussions/259 ; WebKit OPFS bug https://bugs.webkit.org/show_bug.cgi?id=283959
Proof: tests/t1/web_fs.sh (fixture tests/fixtures/web-fs, export + reload in headless Chrome) PASS; web_caps PASS; qjs_platform PASS; carnet and kanban exported without --force and ran in headless Chrome with no console error (carnet shows its welcome pages, kanban says it finds no project).
