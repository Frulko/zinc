## Description

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Worked by a parallel agent (worktree), 2026-10-11, one commit.

What was made
- `src/chooser.ts` (new). The list: the tables of the game's assets (a folder `tables/<name>/` with its table.json, or a package `tables/<name>.zpinball`), then the one `--table` names, which takes the place of the table of the same name when the list has one and is the one that is on. An entry is read without the full check (its name; its picture: the backglass of the landscape layout, else of the portrait one, else the painting of the playfield): a table with a fault is in the list and the fault is told when it is chosen, the table that was on stays.
- While the game waits for a player (its attract phase) a card per table is drawn over the table's view, under its middle: the picture cut to its place, the name, the chosen one bright with a border, "TAB: NEXT TABLE" under them; in the pixels of the layout, so it scales with the window, in both layouts. With one table there is no list.
- Tab or T (pad: Select) goes to the next table; a press on a card takes that one. The table chosen is put on at once (main.ts show: its game, scene, sounds, view and its own high scores), so its lights and its panel are behind the list; Start plays it as before. With --log, a line `table <name>` says a table came on; nothing else is printed that was not, so play.log and sounds.log are unchanged.

Tests
- pinball3d_chooser (new, 6 s): Tab then Start prints `table Twilight Fair`, `game start`, `game ballStart`, `ball 1`; frame 14 (the two cards, the second chosen, Twilight Fair behind and on the panel) equals tests/golden/pinball3d/chooser-14.png; the interpreter draws that frame byte for byte as the compiled game does; a press on the second card takes it; on a copy of the game with a table folder and a package put in assets/tables and another package named with --table, Tab goes through `Low Tide`, `Packed Tide`, `Tidal Lock`, `Twilight Fair` and back to `Named Tide` (the one that was on).
- pinball3d: its frame 12 of each layout now has the list on it (the first table chosen): landscape-12.png and portrait-12.png were made again; they are the golden of the list in both layouts. The four other frames and the log did not change.
- Looked at: the list in landscape (640 x 400) with each table chosen, and in portrait (400 x 640).

Decisions
- A key of its own (Tab, T, Select), not the flippers: the scripted games go on pressing the flippers after their game is over, and would change table; a player who waits flips for fun too.
- The chosen table comes on at once instead of being shown by its picture alone: the table itself, with its lights and its music, is the best picture of it; the card's picture tells the others apart.
- "The folder" of criterion 2 is the game's own `assets/tables/` (a compiled game reads its assets from the folder it runs in, tests/t1/pinball3d_aot.sh): no second folder and no option.

Not proven, limits
- `--engine quickjs` does not start the game at all, before this task too ("Could not find export 'TableDef'": an interface imported by name): the chooser ran compiled and interpreted only.
- The list is read when the game starts. A file dropped on the window is not opened (the game does not use zinc:system). The scene and the sounds of the table that leaves are not freed (said in the code).

For next/backlog/later.md (the coordinator adds them)
- ZN-649.17: the game does not start on the QuickJS engine ("Could not find export 'TableDef'" for an interface imported by name): the engine should drop such imports, or the game import its types as types.
- ZN-649.17: a table or a package dropped on the game's window could join the list and come on (zinc:system `drop`), and the list could be read again while the game waits.
- ZN-649.17: free the scene and the sounds of the table that leaves when another is chosen.
