## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-10-10. tools/gen-zinc-gl holds one table of the zinc:gl methods and generates their host rows (include/zn/runtime.h, 245 with glCreate), their C++ (src/gl/webgl_host_rows.inc, included by webgl_host.cpp's dispatch) and their TypeScript (lib/std/gl.ts); --check says when the generated text is stale. lib/std/gl.ts: GLArray and the typed array classes (number[] plus an element kind, converted in the host, written back for readPixels/getBufferSubData), typed handles for every WebGL object, GLParam for the any-returning queries (rows ParamKind/Count/Number/Text/Object), WebGLActiveInfo, WebGLShaderPrecisionFormat, WebGLContextAttributes (createContext's 4th argument), every WebGL 1 and 2 constant as a getter, the extensions' methods on the context, a simplified lost context.
AC1: tests/t0/zinc_gl_api.sh: all 243 methods of src/gl/webgl_js.cpp have a zinc:gl counterpart (zincPresent = present), and the generated files are up to date.
AC2 (rewritten, D57): moving the QuickJS binding onto the rows would cost every JS call the HostCall decoding and change no validation (both call WebGL1); instead tests/t1/zinc_gl_api_tour.sh runs tests/golden/webgl/api_tour.js on QuickJS and api_tour.ts through zinc:gl interpreted and built: the same 27 lines (shaders, active info, parameters, VAO, getBufferSubData, uniforms, readPixels, texStorage, framebuffers, clearBufferfv, queries, syncs, extensions, errors, uniform blocks). The QuickJS binding is unchanged, so its conformance is too.
Also: gl-cube follows the API (GLParam, Uint8Array of number[]); bench/gl_calls unchanged.
Tests: zinc_gl_api, zinc_gl_api_tour, gl_cube, webgl_js, webgl_present, webgl1_core, webgl2_js, aot, quickjs, zbc, host_direct, native_abi_freeze. usage: n/a
