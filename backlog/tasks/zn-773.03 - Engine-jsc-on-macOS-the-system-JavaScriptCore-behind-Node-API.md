## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-10-21: done on macOS. Design as built (replaces the trampoline of the description): each engine is a module beside zinc (libzn_engine_jsc.dylib) with its engine's Node-API, its own compiled copy of the bindings (native_js, canvas2d, webenv, segmenter) and the driver src/engine/driver.cpp; napi_* are hidden in it, so they never meet QuickJS's in zinc and QuickJS keeps its inlined fast path. zinc exports no C++ (ZN-592.01), so zinc_engine_args carries zinc's live state (host tables, redraw, native provider, decoders, mapStack) and the module links the stateless code (zn_codec, zn_text). The program is bundled to one script: zinc bundle --engine jsc (zinc:native linked in, zinc:web and zinc:audio in a registry for webenv's module(), the whole in an async function for top-level await). JSC needs com.apple.security.cs.allow-jit, now in targets/macos/zinc.entitlements. Proof: tests/t0/jsc.sh; zinc test --runner jsc = quickjs's 8 known failures; webenv, webenv_canvas2d(_full), webenv_image pass; examples/js-gsap and js-anatomy frame 30 identical to QuickJS. Left: AC #3 needs WebGL on Node-API (ZN-773.02), then tools/zbench three on both engines.
