## Implementation and reuse

Built `examples/ui/tracker`, a fictional Fieldwork survey workspace with twelve local issues. One per-document model owns filtering, grouping, sorting, selection, edits, comments and monotonic issue IDs. The app owns one enum/transition function for its closed/sidebar/detail/create overlay lifecycle and cleans up its viewport watcher. No file, account, repository backlog or network service is accessed; changes reset when the window closes.

Need → provider → gap: workspace navigation → kit Sidebar; grouped keyboard rows → Accordion + List/ListItem; editing/filtering → Input/Textarea/SearchField/Select/Tabs; status/summary → Badge/Progress; floating forms/narrow navigation → Dialog/Sheet; empty search → EmptyState. Read the canonical implementations plus kit-gallery and kanban consumers before reuse. All current requirements are covered without a private control layer, backend or dependency. Quiet theme, existing focus/motion paths and named icon subset are reused. Each named component has its own source file.

## Research and choice

Primary reference inspected at the pinned CUI commit: https://github.com/yappologistic/CUI/blob/f70a1d3d095cafd67814b23bdd82c2dfba28efe0/examples/tracker.c and https://github.com/yappologistic/CUI/blob/f70a1d3d095cafd67814b23bdd82c2dfba28efe0/docs/design.md . Borrowed only its three-pane organization, grouped issue list and responsive thresholds (sidebar drawer below760, detail sheet below1200); code, data and copy are our own. Kept only working destinations/actions. In-memory data is the smallest complete local demonstration; no persistence was requested.

Explicit viewport-dependent Sheet/Dialog sizes follow the reference and the portable ZN-382 contract. Classic ignores percentage min/max constraints documented as rn-only, so a size420 Sheet is not clamped by max-w-full at360. Final size=min(420,viewport) and dialog width=min(500,viewport−32) stay within360; no provider/engine code was changed.
