## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Owner request (2026-10-21): txiki.js's features such as WebAssembly, as an automatic download, not in zinc by default. txiki.js is not an engine (QuickJS-ng plus its own libuv loop, fetch, timers; no stable ABI), so its useful part is taken instead: the WebAssembly global over WAMR (Bytecode Alliance, Apache-2.0 with LLVM exception, fast interpreter; txiki's wasm.c + wasm.js, MIT), written against Node-API and installed only on an engine that lacks WebAssembly (QuickJS; V8 and JSC have it), shipped as an engine pack (ZN-773.04). WASI second.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-10-21 (worktree agent).

What there is:
- libzn_wasm (CMake MODULE `zn_wasm`, `src/wasm`): WAMR 2.4.5's fast interpreter (`third_party/wamr`; no AOT, JIT, WASI, SIMD or threads) under the WebAssembly JS API, ported from txiki.js 26.6.0 (wasm.c + wasm.js, MIT) to Node-API. It reaches the engine only through the Node-API table (`include/zn/napi_table.h`) plus a second table, `zn_napi_table_ext` (external and detached ArrayBuffers, BigInt int64, handle scopes), which JSC's Node-API lacks. `nm -u` finds no JS_ or napi_ symbol.
- zinc (`src/main.cpp`, context hook), QuickJS only: `globalThis.WebAssembly` is a lazy getter. The first read dlopens `$ZINC_WASM_LIB`, or libzn_wasm beside zinc, then calls `zn_wasm_install`. Without the module every read throws: WebAssembly needs the wasm pack, which is not installed: run `zinc engine install wasm` (<path>: not found). A program that never reads WebAssembly loads nothing. V8 and JSC keep their own WebAssembly.
- WAMR patches (`ZN_WAMR_JS_API`, `third_party/wamr/patches/0001-js-api.patch`):
  - instantiation runs the start section only (no `__post_instantiate` or `__wasm_call_ctors`);
  - an imported memory or table is made by the instance;
  - a memory keeps its declared pages and maximum when the module has no `memory.grow`.

- Perf: arm64, with a load average of about 30 from other sessions, on QuickJS.
  - A 20,000,000-iteration i32 sum loop takes 135–137 ms in wasm, against 650–680 ms in plain JS (x4.8–5.0).
  - One call from JS to an exported `add` costs about 104–115 ns.

Ceilings (upgrade when a program needs it):
- An imported Memory, Table or mutable Global is copied into the instance, not shared. WAMR's embedding API cannot link a host memory without multi-module. An imported Table is checked but not filled.
- funcref and externref parameters of an import arrive as null (WAMR's raw call convention).
- Externrefs and import closures live as long as their instance.
- One Ctx per context. Multi-value results of imports are not supported.

Integration (coordinator, with ZN-773.04):

- `tools/package` does not ship the module.
- The build always makes it (`add_dependencies(zinc zn_wasm)`, option `ZN_WASM`).
