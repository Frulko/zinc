## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done in a parallel worktree (2026-10-12).

What: zinc dev [dir] --device <name> runs the dev loop of zinc dev with the program on a paired device, over one session of the agent (op dev). src/cli_core.cpp keeps the loop (watch, asset rebuild, red box) and runs the program through three hooks (zn::cli::DevRemote: start, assets, poll); src/agent/dev.cpp fills them (client) and holds the agent's side (opDev). A save packs the project on the workstation (zinc pack is the check: its output is the diagnostics), sends the members whose SHA-256 changed, and the agent restarts zinc run program.zbc in ~/.zinc/agent/dev/<pid>-<n>/. Output comes back as O frames, the exit as X. A compile error packs a one-file red box started over the project's files. A saved asset is rebuilt here and its ZN-450 messages go as I frames to the program's ZINC_DEV_FD (descriptor 3). The program ends with the session; an agent that stops ends its dev programs (atexit).

Measured (loopback, M1 Pro, other trees building, load average 7 to 10): the new version's first line read back 211 to 250 ms after the save of a source file (six runs); zinc dev reports the start 77 to 85 ms after the save, the red box 112 to 119 ms, an asset sent 35 ms after its save. The test takes 1.7 s.

Tests run: t1 agent_dev PASS (new), t0 agent PASS, t1 agent_apps PASS, t1 dev_mode PASS, t1 asset_reload PASS (the last two cover the local loop of zinc dev, whose code changed).

Decisions (no number taken): (1) the pack is the check on a device, no separate zinc check: one compile per save, same diagnostics. (2) The device holds an unpacked .zapp and runs program.zbc: the program is compiled on the workstation, so the agent refuses a workstation of another engine version. (3) The dev program is not an app (no pid file, not in zinc device apps) and ends with its session; deploy is what leaves a program running. (4) No inspector wrapper on a device (ZN-729.05 has the inspector). (5) server.cpp's environment, pointers, execChild (now with the first descriptor to close) and exitCode are declared in wire.h for dev.cpp instead of copied.

Not proven: a real second machine or a network (loopback only); a UI project with native plugins; a device of another architecture (the pack is for the workstation's target, as with zinc device deploy); megabytes of assets in one save; Linux.

Lines for backlog/later.md: see the final report (the ZN-450 line 'send the asset reload messages over zinc dev --device' is done and can go).
