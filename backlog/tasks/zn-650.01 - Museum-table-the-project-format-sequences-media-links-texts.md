## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
One project file holds a whole installation: sequences (the nodes of the story), each with its media (photo, 3D model, text, audio, video), their layout and timed appearance, hotspots and links to other sequences, descriptions and captions in several languages, the storyboard positions, the idle and attract settings, the theme. A loader that validates with messages naming the field, versioned, with a written reference. (Owner request, 2026-10-10: a demo app useful for mediation in museums: an interactive presentation on a touch table, photo gestures, 3D models, descriptions, presentations, in the manner of Klynt.)

Owner, 2026-10-10 (answers relayed by the coordinator, applied to the format)
- One or two visitors, one shared story; texts and panels turn toward the side of the last touch, photo cards stay free: table.visitors defaults to 2.
- Media kinds in version 1: photo, model, text, audio, video, panorama (360 degrees). Built now: photos and 3D; the others are read, validated and placed.
- Models: glTF/GLB besides OBJ: `file` must end in .obj, .glb or .gltf.
- Narration: audio media with `transcript` (the text the voice is synthesised from) and `subtitles` (WebVTT, `{lang}`); videos have both too.
- Accessibility: accessibility.textSizes, accessibility.highContrast, media.audioDescription, subtitles, table.reach (buttons checked against it).
- Kiosk: kiosk.fullscreen, attractAfter 60, resetAfter 120, attract (a presentation), statistics, updateUrl.
- Theme in the file: six colours, font, titleFont, logo; dark and calm by default.

Decisions (to record by the coordinator; no number allocated)
- Klynt's model kept: media library, sequences with items placed in space and time, links (button or hotspot `on` an item, `overlay`, `transition`), an explicit `next` instead of Klynt's implicit first automatic link, storyboard positions. Differences, with the why: texts are maps by language inside one project (Klynt duplicates the project per language: unusable on a shared table); times are numbers in seconds; no iframe, URL or hover actions (offline table, no pointer hover); every file-backed medium requires credit.source and credit.licence (open-access content must keep its provenance).
- JSON read with JSON.parse (Dyn) and typed by hand: the engine has no key enumeration on a parsed object (no Object.keys, no for-in), so unknown fields cannot be reported: they are ignored and not written back. Documented. An engine follow-up would lift it (below).
- Canonical form written by our own serializer (fixed field order, defaults left out, one line per item): load-save-load is byte-identical and diffs show real changes only.
- Paths are checked to stay inside the assets (no absolute path, no `..`, no backslash or drive): a project file is data that may come from elsewhere.
- table.reach default 520 units: Ideum's roll-under reach for touch tables is 262 mm on 43 inches and 338 mm on 55 inches, about 530 units of a 1920-unit table on both (https://informalscience.org/wp-content/uploads/2021/02/accessibility-touch-tables-ada-white-paper.pdf).
- View holds distance (model) and fov (panorama); a point of interest's `at` is a place on a model and a direction in a panorama, so one projection serves both.

Research used (sub-agent, URLs in the coordinator report): Klynt player source (Sequence, Element, Link, Action models), Hornecker 2008 (Berlin museum tabletop), Hinrichs and Carpendale 2010/2011 (Vancouver Aquarium tables: visitors hardly rotate items, text often wrongly oriented, buttons too small), Scott and Carpendale (territories), Wigdor and Balakrishnan 2005 (rotated text reads 26 to 54 percent slower at 90 degrees), Ideum 2020 and the Smithsonian guidelines (reach, 75 mm targets, x-height 4.5 mm).

Proposed follow-ups (not created)
- Engine, size S: key enumeration on a parsed JSON object (Object.keys on a Dyn, both engines), so that loaders can refuse unknown fields. AC: Object.keys(JSON.parse('{"b":1,"a":2}')) is ["b","a"] on the interpreter and the AOT; museum_format gains an unknown-field case.
- Format, when a second version is needed: per-item `locked`, table physical size in millimetres for target sizes.
