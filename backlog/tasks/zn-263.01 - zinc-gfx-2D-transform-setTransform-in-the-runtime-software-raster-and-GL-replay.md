## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The renderer half of ZN-263 (design: docs/reports/ui-style-system.md ST-14). gfx.setTransform(a, b, c, d, e, f) / gfx.resetTransform() (canvas order: x' = a x + c y + e, y' = b x + d y + f, logical pixels, after translate) apply to the commands that follow: rect, rrect, gradient, border, shadow, drawText, drawImage, polygon, path, stroke. Points (polygon, path, stroke) are transformed when recorded; boxes become transformed commands whose box is their screen bounding box (tiles, damage and culling stay as they are) and whose local box and matrix travel with them, drawn per pixel by the software raster through the inverse matrix (the same coverage formulas as the GL shader) and by the GL replay as quads with local coordinates. The identity is today's path, byte for byte. runtime/gfx.cpp and raster.cpp are shared with the prototype: sim/gfx.mjs gets the no-op functions, lib/gfx.d.ts the declarations.
