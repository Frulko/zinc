## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-10-16 (worktree agent). Built step 2 of docs/reports/zinc-next-fast-refresh.md §7 A; what and where in §10 of that report.

- zinc dev gives its child ZINC_HOT=1 and ZINC_HOT_FD (src/cli_core.cpp dev()). The child runs through src/dev/hot.cpp (zinc command line only): 'hot ready' at its first frame end; to 'reload' it compiles in-process (stderr captured) and answers 'ok <ms> <modules>' at the end of the first new frame, 'restart <reason>', or 'error' + diagnostics + 'end'. zinc dev prints 'zinc dev: v1 refreshed <file> (N ms after the save)' or 'zinc dev: restart: <reason>'; error keeps today's red box. zinc check only runs when no hot version is running.
- Plan: React Native's rules (changed modules by text hash; non-component modules re-run their importers up to a boundary: only capitalised-function exports, or import.meta.hot.accept). Restart reasons: native exports, a library module or the prelude added/removed/changed, baked resources, a re-run module's top-level expression statement (render/renderWindow/onFrame and import.meta.hot calls allowed) without import.meta.hot.dispose, a non-module file, no frame loop, no answer in 5 s.
- Safe point: zn::host::pauseLoop() (src/host/gfx_host.cpp): the loop ends and HostGfxFinish keeps the window. __runLoop is a hot-mode entry (src/ir/lower.cpp).
- Swap: beforeUpdate in old code, release re-run modules' globals, map every live object's class by key + shape (keys two classes share never map), closures of changed files become zombie classes (fields kept, methods trap), copy kept globals by key, load the new ZBC into a fresh Machine and move its code into the running one, rt::rebindCallbacks (gCbs cached a Func*), run the inits then afterUpdate, restart if a zombie is still alive, start the new __runLoop.
- Builtin ZBC classes (string, arrays, maps, sets) get keys from their element types (hot::finish); IR classes and globals are 1:1 with the ZBC (checked in emit.cpp: IR classes first, builtins appended after).

Deviations: (1) the in-process compile runs inside the frame-end hook, so frames pause during it (as they did during a restart); compiling on a thread is a later.md line. (2) Library-module or prelude changes restart (adding an import of a std module restarts, e.g. dev_mode's zinc:gestures). (3) onFrame is allowed at the top level like render. (4) The hot child skips the ZBC run cache (keys need a compile).

Proof: tests/run --tier t1 --only hot_swap PASS (6 s); dev_mode PASS; asset_reload PASS (its code-edit step accepts 'refreshed' now); hot_off PASS; modules PASS; affected_paths PASS; diff-matrix conf:async, conf:modules aot=ok (interp=DIFF is pre-existing, see ZN-742.01). zbc T0 not run (its zbc_test binary is not built in this tree; zbc untouched).
Measured: save to the first new frame 114-126 ms (gfx fixture), 330-400 ms (Solid fixture), 180-300 ms (game-2d template). desktop-app: home.tsx restarts (live closures of the old file, needs ZN-742.03's _hotC), state.ts/main.tsx restart for top-level effects (setColorMode, installMenus), router.ts through state.ts.
Not proven: the window case (pause keeps a real SDL window): no window tests in a worktree; run once after integration.
