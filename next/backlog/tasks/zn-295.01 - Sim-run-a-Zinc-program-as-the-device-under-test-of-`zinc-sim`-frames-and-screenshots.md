## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Second half of ZN-295: the Dut that runs a program (zinc run under the virtual clock) over board.json parts, the zinc sim command, expect-frame, expect-pixel, take-screenshot and the failing-step PNG, SimRunner for zinc test, s3-matrix scenario and the Wokwi example on an equivalent board.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
usage: n/a. zinc sim <scenario.yaml> [--out DIR] [--update-goldens]: a scenario with project: and board: runs against a Zinc program. ProgramDut replays a deterministic run (zinc run, headless, ZINC_STAMP_OUT console lines stamped with the frame, ZINC_FRAMEHASH per frame, ZINC_INPUT script, ZINC_SHOT frame PNG): inputs land as scripted events (set-control through the part's attrs.inputs, e.g. imu shake = pad A, new ZINC_INPUT events pad/padup), runs go ahead of the clock so a wait-serial costs one run. Steps wait-serial, advance, delay, set-control, expect-frame, expect-pixel, take-screenshot (compare-with, tolerance, --update-goldens) work on examples/boards/s3-matrix/dice (scenarios/shake.yaml, 0.46 s wall for 2 s of virtual time); a failing step exits 1, prints the virtual time and leaves fail-step-N.png. NOT done: write-serial, expect-pin and expect-bus on a program (they fail with a clear message: the engine has no pin or bus model behind a program yet), SimRunner for zinc test, the Wokwi example on a board with pins.
<!-- SECTION:NOTES:END -->
