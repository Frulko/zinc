## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done (2026-10-11). zinc debug --cdp[=port] <entry> (src/dbg/cdp.cpp): the engine serves a target of its own on 127.0.0.1 (9222 by default, in chrome://inspect's default list; the zinc:devtools inspector keeps 9229): /json/list (type node, js_app.html frontend URL), /json/version, Host check against DNS rebinding, a WebSocket (RFC 6455; Sec-WebSocket-Accept with mbedTLS's PSA SHA-1 and base64, so the server exists when ZN_TLS is on) on a thread of its own. That thread answers Runtime.enable (executionContextCreated), Debugger.enable (scriptParsed for each program file with code, before the answer as V8 does), getScriptSource, setBreakpointByUrl (0-based lines, file:// URLs), removeBreakpoint, pause, runIfWaitingForDebugger (the program waits for it and starts paused at its first statement, like node --inspect-brk); unknown methods answer empty. The main thread, while paused, sends Debugger.paused (call frames with locations, a local scope per frame, hitBreakpoints) and answers Runtime.getProperties (scope:i and obj:k ids: numbers, booleans, strings, null, objects with className, arrays), evaluateOnCallFrame (a local's name), resume/stepOver/stepInto/stepOut (then Debugger.resumed). SIGPIPE ignored. AC1 and AC2: tests/t1/debug_cdp.sh with tests/cdp_debug_check.mjs (16 checks: discovery, scriptParsed and source, breakpoint by URL, paused stack, locals and unfolding, evaluate, steps, run to the end, Debugger.pause of a running loop), 3 runs in a row pass. Docs: docs/dev-mode.md, the command table. Not verified: DevTools' own frontend (follow-up ZN-709). usage: n/a
