Started 2026-10-11, interrupted at 01:52 when the machine stopped launching non-Apple binaries (python3, cmake, node, zinc builds hang in the kernel, unkillable; reported by zinc-b6, needs the owner, probably a restart). Nothing of it is written in the tree yet: the two edits were made by python3 processes that hung before writing. The plan, ready to apply:
- src/aot/aot.cpp, FnEmitter: in a debug module (m.lines not empty) a Line instruction sets `dbgLine = "#line <line> \"<absolute .ts path>\"\n"` and line() prefixes every emitted C++ line with it (a single #line would let the following C++ lines count up the .ts lines); `#line 1 "zinc-runtime"` before each function and after its statements, so the engine's code is not shown as program lines. declareLocals(): one typed C++ local per VarInfo under its source name (bool, std::int64_t, std::uint64_t, float, double via zn::ops::asF/asD, zn::rt::StrObj* / ArrObj* / Obj*; `this` -> self; C++ keywords and the emitter's own names r, m, win, zt, ze, st, e, rN, aN, LN... get a trailing _), updated after each Move, LoadI or LoadNull into its home register.
- src/main.cpp: `zinc build --debug` (stripped like --bundle) sets gDebug (the debug lowering) and gDebugNative: cflags -O0 -g instead of -O2, no -Wl,-x.
- Test tests/t1/debug_lldb.sh: build tests/data/debug_cli/main.ts with --debug; `lldb --batch -o "b main.ts:19"` must resolve to main.ts:19 without launching (the line table); dwarfdump of the .dSYM must name `total`; the full session (run, frame variable total, bt) only when `DevToolsSecurity -status` says developer mode is on.
