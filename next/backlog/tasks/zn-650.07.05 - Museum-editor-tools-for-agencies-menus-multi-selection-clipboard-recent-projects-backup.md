## Implementation Notes

Done (parallel worktree, 2026-10-11). Test: `next/tests/run --tier t1 --only museum_editor_tools` -> PASS museum_editor_tools (11 s); museum_editor, museum_editor_views and museum_editor_sound still pass with their goldens untouched. Usage: n/a (worktree).

What exists (examples/museum-table/editor)
- doc.ts: `arrange` (align on six edges and axes, distribute across and down; pure), `together` (several operations as one undo step), `clip` / `paste` (sequences on the storyboard, items on a table with the hotspots of the media the table did not show; media adopted by the target project, under a free id when the id is taken by another medium; the result is tried against the player's loader first).
- tools.ts: the selection of several things (Shift or Cmd and a click, Select all), nudge with the arrow keys (table: 1 unit, 10 with Shift; storyboard: 10, 50 with Shift), align, distribute, cut, copy, paste, duplicate, delete of the whole selection; one table of commands that the keys, the system menu bar (zinc:system/menu setApp: File with Open recent, Edit, Arrange, View) and the context menus (menu.popup on a sequence, the storyboard, an item, a table) all run through `perform`.
- files.ts: the editor's own directory (window.dataDir()/museum-table-editor, MUSEUM_EDITOR_DATA for tests; a deterministic run that names none keeps nothing), the ten recent projects, the backups.
- state.ts: files dropped on the window (a .json is opened; a medium is copied into the project folder unless a file of that name is there, then "Add a file" opens on it, one question per file); the backup every 60 s (MUSEUM_EDITOR_BACKUP=seconds) of a project with unsaved changes, deleted by Save and by "Do not save", offered when the project is opened again (Restore, Delete the backup, Later).

Acceptance criteria
- #1: selftest.ts writes the file each of 16 commands leaves (golden/museum-editor/tools/<command>.json), each one step undone byte for byte; session.input + session.system drive the same commands through keys, the menu bar (menu-click), three context menus and a drop: session.json, one frame (session-22.png); recent.input opens the project from File > Open recent: recent.json.
- #2: backup.input ends unsaved after 130 frames with a backup every second: the project file is untouched, the backup equals backup.json; restore.input starts again: the question is on frame 4 (restore-4.png), Restore then Save gives the file the exact bytes of the backup, and the backup is gone.

Decisions (for the coordinator to file)
1. The clipboard holds one header line (what was copied) and the whole project text: Paste reads it with the player's own loader, so copies travel between projects with their media and no second format exists. Cost: 45 KB of text for the sample (marked `ponytail:`).
2. Undo, Redo, Cut, Copy, Paste and Select all show no key in the menu bar: a native menu that owned Cmd+Z/C/V would take them from the text fields (zinc:system edit roles are not wired to fields). The keys still work through ui.onKey.
3. A command asked by a menu within two frames of the same command runs once: on macOS a context menu reports its choice both as the answer of popup and as a menu-click.
4. Deleting or cutting several sequences asks nothing: the links that led to them go in the same step and the status bar says Undo brings them back; one sequence alone still asks where its links should lead.
5. A dropped file never replaces a file of the same name in the project folder (the library may show it); the status bar says so.
6. One backup per project path, in the editor's directory, never beside the project (a museum's shared folder stays clean).

Not proven
- On a real macOS window: the native menu bar, native context menus, key equivalents against ui.onKey (decision 3 is the guard), a real drag and drop. Tests that open a window run after integration.
- Shift/Cmd-click: scripted clicks carry no modifier (ZINC_INPUT `down` has none); the session selects with Select all, the toggle is two functions of tools.ts.
- ZINC_SYSTEM_SCRIPT ticks are passes of the event loop, one or two per frame (once in six runs every event came about twice as late): the session leaves the frames T/2..T free for each event.
