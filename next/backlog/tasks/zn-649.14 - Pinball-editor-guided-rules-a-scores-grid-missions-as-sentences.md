## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
(Left by the pinball table editor, ZN-649.04, see its decision record.) Rules and missions are edited through generic forms of the file's objects. A scores grid (element or group by event), a mission written as sentences with choices, and a confirmation that lists what a deletion takes with it.

Start with conditions (from the second table, ZN-649.05): the form cannot build a `lights` or a `targets` condition one field at a time because every intermediate state is refused by the loader, so Twilight Fair's two conditional rules were written in the advanced field. Conditions and action kinds are built from choices; acceptance also: those two rules are redone by form and the sessions of `tools/twilight_fair` no longer use Cmd+J.

Slice 1: conditions and actions from choices
- The format says what each kind reads. `schema.ts` gains `Variant` / `Variants` (the kinds of the objects of a schema: the field that says the kind, the target, the way, and per kind the name space of its target, the words it may be, whether it is any text, the ways, the numbers); `table-schema.ts` fills them for `condition` (7 tests) and `action` (10 kinds). The loader's rule check (`table.ts` checkKind) reads these lines instead of its own if-chain: one description for the loader, the reference (a table "What each test / do reads" under both sections of docs/pinball-table-format.md) and the editor. No field was added to the file format; 30 broken rules give the same message as before, character for character (compared with the loader of main).
- The editor: adding a condition or an action offers its kinds (the button Add of the list), and the kind chosen is added whole and valid (`presets.ts` startOf: the first group of lights, the first bank of drop targets, the first sound, a counter made with the first thing that counts); a kind that speaks of what the table lacks is not added and the status bar says what to add first. Each part is then a choice among what the table has for that kind (targets and their groups for a test of targets, not all 60 elements), a way among the kind's ways, or a number / a text for the panel. Changing the kind replaces the object by a whole one of the new kind (`state.ts` setKind). A rule's `if` and `do` are shown as sentences (`sentences.ts`, `form.tsx` Guided / Sentence / Part) built from one template per kind and per language in `strings.ts` (word order differs: "there are {way} {value} balls in play" / "il y a {way} {value} billes en jeu"); a kind the format gains later is said by its word and what it reads until it has a template. The list of rules, and a rule's title, are sentences too ("When the ball rolls over lanes, if the lights of lanes are all on: ..."). The advanced mode keeps the plain fields and the text of the file.
- "Find a field" reaches a part of an item of a list from the thing that holds the list ("do[1].target"): sessions no longer need the path of an action.
