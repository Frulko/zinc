## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
(Left by the pinball table editor, ZN-649.04, see its decision record.) Rules and missions are edited through generic forms of the file's objects. A scores grid (element or group by event), a mission written as sentences with choices, and a confirmation that lists what a deletion takes with it.

Start with conditions (from the second table, ZN-649.05): the form cannot build a `lights` or a `targets` condition one field at a time because every intermediate state is refused by the loader, so Twilight Fair's two conditional rules were written in the advanced field. Conditions and action kinds are built from choices; acceptance also: those two rules are redone by form and the sessions of `tools/twilight_fair` no longer use Cmd+J.

## Implementation Notes

State, 2026-10-11 afternoon (a second agent, fresh worktree on main 51d4809e, binary built there with `tools/build zinc`): slices 1 and 2 are done, slice 3 is criterion 2. The first agent's unrun start of the scores grid (scores.ts) was finished and is part of the commit of slice 2.

Slice 1: conditions and actions from choices
- The format says what each kind reads. `schema.ts` gains `Variant` / `Variants` (the kinds of the objects of a schema: the field that says the kind, the target, the way, and per kind the name space of its target, the words it may be, whether it is any text, the ways, the numbers); `table-schema.ts` fills them for `condition` (7 tests) and `action` (10 kinds). The loader's rule check (`table.ts` checkKind) reads these lines instead of its own if-chain: one description for the loader, the reference (a table "What each test / do reads" under both sections of docs/pinball-table-format.md) and the editor. No field was added to the file format; 30 broken rules give the same message as before, character for character (compared with the loader of main).
- The editor: adding a condition or an action offers its kinds (the button Add of the list), and the kind chosen is added whole and valid (`presets.ts` startOf: the first group of lights, the first bank of drop targets, the first sound, a counter made with the first thing that counts); a kind that speaks of what the table lacks is not added and the status bar says what to add first. Each part is then a choice among what the table has for that kind (targets and their groups for a test of targets, not all 60 elements), a way among the kind's ways, or a number / a text for the panel. Changing the kind replaces the object by a whole one of the new kind (`state.ts` setKind). A rule's `if` and `do` are shown as sentences (`sentences.ts`, `form.tsx` Guided / Sentence / Part) built from one template per kind and per language in `strings.ts` (word order differs: "there are {way} {value} balls in play" / "il y a {way} {value} billes en jeu"); a kind the format gains later is said by its word and what it reads until it has a template. The list of rules, and a rule's title, are sentences too ("When the ball rolls over lanes, if the lights of lanes are all on: ..."). The advanced mode keeps the plain fields and the text of the file.
- "Find a field" reaches a part of an item of a list from the thing that holds the list ("do[1].target"): sessions no longer need the path of an action.

What the tests are written to prove (tests/t1/pinball3d_editor_rules.sh, new; sessions written by tests/golden/pinball3d-editor/guided.py). Each point was seen once by a direct run; see the handover above for what no test run has confirmed yet.
- AC1: rules.input is rewritten without Cmd+J, without a path and without a name typed in a text field (a rule made in its form, a mission's step reached from the mission) and still saves rules.json byte for byte (pinball3d_editor).
- The two conditional rules of Twilight Fair are made by choices: `tools/twilight_fair/sessions.py` builds all 22 rules that way, no session has a Cmd+J left, and pinball3d_second_table still gets the shipped table.json byte for byte.
- conditions.input: three rules with a condition of every kind and actions of nine kinds, the buttons of a sentence (up, another kind, take away), a sound refused on a table without sounds: conditions.json, accepted by the game's loader.
- selftest: every kind starts whole; every kind and every event has its sentence in both languages with exactly the parts the format says the kind reads; the 24 rules of the test's table printed as sentences in English and French.

Decisions (slice 1)

Slice 2: the scores as a grid
- The format says what sends what: `SENDS` in table-schema.ts (the events the elements of each list send: bumpers, slingshots, walls and models hit, targets hit and down, rollovers roll, spinners spin, kickers capture and eject, ramps enter and exit, gates pass, flippers flip). The loader does not check by it and the reference is unchanged.
- `scores.ts` (pure): a row per group, then per element, of each of those lists, with the events it sends (a group of several lists once, with the events of all); `scoreOf` reads the first rule that listens there without a condition and scores; `scoreChange` sets its points, or adds a scoring action first in a rule that listens there without a condition, or adds a rule at the end; 0 takes the scoring action away, and the rule when it did nothing else. A rule with a condition is never touched.
- `scoregrid.tsx`: the grid takes the place of the top view while `rules` itself is selected (as the screen layouts do): a number box where the thing sends the event; the box above the names keeps the rows whose name holds what is typed, the one called exactly so first (Cmd+K), so a session reaches a cell by the name of its row and Tab, not by its place. The names do not answer a click (the typist's click beside the board lands on them). One undo step per cell ("Change pops.hit").
- Tests: selftest (5 lines: rows and events, read, write, a new rule or a scoring action more, an emptied cell); scores.input (written by guided.py: 7 cells) saves scores.json, which the loader accepts and on which the probe gives pop1 750 points. rules.input ends on `rules`, where the grid now is: pinball3d_editor compares its frame 34 only (rules-152.png removed).
- PASS pinball3d_editor_rules, pinball3d_editor, pinball3d_second_table, pinball3d_editor_table, pinball3d_format (2026-10-11, after this slice).
- Decisions: the event list of a rule is not narrowed by the chosen thing (`Field.given` of the plan): the grid needs only SENDS, and narrowing changes every session that chooses an event; left as a line for later. The columns have a fixed width that fits the ten events of today in a window of 1440 (no horizontal scroll).

Plan for the next slices

One template per event and per language for a step ("Hit {on} {count} times", "then ..."), the award as "reward: {award} points"; steps added, moved and removed with the same buttons as a rule's sentences; an optional list `do` of actions on a mission (what else finishing it does: "and light the lock"), run by rules.ts when the mission is done, default empty so that no file and no log changes; a button beside a choice of lights or elements that takes the next click on the top view as the choice.
