## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The agent starts apps with an inspector port and says which. `zinc device <d> inspect <app>` forwards it and prints the DevTools address; Zinc Inspector lists the apps of paired devices next to the local ones; `zinc device <d> shot <app>` is the app's own frame through the inspector protocol; `zinc device <d> monitor <app>` is the zinc:telemetry stream in the words of zinc monitor, and `zinc device <d> top` the machine's load, memory and temperature with each app's CPU and RSS every second. Replaces the ssh forwarding of ZN-373.06.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done 2026-10-12 in a worktree (agent of the coordinator), on the Mac, loopback only.

What exists: src/agent/inspect.cpp. The agent gives every app it starts ZINC_DEVTOOLS_PORT (a free port unless run --env names one), keeps it as the second line of run/<name>.pid and says it in apps and info with cpuMs, rss (the app's process group) and at; op top is the answer of info every second. Client: zinc device [<d>] inspect <app> [--port n] (forward + the DevTools address), inspect --all (lines '<port> <device> <app>' then 'ready', ends with its parent; Zinc Inspector runs it and lists the apps as '<app> on <device>'), shot <app> [file.png] (Page.captureScreenshot by a few lines of Zinc run with the engine: the WebSocket of zinc:socket, none written in C++), monitor <app> (the followed log piped into zinc monitor), top [-n count] [--json].

Test: tests/t1/agent_inspect.sh, 8 s. PASS with agent (t0), agent_apps and inspector (t1). Criterion 1: tools/cdp-probe reads the document over the WebSocket of the address inspect prints, /json/list gives the forwarded address, and Zinc Inspector started on an empty port finds 'inspected on <device>', attaches and shows its tree and its screen. Criterion 2: the PNG of shot has 0 pixels of difference with the same program run on the workstation. Criterion 3: the three telemetry lines in the words of zinc monitor; top's machine line twice and the app's pid, CPU share and memory.

Decisions (reversible, no record number taken): the agent chooses the inspector's port rather than reading the one the app chose from its log (a log is cut back past 4 MiB); the port lives in the pid file (one file, removed with the app); shot and monitor reuse the engine (a Zinc script, zinc monitor) instead of a WebSocket client or a second telemetry printer in the agent; top is a stream of info, the share of CPU computed by the client from cpuMs and at.

Not proven: Chrome itself was not started (a scripted DevTools client and /json/list were); the per-app numbers on Linux (/proc/<pid>/stat, written, not run) and the temperature column; inspect --port n and the message for a stopped app (not in the test); the debugger of a program on a device (zinc debug --cdp there is reached with zinc device forward; no command of its own).

Lines for later.md: (Cross-platform pass) ZN-729.05: run tests/t1/agent_inspect.sh on Linux and a Pi, top's CPU and memory come from /proc there and the temperature from thermal_zone0. (Ideas) ZN-729.05: zinc device deploy --inspect, a pack with import 'zinc:devtools' in front as zinc dev does, so an app that does not import it can be inspected. ZN-729.05: zinc device debug <app>, the app restarted under zinc debug --cdp with its port forwarded. ZN-729.05: inspect --all follows apps started later (it lists those running when it starts). ZN-729.05: the app chooses its inspector's port (ZINC_DEVTOOLS_PORT=0) and tells the agent, closing the gap between the agent finding a port free and the app listening.
