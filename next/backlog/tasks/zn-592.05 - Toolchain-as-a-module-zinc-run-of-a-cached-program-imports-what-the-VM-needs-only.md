## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ZN-592.03 measured what is left of zinc's launch on the Intel Mac (time from process start to the first initializer, interleaved, best of 40): an empty program 4.8 ms, zinc 7.7 ms; the gap is dyld resolving zinc's imports: 354 libSystem symbols cost ~2.0 ms (a program with only these imports: 6.6 ms; libSystem re-exports 38 libraries that dyld searches in order, the system calls of libsystem_kernel being 32nd), 199 libc++ symbols ~0.3 ms, the 12 MB of the binary ~0.4 ms, the 28 initializers 0.5 ms. Lazy binding does nothing (dyld 4 binds lazy pointers at launch, -no_fixup_chains measured), -dead_strip with an ABI export list removes only ~15% of the imports. So jsonout interpreted (10.6 ms) stays behind qjs (6.9; qjs on an empty file 5.3) while one binary holds the compiler, the toolchain manager, the LSP, the dev server, TLS and the network. Move what a cached interpreted run does not use (frontend, IR, AOT, tc, lsp, dev, prof, sim...) into a module loaded on demand (like libzn_window, D67), measure the imports and the launch, and decide from the numbers (the plugins resolve zrt, hal and JS_ symbols from zinc: keep those in the executable).
