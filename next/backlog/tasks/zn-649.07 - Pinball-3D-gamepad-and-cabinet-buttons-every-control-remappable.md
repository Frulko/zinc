## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-10-11, parallel agent (worktree), Intel Mac, no gamepad and no cabinet attached. On ZN-574's gamepad rows (worked before this task; its Kaplay criterion is still open, which this task does not need).

Done: examples/pinball3d/src/input.ts has a new kind of input, gamepad:<button> (a button of any plugged gamepad by its place, the 17 names of zinc:gfx's GamepadButton), beside key:, pad: and touch:. Defaults added: the two triggers flip, the south button pulls the plunger; the pad: defaults already there now answer for a gamepad too (d-pad or left stick, shoulders, west and north for the bumps, start, back), since the engine adds a gamepad to the twelve zinc:gfx buttons. The next table (Tab, T, Select) was read by chooser.ts on its own: it is now the eighth action, nextTable, in the same table, so the settings file remaps every control. A settings file that names an action that is none is reported (controls.flipper: is no action (...)), as an input that is none already was. A cabinet's buttons are keys (an encoder set as a keyboard) or a gamepad (an encoder that shows up as one): no code of their own; the README gives a default layout to wire.
README: the table of the default bindings for keyboard, gamepad, cabinet and touch with each action's name in the settings, and the four kinds of input.

Test: tests/t1/pinball3d_controls.sh (PASS, 25 s; with pinball3d, pinball3d_aot, pinball3d_chooser, pinball3d_format, pinball3d_editor PASS): a scripted gamepad (play.py --gamepad: start, south, the triggers, west) plays the 60 s game and prints tests/data/pinball3d/play.log byte for byte; a settings file that moves all eight actions to other gamepad buttons plays the first 760 frames as the head of play.log, bumps from the right and the front, goes to the second table, and the default buttons then do nothing; three wrong settings are reported by name.

Not proven: a real gamepad or a real cabinet encoder (scripted input only); play.log itself is played with the scripted pad buttons, not keys (a scripted key is never released), so criterion 1 compares the gamepad with that log; the game compiled was run with the pad script (pinball3d_aot), not with the gamepad script.
