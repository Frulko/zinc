## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`zinc agent` listens on TCP and announces `_zinc._tcp` over mDNS. A client pairs once with the code the agent shows (a PAKE, so the short code cannot be attacked off line), which gives it a key of its own; every later session is TLS with that key. `zinc device list|pair|unpair|info`. No crypto of our own: mbedTLS.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 zinc agent announces itself and zinc device list finds it on the same machine, with its name, address and whether it is paired
- [ ] #2 Pairing with the code shown by the agent succeeds; a wrong code is refused, three wrong codes close the pairing, and a client that is not paired is refused by every other operation
- [ ] #3 zinc device <name> info prints the kind of machine, OS, architecture, cores, memory, load, temperature when the machine reports one, the engine version and the apps installed and running; --json gives the same as JSON
- [ ] #4 A T0 test on the loopback interface covers the three criteria above; the decision record names the PAKE, the session keys and the mDNS library
