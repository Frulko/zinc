# zinc:carplay (experimental)

A separate Zinc plugin, with a native FFmpeg media decoder and a separately
installed GPL receiver process. No CarPlay-specific code is added to the engine.
The adapter uses pinned PlayPort for wireless and a separate DiPlay-derived
macOS USB overlay, including software accessory authentication with a local identity.
No physical MFi coprocessor is required by this backend.

## Offline native demo

`examples/carplay/run` generates local H.264 video and a short PCM tone, then
opens a native Zinc window. It needs FFmpeg and `build/zinc`, but no receiver,
identity or phone. Use `ZINC=/path/to/zinc examples/carplay/run` to reuse an
engine. Offline mode is labelled explicitly and never claims authentication.
See [the demo README](../../examples/carplay/README.md).

## Run on macOS

Prerequisites: FFmpeg development packages on pkg-config's path, JDK 21 or newer,
Xcode command line tools, Bluetooth and an iPhone on the same Wi-Fi network.

```
plugins/carplay/backend/build
export ZINC_CARPLAY_IDENTITY=/absolute/path/to/identity
plugins/carplay/backend/run --wireless --wifi-ssid YOUR_SSID --token YOUR_LOCAL_TOKEN
```

The identity directory must contain `offline-mfi/certificate.p7b` and
`offline-mfi/identity.pk8`. These are external runtime inputs, not generated by
this plugin. No credentials are bundled. An arbitrary self-signed certificate
can exercise tests but cannot authenticate to an iPhone.

For the first pairing, use the fetched backend's
`build/carplay/playport/macos/bt-bridge/bt-bridge --scan` and
`--pair <address>` while the phone's Bluetooth settings are open. macOS must
allow Bluetooth for the terminal and incoming connections for the receiver.
Disable macOS AirPlay Receiver if it conflicts with the receiver.

In another terminal:

```
ZINC_CARPLAY_URL='ws://127.0.0.1:8080/ws?token=YOUR_LOCAL_TOKEN' \
  examples/carplay/run --live
```

The demo uses a native Zinc Canvas, not a browser or a webview. The WebSocket
is only the media/control transport. The backend's `--http` mode is intended
for this local connection; use a trusted network and do not expose its ports
to the Internet. End the receiver with Ctrl-C when finished.

## Wired macOS transport

The separate backend also implements native libusb USBMUX/NCM, Lockdown
pairing/TLS/carkit, wired iAP2 and a macOS utun IPv6 link. It requires libusb
>= 1.0.25 in addition to the build prerequisites above. Start with
`plugins/carplay/backend/run --usb-list` for descriptor-only discovery; USB
capture, mode transition and utun configuration are explicit privileged actions.
See [the wired backend instructions](backend/usb/README.md) for exact commands,
phone selection, Trust, cleanup and physical verification limits. The viewer's
loopback URL and native media/input APIs are the same in either transport.
No physical USB session has been verified.

## API

`new Session()`, `connect(url)`, `view(x,y,w,h)`, `touch(x,y,down)`, `home()`,
`siri()`, `key(name)`, `setNightMode(night)`, `close()`. `image` is a runtime image; `status`, `error`, `width`,
`height` and `frames` expose the connection/media state. `frames` counts accepted
encoded packets, not physical screen refreshes. Close sessions before exit.

`touches(contacts)` sends a full report for up to two simultaneous contacts.
Coordinates use the projected screen's pixels; each contact has `id` (0 or 1),
`x`, `y` and `down`. Missing slots are released. Slot identity is preserved when
a finger lifts or the input list changes order. `view()` reads Zinc's multitouch
points, captures fingers that start inside the video, and clamps drags at its
edges. On a Mac, an ordinary trackpad supplies mouse input rather than screen
multitouch; use a touchscreen or the API to provide two independent contacts.

`setNightMode(true)` asks the phone for night appearance; `false` requests day.
The choice is remembered before connection and reapplied when a phone session
starts. The demo has a Day/Night button. Automatic selection from a light sensor
or vehicle headlights is left to the application calling this API.

`key(name)` maps Arrow keys to rotary focus, Enter to select,
Escape/Backspace to back, Home to Home and S to Siri. A dropped WebSocket retries
at 0.5 seconds with exponential backoff capped at eight seconds. `close()` cancels
retry and releases video, playback and capture; `connect()` replaces any prior
connection. A policy rejection (such as an invalid access token) stops retries
and reports an access error. Old socket callbacks cannot mutate the replacement session.

Receiver microphone requests use the existing Zinc microphone capture and
permission implementation. PCM and FFmpeg/libopus packets match the pinned
PlayPort WebSocket sender; PlayPort owns RTP encryption and delivery to the
phone. Capture stops on a mic stop request, session end, disconnect or close.
The demo declares the microphone permission. Background mode never opens an OS
permission dialog: use `ZINC_BACKGROUND=0 examples/carplay/run --live` for a
manual foreground run that can ask when Siri starts capture. If access was
denied, enable it in macOS Privacy & Security; denial produces a visible error.
A synthetic microphone is accepted only with explicit `ZINC_FAKE_MICROPHONE=1`.
No echo cancellation or live voice-quality claim is made.

H.264/HEVC video and AAC/Opus/LPCM audio are decoded locally. Audio streams are
mixed by zinc:audio. Current video decode uses software FFmpeg and a pixel
conversion; no hardware acceleration or zero-copy performance claim is made.
The configuration envelope is tied to the pinned upstream revision.

## Validation and remaining work

`tests/run --only carplay` generates real H.264 and AAC fixtures with FFmpeg,
checks H.264/HEVC and AAC/Opus decoding, PCM envelopes and image cleanup, rejects malformed envelopes, and sends video
and touch events through an actual loopback WebSocket. No phone, pairing or
network credential is used. The upstream backend has 96 passing tests on Mac.

Real macOS USB projection is verified on an iPhone18,1 running iOS 27.0.1, without a physical MFi chip: authentication, AirPlay, H.264 video and automatic stereo 48 kHz audio playback in Zinc. See backend/usb/README.md. Linux transport, GPS injection and cluster display remain. No Raspberry Pi or real wireless session has been verified. Microphone encoding/capture, keyboard input and reconnect have automated loopback proof; live Siri/calls remain unverified. The plugin is experimental.

See backend/UPSTREAM.md for provenance, license and the pinned source revision.

## Experimental software identity

The pinned [PlayPort identity instructions](https://github.com/youcci/playport#accessory-identity-required)
identify a public experimental pair in the DiPlay v0.2.7 preview APK.
[DiPlay's notices](https://github.com/shihabal3amri/DiPlay/blob/main/docs/THIRD_PARTY_NOTICES.md)
say it came from Carlinkit firmware; it is runtime data, not GPL source, and its
continued acceptance is unresolved. Your own accessory identity or an upstream
remote MFi service is preferable when available. A self-signed certificate
cannot replace an accessory identity.

For a personal local experiment, keep the APK and extracted pair outside the
repository (do not commit, log or redistribute the key):

```sh
umask 077
identity_cache="${XDG_DATA_HOME:-$HOME/.local/share}/zinc/carplay-experiment"
mkdir -p "$identity_cache/identity/offline-mfi"
curl -fL -o "$identity_cache/DiPlay-0.2.7.apk" https://github.com/shihabal3amri/DiPlay/releases/download/v0.2.7/DiPlay-0.2.7.apk
unzip -jo "$identity_cache/DiPlay-0.2.7.apk" 'assets/offline-mfi/*' -d "$identity_cache/identity/offline-mfi"
chmod 600 "$identity_cache/identity/offline-mfi/"*
export ZINC_CARPLAY_IDENTITY="$identity_cache/identity"
```

The APK downloaded for this session had SHA-256
`27b434462da7e78b1ff0987d129ed0a4b0a0e56beceaf8ec221d47150d4675bd`.
Its extracted key/certificate passed an OpenSSL sign/verify challenge locally;
the real pinned receiver loaded it and served a token-protected loopback
WebSocket hello plus public read-only `/api/status` reporting
`sessionActive: false`.
These checks do not establish Apple certification or iPhone acceptance.

## Live acceptance checklist

1. Build the separate backend, set the external identity path and choose a local
   token. Check the receiver's help and transport prerequisites below before
   starting it. Keep logs local and redact tokens or personal device names.
2. Wireless: open the phone's Bluetooth settings, scan/pair with the backend's
   bt-bridge, then start `backend/run --wireless --wifi-ssid ... --token ...`.
   Confirm the receiver and phone share Wi-Fi, macOS allows Bluetooth/incoming
   connections, and AirPlay Receiver is disabled if port 7000 is busy.
3. USB: follow `backend/usb/README.md`: list/select the exact phone, explicitly
   switch/re-enumerate only if needed, start the privileged `--usb` receiver and
   accept Trust. Do not run wireless and USB modes in the same receiver process.
4. Launch `examples/carplay/run --live` with `ZINC_CARPLAY_URL`. Verify the real
   phone reports CarPlay, video and audio arrive, and Home, Siri, two-contact
   press/move/release, keyboard and Day/Night reach the phone.
5. With microphone permission granted, speak to Siri and place a call; check
   both directions of audio, interruptions and capture stopping at session end.
6. Unplug/interrupt the selected transport, reconnect, and verify media resumes,
   night mode survives and Disconnect prevents further retries. Close both
   viewer and receiver when done. Record iPhone model/iOS and actual results.

No attached iPhone was supplied for this session. No pairing, real Siri/call or
physical USB media session has been verified. Raspberry Pi and Android Auto are
later work; no cross build belongs to this Mac validation.


## Native debug tools

The example's Debug panel controls simulated external GPS fixes and GPX playback
over the existing authenticated receiver connection. It shows real decoded iAP2
HUD metadata and a separate stream111 image when the phone supplies a cluster
map. Opt in before receiver startup with `ZINC_CARPLAY_CLUSTER=1`; see the
[debug player guide](../../examples/carplay/README.md#debug-laboratory).

Raw Mac trackpad contacts need this branch's newly built engine. The viewer
launcher sets `ZINC_TRACKPAD_TOUCHES=1`; use `0` to keep normal desktop input.
Screen touches and two stable slots use the same existing plugin input path.
The mouse-based two-contact mode is explicitly simulated.

USB pairing is now persistent under backend state-dir/usb-pairing with private
0700/0600 modes, stable IDs, atomic replacement and narrow re-pair policy. A
locked phone does not erase trust. Actual USB lock restrictions remain enforced
by iOS. Wireless uses classic Bluetooth RFCOMM and Wi-Fi, not BLE. The Mac helper
and new Linux BlueZ helper share the receiver interface; see the
[wireless guide](backend/linux/README.md). Neither Pi hardware nor real wireless
projection was tested during this Mac session.
