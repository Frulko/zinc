# zinc:carplay (experimental)

A separate Zinc plugin, with a native FFmpeg media decoder and a separately
installed GPL receiver process. No CarPlay-specific code is added to the engine.
The current adapter uses PlayPort's wireless macOS backend (DiPlay/xcertplay
lineage), including software accessory authentication with a local identity.
No physical MFi coprocessor is required by this backend.

## Run on macOS

Prerequisites: FFmpeg development packages on pkg-config's path, JDK 21 or newer,
Xcode command line tools, Bluetooth and an iPhone on the same Wi-Fi network.

```
plugins/carplay/backend/build
export ZINC_CARPLAY_IDENTITY=/absolute/path/to/identity
plugins/carplay/backend/run --wireless --wifi-ssid YOUR_SSID --token YOUR_LOCAL_TOKEN
```

The identity directory must contain `offline-mfi/certificate.p7b` and
`offline-mfi/identity.pk8`. These are external runtime inputs, not generated by
this plugin. No credentials are bundled. An arbitrary self-signed certificate
can exercise tests but cannot authenticate to an iPhone.

For the first pairing, use the fetched backend's
`build/carplay/playport/macos/bt-bridge/bt-bridge --scan` and
`--pair <address>` while the phone's Bluetooth settings are open. macOS must
allow Bluetooth for the terminal and incoming connections for the receiver.
Disable macOS AirPlay Receiver if it conflicts with the receiver.

In another terminal:

```
ZINC_CARPLAY_URL='ws://127.0.0.1:8080/ws?token=YOUR_LOCAL_TOKEN' \
  ZINC_BACKGROUND=1 build/zinc run examples/carplay
```

The demo uses a native Zinc Canvas, not a browser or a webview. The WebSocket
is only the media/control transport. The backend's `--http` mode is intended
for this local connection; use a trusted network and do not expose its ports
to the Internet. End the receiver with Ctrl-C when finished.

## API

`new Session()`, `connect(url)`, `view(x,y,w,h)`, `touch(x,y,down)`, `home()`,
`siri()`, `setNightMode(night)`, `close()`. `image` is a runtime image; `status`, `error`, `width`,
`height` and `frames` expose the connection/media state. `frames` counts accepted
encoded packets, not physical screen refreshes. Close sessions before exit.

`touches(contacts)` sends a full report for up to two simultaneous contacts.
Coordinates use the projected screen's pixels; each contact has `id` (0 or 1),
`x`, `y` and `down`. Missing slots are released. Slot identity is preserved when
a finger lifts or the input list changes order. `view()` reads Zinc's multitouch
points, captures fingers that start inside the video, and clamps drags at its
edges. On a Mac, an ordinary trackpad supplies mouse input rather than screen
multitouch; use a touchscreen or the API to provide two independent contacts.

`setNightMode(true)` asks the phone for night appearance; `false` requests day.
The choice is remembered before connection and reapplied when a phone session
starts. The demo has a Day/Night button. Automatic selection from a light sensor
or vehicle headlights is left to the application calling this API.

H.264/HEVC video and AAC/Opus/LPCM audio are decoded locally. Audio streams are
mixed by zinc:audio. Current video decode uses software FFmpeg and a pixel
conversion; no hardware acceleration or zero-copy performance claim is made.
The configuration envelope is tied to the pinned upstream revision.

## Validation and remaining work

`tests/run --only carplay` generates real H.264 and AAC fixtures with FFmpeg,
checks H.264/HEVC and AAC/Opus decoding, PCM envelopes and image cleanup, rejects malformed envelopes, and sends video
and touch events through an actual loopback WebSocket. No phone, pairing or
network credential is used. The upstream backend has 96 passing tests on Mac.

Not yet implemented: macOS/Linux USB host transport; microphone uplink for
Siri/calls; keyboard/rotary input; automatic reconnection; GPS injection and
cluster display. No real iPhone session or Raspberry Pi execution has been verified. The plugin
is a tested integration prototype, not a complete CarPlay receiver release.
