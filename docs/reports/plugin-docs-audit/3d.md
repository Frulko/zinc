# zinc:3d documentation audit

## What it is
3D scenes for makers: meshes (primitives, OBJ, glTF, .zmesh, large streamed worlds), materials, lights, fog, cameras, drawn by a software rasterizer or the GPU. Output is an image that composes with `zinc:gfx` and `zinc:ui`.

## Targets and status
`plugin.json` lists macos (GL back end), linux, windows, rpi1, esp32, wasm, ios. `docs/plugins/3d.md` table: macOS measured; rpi1 and esp32 only under QEMU (no hardware timings); wasm built, not run in a browser; ps1/ps2 not enabled. Console back ends (3ds, psp, vita) are described in prose but not in the table or in `targets`. Backlog: ZN-792 (console targets missing from `targets`), ZN-754 (no psp/ps2 diagnostic), ZN-477 (Vita GXM).

## What is missing
1. Screenshot gallery: link `docs/img/3d-cubes.png`, `3d-model.png`; add shots of `examples/3d/orbit` (`ZINC_SHOT=docs/img/3d-orbit.png zinc run examples/3d/orbit`) and a fog and a glow scene (the t1 tests already render them).
2. A "Your first 3D scene" tutorial in 6 steps: cube, camera, light, texture, load an OBJ/glTF, add fog; each step a screenshot.
3. Document `Fog` and `scene.fog`, `Scene.ambient`, `Node.visible`, and the `zinc:3d/scene` module (scene exchange from Blender: link `docs/scene-exchange.md`).
4. Split the 261-line page: move "Large static worlds" and the PSP/3DS/Vita notes into their own guide ("Streaming big worlds"), keep a short API page.
5. A "Choosing zinc:3d vs three vs animation" box (link `docs/start/choose.md`).
6. A per-target table that includes n3ds, psp, vita, with the renderer used and a link to `docs/reports/tokyo-per-device.md`.
7. Troubleshooting: black screen with `renderer: gpu` and no context, `out of memory (heap budget)` on ESP32, 65535-vertex limit.
8. (hardware) real Pi 1 and ESP32 timings to replace the QEMU estimates.
9. Add the option table to `zinc.json` examples with a copyable snippet.

## Wrong or stale
- "Limits and follow-ups": "no transparency, fog, mipmapping or texture filtering (nearest texel)" contradicts the same page (Blend.Alpha/Add, `Filter.Mipmap`, GPU mipmaps) and the code (`class Fog`, `Scene.fog`).
- "Not done yet: the GLES 2 path ... contexts on Linux, the Pi and the web" and "ps1, ps2 targets: not enabled (see follow-ups)" - the follow-ups list no such item; verify against ZN-477/754.
- The Targets table says "rpi1 ... esp32 builds" but gives no mention of macOS-only GPU in `plugin.json` (`native.impl.macos` only), fine, but the `ios` target is listed in `plugin.json` and absent from the page.
- Timings quoted for an Intel Mac and an M1 Pro side by side; the dev machine is now the M1 Pro.
