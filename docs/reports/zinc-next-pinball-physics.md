# Shared pinball physics and cabinet refresh — 2026-10-25

Owner request: make both pinballs more predictable and lively using Space Cadet as a reference, share improvements across demos, use proven physics libraries, then improve UI and assets.

## Engine and scope

`examples/pinball-kit` now owns the Box2D 3.1.1 adapter, Jolt 5.6.0 adapter, table schema/loader, collision/render geometry, calibration, fixed clock and cosmetic recoil. Nova Patrol and its DS view share Box2D; the 3D game and editor share Jolt. Existing vendored plugins and licences are reused. The game's rules, input, scoring and rendering remain outside the kit. No handwritten collision solver is shipped by the live demos.

Reference: Space Cadet's [pb.cpp](https://github.com/k4zmu2a/SpaceCadetPinball/blob/master/SpaceCadetPinball/pb.cpp) limits ball travel between collision updates; [TFlipperEdge.cpp](https://github.com/k4zmu2a/SpaceCadetPinball/blob/master/SpaceCadetPinball/TFlipperEdge.cpp) transfers energy from a moving surface. We adopt the half-radius relative-travel bound and passive held flippers. Raw original gravity values are not a verified tuning preset: game data and units matter. Microsoft [says it cannot publish the original source](https://devblogs.microsoft.com/oldnewthing/20181221-00/?p=100535); the referenced project is a community decompilation. No original game assets are copied.

## Physics corrections

- Box2D owns 2D contacts, continuous collision, friction, spin and multiball. Kinematic flippers stop explicitly in a held pose: Box2D's target-transform function can return without clearing a previous velocity. Plunger motion retains the final interval's impulse. Tests cover both.
- 2D gravity changes from 58 to about 31.2 in/s², matching a solid sphere's rolling acceleration on a 6.5° board. The common physical gravity is 981 cm/s² and speed cap 700 cm/s. The 2D coil cap changes from 44 to about 31.4 rad/s and the full plunger-tip speed from 230 to about 189 in/s. 3D table-authored coil and material values remain data.
- Jolt's separating contacts are no longer converted to approaching ones by `abs(speed)`. Relative-travel subdivision includes moving flippers and all live balls; duplicate contact reports within one outer step produce one touch per ball/part.
- Ramp layers use separate Box2D worlds; a portal transfers the ball after all worlds have stepped, avoiding a double advance. The target bank moves against the wall; the ramp underside lip slopes instead of forming a horizontal resting pocket.
- All game loops consume rendering delta through `FixedClock`; physics stays fixed-step and ball rendering interpolates. Catch-up is capped at 100 ms after a stall. Tests prove equal physical positions at 30/60/120 rendering Hz and preserve time with uneven frame deltas.

Calibration probes, before → after: left-flipper peak shot speeds at distances 1.2/1.8/2.4/2.9 in from its pivot are 84.5/120.9/187.4/164.4 → 49.9/78.7/127.3/120.4 in/s. A held flipper keeps the dropped ball at approximately (6.3, 35.8), effectively still after three seconds. A 50 in/s ramp shot falls short; 60 in/s reaches the wire. The final ten-minute autopilot soak reports no stuck ball and ends at score 273200. These are calibration checks, not a human assessment of fun or fairness.

## UI and assets

Nova Patrol uses Kenney Puzzle Pack CC0 ball/star sprites, a darker and quieter board, eight score digits growing when necessary, a less prominent panel frame and a compact launch card. Portable input hints also fix the QuickJS TOUCH import failure (ZN-801). Both 3D tables gain moving bumper caps and sling rubbers; 2D bumpers add subtle shake. Score cards, brighter captions, text fitting and mission progress improve the 3D panel. Tidal Lock's quieter playfield, backglass and Kenney-star bumper-cap texture are generated by its existing editable art script. Credits and licences ship with the assets. No new UI or image dependency is introduced.

The frozen numeric-profile pinball outputs remain unchanged: their old pure-Zinc dependencies are preserved in `tests/data/pinball-frozen`; current physics has separate invariant tests. Updated game logs/goldens reflect adaptive contacts, fixed-clock timing, interpolation, recoil and the intended art/UI changes.

New console cores generate/link the existing Physics2D module. A host-only build of `targets/console` with its generated bindings successfully runs the packed `pinball_physics/core.ts` program (`zinc:start`, all checks passed, `zinc:exit 0`). Physical consoles need their core rebuilt; no cross build, emulator or physical-device test was performed.

Short headless timing sample on the M1 Pro, interpreter, 960×600, 2702 fixed-delta frames, after other session checks finished: rules+physics per frame is 0.189 ms with one ball and 0.235 ms with three, versus 0.074/0.142 ms for the former solver. Total frame averages are 0.39/0.46 ms versus 0.25/0.35 ms; one new-run outlier reaches 16 ms. This is added cost for a proven solver and new feedback, not a speedup. Shots diverge with the new physics, so it is not a formal identical-workload benchmark or a device FPS guarantee. See the performance tracker for commands.

Human play, listening and real-device frame costs remain open in ZN-649.12 and the cross-platform pass. Nova Patrol's existing audio module still only records cues; this change does not wire its sound output. No push or release.

## Physical 3DS feedback and version 0.2 — 2026-10-25

The owner reported severe lag and little visible asset change in the SD build. That build did include Box2D, but embedded bytecode still ran through the interpreter; the dual-screen renderer also retained its old flat bumper decals and rectangle sparks. Desktop verification was insufficient for this delivery.

Fixed: compile the complete program through `tools/build-console-core n3ds --aot`, retain 960 Hz/adaptive collision accuracy, send changed ball velocities only, stop moving kinematic mechanisms once, skip resting flipper geometry updates, and synchronize collider enable flags once per outer step. Core invariants and the desktop interpreter/QuickJS pixel comparison still pass unchanged.

The actual DS renderer now uses the shared textured cap with recoil, Kenney star images for sparks, darker score panels, accent strips and mission progress. `quality.n3ds.ts` limits the pool to 12 sparks. Only n3ds-pinball frame hashes change in `n3ds_demos`; the test passes. Azahar's captured top screen visibly confirms the blue cap textures and panel changes.

Matched 360-frame scripted Azahar sessions, serialized under the shared emulator lock and with no build from this session running: embedded interpreter program p50/p99 12/21 ms, compiled optimized 0.2 program 4/7 ms; emulated refresh gaps p50/p99 17/34 → 17/18 ms. Startup baking remains approximately 575–647 ms in these guest logs. These are emulator/guest observations, not physical-console timing or a claim of guaranteed 60 FPS on the owner's model.
