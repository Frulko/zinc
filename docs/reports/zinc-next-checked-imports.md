# Imported types in checked JSON copies

QuickJS acquires record schemas from the same type-only module bindings as the typed frontend. A transform builds one synthetic root containing retained interfaces/type aliases, type-only imports needed by those declarations or JSON sites, and a private alias for each checked JSON site. Function/value bodies and side-effect imports do not enter this graph. Local type reexports retain their imported bindings.

A read adapter resolves each imported/reexported specifier with the engine's existing normalizer, including its import map, plugins and suffixes, and supplies physical relative paths to `loadProgram`. Standard modules carry their physical source base separately from their logical Zinc name. Native specs stay declaration sources rather than simulation implementations. Resolver JSON configuration remains raw data. The adapter calls `loadProgram` once per transform with `nativeContractsOnly` and no loader stage; it does not run the checker, emit IR, register/build native providers or execute application code.

The checked schema generator traverses existing `Ast::modules` imports and exports. Each record name includes its declaring module identity, so private same-named interfaces cannot replace each other. Named aliases, namespace imports, local imported-type reexports, export-from and stars resolve to the declaring module. Recursive records share their private schema reference; export resolution has an RAII visit guard and refuses unresolved/ambiguous bindings. Unsupported class/enum/literal/generic schema categories keep their existing limitation.

Graph reads are bounded to256 files and16MiB of raw or rewritten source; type traversal is bounded to64 levels and the existing record schema depth16. Parse, source-budget and depth failures are explicit transform diagnostics, never an omitted whole-record validation. The new checked path is separate from `schemaOfType(..., false)` and the existing worker-message helper; native record wire output remains byte-identical.

Exact `checked_imports` proof executes valid and malformed imported records on interpreter, actual native AOT and QuickJS. An injected source/normalizer proof covers mapped physical standard-module bases, dormant function-only imports, parse failure, byte/depth budgets, reexport cycles, ambiguous stars, unsupported imported classes and same-directory hidden paths. The actual iPod `ipod.SmartRules` minimal record now rejects missing identity on all three engines. Full production wire/default/null/rules tests also pass all three. The prepared actual sender roundtrip is currently blocked by a separate pure fluent-call checker timeout; no app rewrite or type duplication is used.

References: [TypeScript module syntax](https://www.typescriptlang.org/docs/handbook/modules/reference.html#module-syntax), [module scopes](https://www.typescriptlang.org/docs/handbook/namespaces-and-modules.html#needless-namespacing), [imports and reexports](https://www.typescriptlang.org/docs/handbook/2/modules.html).
