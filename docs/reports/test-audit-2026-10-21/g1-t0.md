## Cross-group notes

- No full duplicate found inside g1; the suite is mostly one test per feature.
- tls (t0) vs netlog (t0): netlog repeats the cert-minting block of tls.sh and only tests TLS when openssl>=3.4, so TLS has no CI coverage at all today; fix tls once (brew openssl) and drop the copy in netlog.
- Hardware/sim pairs are intentional, not duplicates: microphone_sim/webcam_sim vs t1/microphone, t1/webcam (local hardware).
- update_sign vs t1/self_update (wrong signature, unsigned manifest) and package.sh (update --check): small overlap, unique tamper cases remain in update_sign.
- native_call vs qjs_native replay the same program on two engines on purpose; jsx vs qjs_bundle likewise.
- export_android, system_phone, video_phone, t1/permissions_export all run `zinc export --target android`; each asserts different content but each pays an export (consider one shared export).
- console_audio, console_host, hardware_memcard share build/console-pure; console_core and console_assets have their own build dirs (four cmake builds of the console core on a cold runner).
- t0/zinc_gl_api vs t1/zinc_gl_api_tour; t0/aot vs t1/aot; t0/run vs t1/conformance/corpus_complete: related, assertions differ (not checked in depth, other groups).
- hardware_* (7 files, same skeleton) could become one script to cut process start cost; not required.
- Fixed ports: mqtt.sh uses 18831 hard-coded; others use tests/free_ports.py.
