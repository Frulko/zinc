# Sidecar: features worth copying from e-ink monitor tools (research, 2026-10-28)

Scope: what Dasung, Boox Mira, Modos, PineNote and reMarkable mirroring projects do, and what to add to the Mac to reMarkable Paper Pro sidecar. Not repeated: `rmpp-eink-monitor-research.md` (Modos per-pixel update, Mira presets, miractl filters, goMarkableStream deltas) and `rmpp-eink-cursor-latency.md`.
Marking: (S) stated by the source, (I) our inference. Vendors publish little; the search tool returned thin results for Dasung and the Boox desktop app, so those rows are weak.

## 2. How the problems are handled

- **Typing**: PineNote is the only documented design: fast binary waveform while keys arrive, one clean pass after 8 s idle. Boox reviewer wishes the same: full refresh after a drag ends, fast only while scrolling. Our clean-after-1 s-rest is the same idea; 8 s is a gentler "typing" value (I).
- **Caret blink**: every blink is a changed region. Mac: `defaults write -g NSTextInsertionPointBlinkPeriodOn -float 999999` and `...Off -float 1` (or `Off -float 0`); undocumented, restart the app, ignored by Safari, Notes, Mail, Word and some Electron apps; revert with `defaults delete -g <key>` [Apple forum](https://developer.apple.com/forums/thread/712625), [Chromium defaults_utils](https://chromium.googlesource.com/chromium/src/+/main/ui/base/cocoa/defaults_utils.mm), [Literature&Latte](https://forum.literatureandlatte.com/t/blinking-insertion-point-with-recent-update/134175). VS Code: `"editor.cursorBlinking": "solid"`, `"terminal.integrated.cursorBlinking": false` [bobbyhadz](https://bobbyhadz.com/blog/vscode-change-cursor-color-style-and-animation), [Cursor forum](https://forum.cursor.com/t/setting-cursorblinkinginactive-does-not-seem-to-work/138652). Boox reportedly disables caret blink on the device side; a Boox Max3 user as monitor could not find the setting [MobileRead](https://mobileread.com/forums/showthread.php?p=4193373). Our side can do better than prefs: see feature 2.
- **Pointer trails**: Modos says FPGA gives "special compensation" for the cursor, no method given. Mira: cursor speed vs ghosting is the Speed preset trade-off. No source for a pointer overlay drawn by the receiver.
- **Scrolling**: Mira Speed preset (S); reviewer wants A2 only while scrolling plus a clean after (S).
- **Video / animation regions**: Mira Video preset (stronger light filter); Modos per-region modes and 4-level mode; Flow "Watching" mode. No source does automatic content classification; all use manual presets (S). Automatic classification is therefore ours to design (I).
- **Auto vs manual full refresh**: Mira: button, shortcut, timer (5 min example). Dasung: C button plus Auto-Clear. Modos: per-pixel rest clean, no flash. Kindle: every N pages. Everyone offers both.
- **Contrast and dark mode**: Mira white:black clip filters and contrast 0-15; Modos gamma-aware dithering in linear space is "noticeably better at 1 bit". No source evaluates dark mode on e-ink; for 1-bit text, black on white is the PineNote and Mira Text choice (S).
- **macOS settings** for e-ink: only Reduce Motion (System Settings > Accessibility > Display) has indirect support [Readwise e-ink note](https://docs.readwise.io/reader/docs/faqs/eink), [AbilityNet](https://mcmw.abilitynet.org.uk/how-to-reduce-motion-effects-in-macos-15-sequoia). Others (Reduce Transparency, larger pointer, Increase Contrast) are our inference.

## 3. Tablet-side controls

No product found that documents an on-screen quick panel or corner tap on the e-ink device. Controls live on hardware buttons (Dasung, Bigme: a short power press = global refresh), the desktop app (Mira) or the host. Existing sidecar already has a two-finger tap = full refresh. Ideas (I): a small corner hotspot (long tap) opening a strip of 4 buttons (Mode, Contrast -/+, Clean, Rotate lock) drawn by the receiver in pure 1-bit; three-finger tap to cycle presets; hardware Home button short press = full refresh if the OS lets the receiver read it.

## 4. Ranked features to add

1. **Typing mode with idle clean (PineNote).** Fast-only updates while input events are within N ms; one quiet complementary-dither clean after 2-8 s idle, tuneable. Why: removes visible flashes mid-sentence, ghost cleaned when the eye is off the screen. Mac: event tap (CGEventTap) timestamps keys; capture sends `typing=1`; tablet delays the clean timer while typing and uses a single batched pass. Source: [pinenote](https://github.com/CVERInc/pinenote).
2. **Caret blink suppression on the Mac side.** Why: a blinking caret is an endless 2 Hz stream of tiny updates, each a ghost. Do: at sidecar start write the two `defaults` keys (restore on quit), plus the VS Code/terminal settings hint in docs; and in the capture, mask a 1-char-wide region that toggles with period 0.5-1.2 s (detect an on/off region by repeated identical diff, hold it "on"). Source: Apple/Chromium links above; Boox forum thread.
3. **Per-pixel (per-tile) rest clean with a non-flash pass.** Already half there; improve with PineNote's complementary dither (mean luminance mid-grey, no black-white flash) and rest delay per tile instead of global 1 s. Why: ghosts disappear without a visible flash. Mac: keep a tile "last changed" timestamp; tablet schedules clean per tile. Sources: Modos Glider; pinenote.
4. **Presets with one-key switch (Text / Speed / Video / Reading).** Each preset is a bundle of tone curve, dither type, refresh delay, tile size, scroll behaviour. Why: all vendors ship it; users pick by task. Mac: menu-bar item plus global hotkey; settings window already live, so a preset is a JSON of existing knobs. Sources: Mira, Mira Pro, Modos Flow.
5. **White and black clip (levels) knobs.** Why: near-white backgrounds become pure white so dither noise vanishes; near-black text becomes pure black. Mac: two sliders before the tone curve (clip below b, above w); default like Mira 10:96 of 127 scale. Source: miractl.
6. **Scroll mode: fast while scrolling, clean when it stops.** Detect scroll events (already two-finger and wheel); during scroll use biggest tiles, coarser dither, optionally skip frames; on stop send one clean of the moved area. Why: less ghosting trail, matches Boox reviewer's wish. Source: Mira review.
7. **Per-region content classification (text vs image vs video).** Per tile compute cheap stats: histogram bimodality, edge density, change rate. Text: threshold or ordered dither with sharp edges; photo: blue-noise or error diffusion (slow, run only at rest); video (change over 15 frames/s): 4x coarser tiles, no cleans until stop. Why: one dither does not fit all. Source: Modos per-region modes and dithering list; Boox video preset.
8. **Better dithering by content: blue noise and gamma-aware (linear light).** Why: Bayer 8x8 shows a cross-hatch; blue noise looks smoother, linear-space dither fixes tone. Mac: precomputed 64x64 blue-noise mask (void-and-cluster) in a Metal/CPU thresholding pass; error diffusion only for still images. Source: Modos deep dive.
9. **Tablet-side quick panel (corner long-tap).** Buttons: Clean now, Mode, Contrast, Rotation lock. Why: no need to reach the Mac; matches C-button and short-power-press habits. Tablet: receiver draws the strip as 1-bit UI over the stream and sends commands back over USB. Source: Dasung buttons, Bigme guide; UI itself is our design (I).
10. **Receiver-drawn pointer overlay (1-bit, high contrast) with its own tiny dirty rect.** Hide the Mac cursor in capture, send position only; receiver draws arrow, I-beam or hand by the cursor type. Why: pointer motion costs bytes of position, not a full tile diff; no trail from the captured cursor. Source: idea from Modos "cursor compensation" (no method published) (I). Sprites: section 5.
11. **Quick toggles for the Mac environment.** On start: Reduce Motion, hide animated wallpaper, solid caret, mouse pointer size big, light mode; restore on exit. Why: fewer changed pixels per second. Source: AbilityNet, Readwise (Reduce Motion); rest is (I).
12. **Auto full refresh timer plus "refresh after drag ends".** Optional timer (5 min default off) and refresh on a long window drag or Space switch. Why: Mira's timer alone is criticised as untied to the task; tie it to events. Source: Mira review.

## 5. Kenney Cursor Pack

- Licence: **CC0 1.0** (page [kenney.nl/assets/cursor-pack](https://kenney.nl/assets/cursor-pack), `License.txt` in the zip; Kenney credit appreciated, not required). Version 1.1, 180 files, 2024. Also CC0 on [OpenGameArt](https://opengameart.org/content/cursor-pack-1).
- Direct zip: kenney.nl serves it only through a JS call (`/download-link/<id>` returned `forbidden` to curl), so there is no stable direct URL there. Page to click: https://kenney.nl/assets/cursor-pack (also https://kenney-assets.itch.io/cursor-pack). **Verified direct zip (same pack, v1.1, downloaded and checked): https://opengameart.org/sites/default/files/kenney_cursor-pack_0.zip**
- Layout: `PNG/{Basic,Outline}/{Default,Double}/name.png` (Double = 64x64, Default = 32x32), `Vector/Basic|Outline/*.svg`.
- Picks (open the files in `PNG/Outline/Double/`, black outline, white fill, ideal for 1 bit; the SVGs in `Vector/Outline/` allow exact threshold at any size):
  - Arrow: `pointer_a.png` (classic arrow with tail, closest to the macOS arrow); alternates `pointer_c.png` (large triangle), `pointer_b.png` (small).
  - I-beam: no file named so; `bracket_a_vertical.png` is a serif I-beam with caps, `bracket_b_vertical.png` a narrower one; `line_vertical.png` is a plain bar (hot spot at centre).
  - Hand pointer: `hand_point.png` (index finger), `hand_open.png` for grab; thin variants `hand_thin_point.png`.
- Check: outlines are thick enough to survive a 1-bit threshold at 64 px; at 32 px confirm hot spots by eye (arrow tip top-left, hand finger tip top-left).
