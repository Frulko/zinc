# Fixed-function replay reference

`targets/console/ff_cpu.{h,cpp}` implements the same backend functions as PSP and 3DS, using the already vendored SDL3 software renderer. Link it with `ff_replay.cpp`, the raster and SDL3 in a standalone desktop program; do not link two backend implementations together. The public header contains no SDL or platform header.

Create `zn::ff::Cpu` with a caller-owned `0x00RRGGBB` pixel buffer and dimensions, then call `render(lists, count)`. It flushes the SDL software queue before returning. Use it on the main thread. There may be one live CPU backend; construction failure throws and releases any SDL objects already acquired. Destruction releases textures before the renderer and surface and invalidates the shared atlas caches. An unsupported frame or SDL error returns false; pixels may be partial, and the caller must rasterize the complete frame. Runtime image textures refresh on version/identity changes; destroyed runtime images are collected on the next render.

SDL supplies triangle rasterization, interpolation, texture blits, sampling and alpha blending rather than adding another rasterizer. See [software surfaces](https://wiki.libsdl.org/SDL3/SDL_CreateSoftwareRenderer) and [per-vertex geometry](https://wiki.libsdl.org/SDL3/SDL_RenderGeometry). The triangles use the same corner order as PSP/3DS. Uniform textured quads use SDL’s texture blitter because its software geometry path samples nearest even when linear filtering was requested. SDL blend rounding can differ from the Zinc raster: this backend is a tolerance reference, not an exact-pixel implementation.

`begin_frame()` resets counters once before validation; `end_frame()` reports them once when `ZINC_LOG` is `info`, `debug` or `trace`. The CLI already sets `ZINC_LOG=info` for `-v`. PSP surrounds a presentation; 3DS surrounds its existing GPU frame, including both eyes and bottom-screen surfaces. Counters are emitted quads after clipping, successfully obtained shape tiles drawn, and those tile draws whose coverage was cached in an earlier frame. Validation prewarming and repeated lookups do not create cache hits. A software frame displayed through `full()` emits one quad and no shape tiles. They describe replay work, not backend vertex-pool overflow or GPU completion.

Linear rectangle/shape gradients already use per-corner colours. Rounded clips, radial/paint gradients, transforms, lines and unsupported image effects remain whole-frame software fallbacks; the CPU backend preserves that capability check.

`tests/run --only ff_cpu` compiles a small native program against the existing SDL archive (`ZN_FF_SDL_LIB` overrides its path). It checks a tiny two-list frame against the raster within channel tolerance 8, cold/warm counters, verbosity, clipping, gradients, shape atlas coverage, dynamic image updates/deletion, alpha, nearest/linear sampling, full-frame quads and backend restart. The layout/bouncing-ball/kit-gallery T1 comparison is still pending an owner-selected milestone; this small check does not establish that acceptance criterion.
