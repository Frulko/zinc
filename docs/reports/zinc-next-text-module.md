# The private text module

`libzn_text_module` holds HarfBuzz, hb-subset, SheenBidi, the layout implementation and the MSDF font baker. The CLI keeps the existing `Face`, layout and baker interfaces as small proxies, plus the graphics shape hooks and sbix decoder. libunibreak remains in the core for segmentation. No public plugin format changes.

The first face open, layout or font bake loads the sibling module with `RTLD_NOW | RTLD_LOCAL` through the platform library helper. The executable path is resolved before choosing its sibling; the working directory is never searched. `ZINC_TEXT_LIB` explicitly overrides the path for development and testing. The descriptor version, size and all required callbacks are checked before use. A locked state machine records NotTried, Ready or Failed with its diagnostic. Failures remain failures, rather than retaining a whole font or dropping fallback text. Module handles and loader state stay resident because host font caches can outlive ordinary static destructors. Faces keep their existing ownership and destructor behavior.

D207 still applies: fallback shaping is enabled by default; `"text": "simple"` and `ZINC_TEXT=simple` opt out of drawing through the shaping tier. Font subsetting and MSDF cooking independently need the module. Missing modules produce a diagnostic and exit status 1. The raster callback boundary reports the same error without throwing across runtime code.

The static `zn_text`, HarfBuzz and SheenBidi archives remain available for AOT and app-library consumers. The JavaScriptCore, V8 and Hermes modules retain their existing private static copies. `layout.cpp` is hidden in the dynamic text module so ELF cannot redirect its Face methods into the CLI proxy.

CLI packages, development bundles and JavaScript app bundles copy the module and its combined third-party license notice. `zinc fuse` adds its own host tuple's module and licenses to its internal checked archive. Ordinary `.zapp` files stay portable and never supply executable text code to an unfused CLI. A fused run obtains the expected module SHA-256 from the embedded source manifest, independently of the extraction cache and its `.checked` marker. At first use it locks the cached module, checks its actual bytes against that pin and opens it under the same lock. Corruption is refused; it is never silently repaired or accepted.

Research: [HarfBuzz build options](https://harfbuzz.github.io/building.html), [HarfBuzz configuration](https://github.com/harfbuzz/harfbuzz/blob/main/CONFIG.md), [upstream shaping/subsetting build separation](https://github.com/harfbuzz/harfbuzz/blob/main/src/meson.build), and [dlopen binding and lifetime](https://man7.org/linux/man-pages/man3/dlopen.3.html). The boundary reuses the existing layout API rather than moving graphics/runtime host tables.

`tests/run --only text_module` checks absence of HarfBuzz/SheenBidi symbols in zinc, lazy opening, cached missing/incompatible-module errors, shape/raster/outline/break/subset/MSDF calls, native Canvas 2D missing-module errors after JavaScript entry, and refusal of a previously used fused cache module after tampering. The shaped-text golden campaign, platform packaging campaigns and device execution remain owner-selected milestone checks.
