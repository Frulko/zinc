# Review: examples/music-tree (2026-10-19)

`examples/music-tree` rewrites `examples/music` (the Sonos/Spotify wall remote for the HP TouchPad and Nexus 7, 1024x768, drawn with
zinc:gfx) around an AS3-style display tree (`core/display.ts`) plus a small flexbox (`components/layout-nodes.ts`). This review compares
it with `examples/music` at c548da1c (v1.3.0). `zinc check examples/music-tree` passes (exit 0). The code was read in full. One engine
behaviour was checked with a probe program, run headless outside the repository (see H2). Nothing else was run: Sonos, Spotify and the
network were not available.

Size: 11,419 lines in 38 files, against 3,676 lines for music. That is 3.1 times more code, and music-tree has fewer features (see "Worse").

## Architecture

- **The tree duplicates zinc:ui.** zinc:ui already offers Yoga flexbox, a retained tree that costs nothing on idle frames (`gfx.keep`), hit testing and gestures, a ScrollView with the Android overscroller, a TextInput that uses the system IME, and transitions. `display.ts` rewrites a subset of the flexbox: no wrap, no min/max, no percentages, no margins, no absolute positioning, no measure cache and no dirty propagation. Half of that subset is never used (L8).
- **And it only covers part of the UI.** The home slides, sidebar, status bar, sheets, toast, grids and lists are still drawn in immediate mode inside `onDraw`; only Settings, Rooms, the volume popover and the page headers use the flexbox nodes. That is two UI models in one app, a third in the repository.
- **The layout nodes repeat the draw functions' measurements.** Most of them only wrap a `draw*` function and compute its size a second time: `PillButtonNode.onMeasure` (`layout-nodes.ts:215-219`) repeats `drawPillButton` (`buttons.ts:65-68`), `SegmentedControlNode.onMeasure` (`:260-271`) repeats `drawSegmentedControl` (`:100-110`), and `drawNoSpeakerEmptyState` recomputes the pill's width (`player-slide.ts:67`).
- **The reason given is not measured.** The README says the tree exists to avoid "the cost of zinc:ui". No decision record and no perf entry measures zinc:ui on the TouchPad (D142 measured music's raster only).
- **Recommendation.** Either (a) keep music's immediate-mode drawing and take only the module split, or (b) measure zinc:ui with `zbench` on the TouchPad and Nexus 7, then port the app to JSX (`<View className=...>`, `<ScrollView>`, `<TextInput>`). (a) is the smallest change. Do not keep a third UI model.
- **State coupling.** Every page reads and writes `appState` directly (for example `context-sheet.ts:124` sets `currentPage` without `navigateToPage`, so the keyboard and search state are not reset). There is no seam between the pages and the actions.

## What is better than music (input for the demo quality bar)

- **One module per concern.** `core/` holds the tree, input, pictures and screen power; `services/` the config, radios, UDP, weather and notifications; then `components/`, and `pages/<page>/`. music's `main.ts` is 1,622 lines holding the config, the network, the input and all five pages.
- **Names that read.** `PAGE_RADIOS`, `SLIDE_CLOCK`, `COLOR_TEXT_SECONDARY`, `LIST_ROW_HEIGHT`, `navigateToPage`, `pollActiveSonosGroup`, against music's `TEXT2`, `F.bodyB`, `P`, `SIDE`, `sc`, `gg`, `tGroup`.
- **Shared values in one file.** `constants.ts` holds every identifier and limit (page, slide and face ids, ports, cache sizes), instead of bare numbers.
- **A typed config.** `AppConfig` documents each field, and loading and saving live in their own service.
- **One place where a page loads its data:** `onAddedToStage` (once the duplicate calls in L2 are removed).
- **Local coordinates.** Each component draws in its own frame and zones are offset automatically (`input.ts:139`), instead of music's manual `ui.ox`/`ui.oy` bookkeeping (`main.ts:1390-1411`).
- **A declarative Settings page.** The tree is built once in the constructor and the values are bound in `onMeasure`, with no hand-accumulated y.
- **Pooled popover rows.** The volume popover reuses its row nodes and only grows the pool (`volume-popover.ts:100-107`).
- **Documentation and editor support.** Every exported function and class has a JSDoc comment, and `env.d.ts` plus the tsconfig paths give editor completion.

## What is worse than music

- **Visible regressions.** The blurred backdrop is black (H2). The Rooms page redraws every frame (H1). The warm-up render has lifecycle side effects (M2). The clock's face dots move during a swipe (M6).
- **Two days of feature drift** (music-tree was forked from music around 1.0 on 2026-10-17). It is missing desktop typing, Escape and Backspace repeat (H3), wheel and trackpad scrolling, the in-app Spotify login and logout, "Reprendre ici" (handoff), the Spotify queue, the glances and notifications settings, and zinc.json permissions.
- **French text.** Comments and the README are in French, against the repo rule.
- **3.1 times the code for fewer features.** Each `rrect` is formatted over 9 lines, and about 1,800 lines are comments.
- **A second UI model mixed with immediate mode**, and adapters that measure every widget twice.
- **A README perf claim that is not true** (M5).
- **An installer that overwrites music** on the tablet and drops its settings (M8).
