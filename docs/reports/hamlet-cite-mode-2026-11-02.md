# Hamlet "Cité" mode: an Augustus-style city builder (2026-11-02)

Owner request (2026-11-02): real topography; on a large map the animations make it lag badly; nobody understands how the game works (the tree is too complex); a mode close to Augustus in its logic (resources, buildings, how people move) and optimised for movement, UI, missions, sandbox, mountains, topography, assets, tiles. "A real thing." Reference: `/Users/mowmow/Lab/augustus` (GPL-3: mechanisms only, nothing copied). Earlier studies: `hamlet-augustus-study-2026-11-01.md`, `hamlet-augustus-reference-2026-11-01.md`, `hamlet-perf-2026-11-01.md`.

## Decisions

1. **Why it lags (measured in the perf report).** The view is a software, per-pixel renderer (a 360x280 buffer of lit volumes, rebaked per zoom level, the idle frame grows with the number of animals in view). Cost follows the map and the herds, not the screen. No tuning fixes that: the view is replaced, not patched.
2. **The sim stays, the view is replaced.** `world/`, `rules/`, `engine/` never draw; they are kept and made faster. A new view `src/cite/` draws with `zinc:gfx` as GPU quads (`drawImageRect`, batched per image): tiles of a baked atlas, culled to the screen, animation = a frame index chosen by time (no buffer to redraw). The old pixel view stays selectable (`settings.view`) until Cité reaches parity, then goes.
3. **Tiles, like Augustus.** Iso diamond tiles (64x32 on screen at zoom 1), one atlas per season, sprites for buildings/trees/rocks/people/animals with 8 directions x N frames. Sprites are generated by code at first start (baked from the existing models into an RGBA image with `imageFromPixels`, cached) or drawn as vector shapes where cheaper: no artist is needed, art can be replaced by a PNG atlas later. Only tiles and sprites on screen are touched.
4. **Topography.** `world.height[t]`: an integer level 0..15 per tile (1 level = 0.5 world unit; sea level 0; water only at 0). Mountains (levels 8+) are rock, not buildable, hold stone and ore. Neighbouring tiles differing by 1 form a slope (the renderer interpolates the corners), differing by 2 or more a cliff (a wall drawn, impassable). A building needs a flat footprint; a road may climb one level per tile (cost 1.5x, slower walkers); bridges cross water only on flat banks. The generator makes it from seeded noise (ridged noise for ranges, a river carved downhill, plateaus). Same seed gives the same map on every engine.
5. **Augustus logic, at our scale.** The mechanics are those of the Augustus study, in data (`assets/economy.json`): a road network id per connected road (a building off the gate's network is idle and the hint says so); a building has a fixed number of jobs filled from one labour pool (adults = share of residents, by building priority); output scales with staffing; storage buildings (granary-like store) accept loads, producers send a cart-walker to the nearest accepting store that has room (reservations, as `Building.reserved/incoming` already do); service buildings send one roamer at a time that walks the roads with a straight-ahead bias and sets a coverage counter on the houses it passes, which decays daily; housing levels with separate evolve and devolve thresholds and a "what is missing" list; desirability rings. Whole-map passes (network ids, desirability, labour) run as daily slices spread over ticks.
6. **One screen to understand it.** The tree window goes. Replaced by: the top bar (population, workers/jobs, the stock of the five goods that matter), an advisor list (labour, housing needs, stores, services, each line says what to build), a click on any building shows what it needs and why it stands idle, overlays (water, services, desirability, jobs). Costs and recipes live in the build menu tooltip, not in a graph.
7. **Missions and sandbox.** A mission is a data file `assets/missions/<id>.json`: map (seed + params or tiles), starting stock, buildings unlocked, goals (population, a stock, a building count, a rating), a time limit optional, a briefing text. Sandbox = the same map options with no goals and everything unlocked. A campaign is an ordered list of missions. The existing `goals` of economy.json become the first mission's goals.
8. **Scale target.** 128x128 tiles (up to 256), 500 people, 300 animals: view frame under 4 ms on AOT (M1 Pro, headless, one core); simulation step under 2 ms; no frame over 16 ms when panning, zooming or idle.

## The contract between the three work items

- `world.height: number[]` (one level per tile, row-major like `world.terrain`), `HEIGHT_STEP = 0.5` world units and `MAX_HEIGHT = 15` in `constants.ts`; `heightAt(tile)`, `isSlope(tile)`, `isCliff(a, b)` exported from `world/world.ts`. The saved village gets the array (new save version; older saves load flat).
- The view reads `world`, never writes it, and never imports from `engine/`.
- The sim is deterministic: same ticks, same village.
