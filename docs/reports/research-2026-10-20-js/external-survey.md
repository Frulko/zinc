# External survey: an optional JS engine behind a native typed engine (2026-10-20)

Scope: facts with sources for the Zinc architecture (TypeScript AOT to C++, own renderer, optional QuickJS-ng / JavaScriptCore / V8 for untyped npm/browser code, DOM shim, fastest native<->JS boundary).
Method: web search and fetch on 2026-10-20. Rules: a number is quoted only with its source; "not found" means the searches did not return it; "derived" marks my arithmetic; "(vendor claim)" marks self-reported numbers. Several searches returned thin results, so section gaps are listed at the end.

## 1. Engine embedding APIs and native<->JS call cost

| Topic | Fact | Source |
|---|---|---|
| V8 Fast API (CFunction) design | Fast calls are invoked directly from optimized (JIT) code, with the type checks done in the compiler instead of on the embedder side. The embedder must not allocate on the JS heap or run JS, so a fast call cannot throw a JS exception directly. `CFunction::MakeWithFallbackSupport` falls back to the slow call when allocation or errors are needed. Consequence: the fast path exists only when V8 has optimized the caller, so a jitless V8 (iOS, consoles) gets none of it. | https://chromium.googlesource.com/v8/v8.git/+/main/include/v8-fast-api-calls.h |
| V8 Fast API ns | No independent V8 ns figure found. Deno FFI README claims about 1 ns per call on an M1 16 GB, built on V8 fast calls plus a JIT-compiled trampoline, Linux and macOS only (vendor claim). | https://docs.rs/crate/deno_ffi/0.239.0 |
| Deno op2 | No measured ns for op2 fast calls found. The FFI commit mirror notes u64 for pointer types in the fastcall world. | https://code.fosterhangdaan.com/foster/denoland-deno/src/commit/722ea20e860df0a568b5d97734ad8d89aa7382a9/ext/ffi |
| V8 external / GC bridging | cppgc (Oilpan, standalone since V8 9.4) lets embedders link C++ objects and JS objects so V8's GC sees the links; `CppHeapCreateParams` takes a `WrapperDescriptor` (which internal fields hold wrappable objects, by embedder id). A newer `CppHeapExternal` is an on-heap alternative to `v8::External` that stores GarbageCollected objects in a non-JSObject value. ## Reading for Zinc (short)

- Cheapest published call shape: JSC C++ API 2 ns, Node-API 7 ns, V8 fast call ~1 ns only on JIT-optimized callers (Deno, vendor claim). QuickJS has no published ns; it must be measured in-tree.
- In JSI the property-getter (HostObject) path is ~5x slower than function/native-state shapes: prefer methods and opaque native state over per-property hooks, and typed-array/ArrayBuffer sharing over copying (QuickJS-ng `JS_NewArrayBuffer`/`JS_NewUint8Array` are no-copy).
- scriptc's `--dynamic` (typed AOT + embedded quickjs-ng) is the closest published precedent, removed in scriptc 0.3 (its CHANGELOG: "Compilation is native-only"; no reason given); Lynx (PrimJS + native element tree, no DOM) and Blitz (native DOM, no JS yet) are the closest on the rendering side.
