# Onboarding benchmark: creative-coding and beginner tools

Research date 2026-10-22, from the live sites where they could be fetched. Many sites are JavaScript apps that a page fetch returns empty (p5 web editor, Scratch, Arduino Docs, Roblox Studio itself): the first screen of those is **not verified** and is marked so. Nothing here was run on a device; the tools were not installed.

Zinc today (not recommended again): CLI welcome and language choice, `zinc new`, `zinc tour`, translated diagnostics and `zinc explain`, Atelier (start view, examples by style, templates, spotlight tour, five languages), 20 lessons, "choose your kind of program", cheat sheet, site in five languages.

## Tool by tool

**Processing** (https://processing.org/, /download). Landing page gives three steps: download and open the app, select something from Examples, press Run. "Open one, change the code, and make something new." Download page offers 4.5.7 for macOS, Windows, Linux, Raspberry Pi. Getting Started tutorial, reference, books; community links (OpenProcessing, Discourse, Discord, Reddit). Extra languages (Python, p5.js) are "modes" installed from the Contribution Manager (https://github.com/processing/processing/wiki/Mode-Overview). Not verified: the Processing 4 welcome screen, translations of the site, error display. Remarkable: the whole first-run story is one sentence long, examples are the tutorial.

**p5.js and its web editor** (https://p5js.org/tutorials/, https://editor.p5js.org/). Browser only, "Start Coding" link on every page. Tutorials: 8 lessons "Introduction to p5.js" (set up editor, get started building an interactive landscape, variables, conditionals, functions, loops, data, media), grouped with Drawing, Web Design, Accessibility, WebGL. Friendly Error System prints "p5.js says:" hints with a link to the function's reference instead of a raw browser error (https://processingfoundation.org/blog/friendly-error-system-for-p5js/). Not verified: the editor's first screen, sharing and collections (known from memory: accounts, public sketch links, collections), language selector (page shows "English" only). Remarkable: zero install, the share link is the community.

**Arduino IDE 2 and Arduino Docs** (https://docs.arduino.cc/software/ide-v2/tutorials/getting-started-ide-v2). Install, pick board and port, File > Examples > 01.Basics > Blink, upload. IDE 2 adds autocomplete (off by default, "Editor Quick Suggestions" in preferences), debugger, serial monitor as a tab, sketch sync with Arduino Cloud (remote sketchbook). Community guides all converge on Blink as the first result (https://workshops.hackclub.com/blink). Not verified: Cloud Editor today, docs translations, how compile errors are rendered. Remarkable: the first result is physical (an LED), one agreed hello-world for the whole ecosystem.

**Scratch** (https://scratch.mit.edu/). Browser editor. A Tutorials button opens a library inside the editor; a tutorial opens as an overlay card and a green arrow advances one step; afterwards it suggests the next one (Scratch getting started guide PDF, https://resources.scratch.mit.edu/www/guides/en/scratch-getting-started-guide.pdf, may be dated). Coding Cards printable at /ideas. Translations: volunteers through Transifex with reviewer roles, only reviewed strings ship; "more than 40 languages" per forum posts (dated, not verified now). Remarkable: tutorial lives in the editor beside the work; share and remix is built in. Errors do not exist (blocks).

**Microsoft MakeCode** (https://arcade.makecode.com/skillmaps, https://makecode.microbit.org/, https://www.makecode.com/writing-docs/skillmaps). Browser, simulator always beside the code, Blocks / JavaScript / Python toggle. Tutorials are markdown files run inside the editor; a skillmap chains tutorials as a map, finishing one unlocks the next, ends with certificate and confetti (Beginner Skillmap: Storytelling, Clicker, Dino Run). Sharing: Share button gives a project link; embed code, and import from URL in VS Code. Switching blocks to text can fail with "Oops, there is a problem converting your code" (forum, shows a weak error spot). Remarkable: authors write a lesson as markdown, the editor does the rest (https://github.com/microsoft/pxt-skillmap-sample).

**Thonny** (https://thonny.org/). One installer including Python; the initial interface hides distracting features. Variables view, step-by-step debugger without breakpoints (F6 big step, F7 small step, shows how an expression is evaluated), unclosed quotes and brackets highlighted, local versus global variables coloured differently, package manager GUI. An "Assistant" explains errors in plain words (per secondary sources, https://realpython.com/python-thonny/, not checked on the official site). Remarkable: it makes the running program visible, not only its result.

**Godot** (https://docs.godotengine.org/en/stable/getting_started/introduction/index.html). The Project Manager is the first window: create, import, run. Templates and demos are on a Projects tab served from the Asset Library; it asks you to press "Go Online" first because the editor does not touch the network by default (docs 4.4). Docs: "Getting started" opens with Introduction (what Godot is, GDScript, key concepts, a first look at the interface, how to learn). Translations: Hosted Weblate, gettext PO, three resources (editor interface, class reference, manual), no pull requests, maintainers sync (https://godotengine.org/article/godots-documentation-now-open-translation/ and docs "Editor and documentation localization"); a language dropdown top right of the Project Manager and of the docs. Remarkable: explicit offline-by-default plus opt-in online library; single large PO template instead of one per page.

**PICO-8 and TIC-80** (https://www.lexaloffle.com/dl/docs/pico-8_manual.html, https://github.com/nesbox/TIC-80/wiki). Boot straight into a command prompt with code, sprite, map and sound editors one key away. First commands in the manual: `print("hello world")`, `rectfill(...)`, `install_demos`, `load jelpi`, `run`. `HELP` lists commands. TIC-80's `help <function>` prints the API entry in the console and can export the whole help as a Markdown cheat sheet. Sharing: the cartridge is a PNG image you send, a BBS page with a web player, `export mygame.html` and native binaries. Not verified: runtime error display. Remarkable: sharing a game is sending one picture; the reference is a command.

**LÖVE** (https://love2d.org/wiki/Getting_Started, fetch blocked 403, from search snippets). Drag the folder that holds main.lua onto love.exe; a missing main.lua gives a "wrongly packaged game" message. Wiki per function with examples, in several languages (Turkish seen). Not verified: the error screen design (from memory it shows the stack trace on a coloured screen). Remarkable: nothing to install beyond the runtime, a game is a folder.

**Roblox Studio** (https://create.roblox.com/docs/experiences, https://create.roblox.com/docs/tutorials/curriculums/studio). Official path in three steps: Studio's onboarding tour, build a 3D platformer that teaches building and scripting, learn the platform. Templates (platformer with coins, double jump, dash) can be opened and played with no code first. Docs are localised, with a visible notice that French, Spanish, Portuguese pages are "AI-generated (Beta)". Not verified: Studio's first screen itself.

**Unity Hub and Unity Learn** (https://learn.unity.com/tutorial/get-started-with-the-unity-hub). Hub has Projects, Learn, Community, Installs tabs; templates are starter projects per Unity version; "Learning" templates open a Unity Essentials pathway whose instructions appear inside the Editor (Unity 6, labelled experimental), then the learner returns to the website for a quiz, XP and a badge. Remarkable: the lesson is a project template, so it needs no new mechanism.

**Swift Playgrounds** (https://developer.apple.com/swift-playgrounds). Guided "Get Started with Code" lessons built as puzzles, results shown instantly as you type, inline completion, errors found as you type, tap a colour or image value to edit it (iPad), App Gallery and starting-point playgrounds. Swift only. Remarkable: the live result and the structured puzzle replace documentation.

## Ideas for Zinc, ranked (value for education, makers, artists, DIY against effort)

1. **Lessons as projects that open inside Atelier, with the tour's step check** (Unity Learning templates, Scratch tutorial overlay, MakeCode tutorials as markdown). The 20 existing lessons become a side panel: markdown with a "check" per step, reusing the `zinc tour` checker. Atelier plus docs; medium. Biggest gap named in the brief, and the engine for it exists.
2. **Skillmap / path with unlocks** (MakeCode Arcade skillmaps, Unity pathways). A small JSON listing the 20 lessons in order with progress stored locally, shown on the Atelier start view and `zinc tour`; a finish message. Atelier and CLI; small once idea 1 exists.
3. **Browser playground with share link** (p5 web editor, MakeCode, PICO-8 web player). Compile the current interpreter or the wasm target (`targets/web`, `targets/wasm`) into a page on the site; the code lives in the URL fragment so no server or account. Site; medium to large, but it unlocks sharing, the lessons on the site, and "try before install". Do the URL-fragment version first.
4. **Hello-world agreed for each kind** (Arduino Blink, Processing "select an Example, press Run", PICO-8 `print`). One named first result per kind in `zinc new` and the start view (a circle that follows the mouse for drawing, a blinking LED for boards), always the same across docs, tour and Atelier. Docs, CLI, Atelier; small.
5. **Hints that link to the reference from the error itself** (p5 Friendly Error System, Thonny Assistant). Each diagnostic prints a "see also" with the function's doc page and one example; Atelier shows it under the error with an "open reference" button. CLI plus Atelier; small to medium since `zinc explain` exists.
6. **Reference at hand: `zinc help <name>` and offline docs bundle** (TIC-80 `help <function>` and Markdown cheat sheet export, Godot's offline-by-default docs, Processing's built-in reference). Generate from `lib/zinc.d.ts` comments; Atelier opens it on F1 over the symbol under the cursor; ship the docs inside the app. CLI, Atelier, docs; medium.
7. **Share as one file** (PICO-8 cartridge PNG, MakeCode share link). `zinc pack` already makes a `.zapp`; add "Share" in Atelier that writes the sketch as a single file or a text link (idea 3), with a screenshot as cover. Atelier and CLI; small to medium. A gallery of shared sketches is a later step (moderation cost).
8. **Show the program running: step and variable view** (Thonny, Swift Playgrounds live values). Atelier panel with variables and a step button on the interpreter; live edit of numbers and colours in the code by dragging (Swift Playgrounds). Atelier; large, high value for education.
9. **Translations through a hosted tool** (Godot Weblate with PO files, Scratch Transifex with reviewer roles, only reviewed strings ship). Move the five languages to PO/JSON catalogues kept in Weblate hosted (free for open source), CLI diagnostics, Atelier, docs and site from one catalogue; mark machine translation visibly (Roblox beta notice). Process; medium. Needed before adding a sixth language.
10. **Printable cards** (Scratch Coding Cards). One page per kind, PDF generated from the lessons, for classrooms and workshops. Docs; small, useful for teachers.
11. **Boot straight into code** (PICO-8, LÖVE: a folder is a program). `zinc run` of an empty folder offering to create `main.ts`; drag a folder on the Atelier icon opens it. CLI and Atelier; small.
12. **Video** (Scratch, Unity Learn, Arduino community). Skip for now; a 60 second screen capture of `zinc tour` and Atelier's first run, recorded by `zinc capture`, would be the cheapest start. Site; small.

Rejected: block editor (MakeCode, Scratch; Zinc is typed text), account system and gamification XP (Unity badges; the confetti at the end of a path is enough).
