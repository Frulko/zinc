# Pi account provisioning and failed first boot

ZN-784, 2026-10-23. Read-only checks identified the owner's paired Pi at its new DHCP address, matched its SSH host fingerprint and found the configured administrator account. One password authentication attempt failed. The saved builder profile retained the intended credentials; no credentials are reproduced here. The Pi's boot report recorded failures of all four cloud-init stages, but the old cleanup had nevertheless disabled cloud-init and recorded firstboot.done. The protected cloud-init logs and password state were not available to the unprivileged agent, so the original cloud-init failure is not established.

Two independent defects were corrected. The build wrote `users[].passwd`; cloud-init ignores that field for existing users, including an account renamed by Raspberry Pi OS before its users module runs. `hashed_passwd` applies to existing users as well. The first-boot cleanup also assumed that ordering after cloud-final implied success. It now requires a successful cloud-init status before any cleanup; errors or degraded status retain setup inputs and the initramfs.

The installed cloud-init source corroborates the first behavior. Primary references: [cloud-init user schema](https://docs.cloud-init.io/en/latest/reference/modules.html#users-and-groups) and [create_user implementation](https://github.com/canonical/cloud-init/blob/main/cloudinit/distros/__init__.py). Independent recovery research found no remote administrator verb in Zinc's restricted helper; the official [userconf service](https://github.com/RPi-Distro/userconf-pi/blob/pios/trixie/userconf-service) is masked by the image, so userconf.txt alone is insufficient.

The native regression runs the actual cloud-config generation for password/key/no-user profiles, verifies its SHA-512 hash, and runs cleanup against temporary files with successful, failed and degraded cloud-init responses. No target build, flash, account change or remote service restart was performed. Existing cards are not repaired by changing the repository; owner-controlled recovery or a new flash is required.
